# R2 回板验证和数据回传

本轮不连接机械臂。默认仍为冻结 V3；R2 只提供抓取/抬升的小修正，不替代现有执行器、限位、保护或重试程序。

## 板端先做离线和影子推理

1. 下载交付包，先用 `infer.py` 对 `example_observation.npz` 离线推理，对比包内示例输出。39 维顺序、归一化和修正上限见 `inference_config.json`。旧 R1 的 36 维输入不能直接使用。
2. 用真实图像、相机标定和只读关节反馈构造相同输入；最后三维是“视觉估计抓取点减去自身 TCP 位置”，按 40/40/160 mm 缩放并截到 ±3。目标暂时看不见时保持最近有效视觉特征，并明确可见标志为零；不得补入仿真目标真值。
3. 记录模型提议但先不执行，分别测相机等待、视觉、残差模型、IK、完整流程的 P50/P95/P99、RSS、CPU、温度及功耗。主机微小残差网络的速度不等于板端整套系统速度。
4. 实际运动需要现场重新核对相机/TCP/桌面/区域标定、J7 电机角度与真实开口查表及现有保护执行层。仿真夹爪米数不能当作 J7 弧度。五步张开对准和十八步抓取的时序也要先做影子核对。

## 每个回传回合至少包括

- `manifest.json`：设备、任务 A/B/C、源码/模型/标定哈希、固件、时间与单位。
- `calibration.json`：内参、深度尺度、相机外参或同步变换链、TCP、J7 查表和区域位置。
- `observations.npz`：原始 RGB、米制配准深度、图像时刻与接收时刻。保留遮挡、缺失和过期标志。
- `trajectory.jsonl`：单调时间、关节位置/速度、J7 原始角度与已标定开口、视觉估计、39维实际输入、模型提议、执行器接受/拒绝及原因、真正下发的命令和时间。
- `events.jsonl`、`outcome.json`：抓空、偏抓、滑落、人工接管、重试次数、视觉验收和人工复核。成功、失败、未执行提议都保留。
- `SHA256SUMS`：逐文件哈希。压缩包交回训练主机时校验后入库，并记录设备/日期/完整回合的数据划分。

按设备和采集日期预留独立测试，不把相邻图像分到训练和测试两边。先用命令与反馈拟合响应延迟、跟踪误差和 J7 滞回，用重复静态 RGB-D 校正深度噪声和标定，用实际滑落/夹持记录约束接触范围，再补视觉与正确动作示范、继续仿真学习。不要为了提高仿真分数任意调大摩擦。

现场图像是否适合公开应按其实际内容决定。当前用户已授权公开本轮仿真记录；这不预先授权上传未来现场私人画面。实机独立至少30个新场景通过后，再讨论采用。
