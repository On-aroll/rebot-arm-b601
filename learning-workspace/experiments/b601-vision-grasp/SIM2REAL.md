# 接实机前需要对齐的接口

目标抓取放置 V0 新增的残差模型与目标区域同样是仿真接口。目标区域必须来自现场标定；夹爪行程判断必须用真实开口/接触实验确定，不能沿用当前 8–38mm 阈值。最终仿真真值评分器不会迁移到机器人上，实机必须独立验收视觉结果检查。具体仿真能力见 [GOAL_TASK.md](GOAL_TASK.md)。

本实验已提供可复现的数据与视觉模型，尚无实机控制适配器。训练完成不等于插上机械臂即可可靠抓取。

## 坐标与控制契约

| 数据 | 本实验约定 | 实机需要完成 |
| --- | --- | --- |
| RGB-D | 同一仿真时刻，深度单位 m，160×120 | RGB/深度配准、深度尺度和相机时间戳；缩放图像时同步缩放内参 |
| 相机坐标 | optical：X 右、Y 下、Z 前 | 与真实相机 optical frame 一致 |
| `T_base_camera_optical` | 已知固定相机外参 | 固定相机做外参标定；腕部相机用拍摄时 `T_base_tool × T_tool_camera` |
| 工作空间 | X 0.265–0.395 m，Y ±0.125 m，桌面 Z=0.1 m | 按实际桌面、底座和障碍重建；这些数值不是现场允许范围 |
| 关节目标 | J1–J6，rad，模型规范角 | 核对实机方向、零位、关节名和限位，再交统一规划/执行器 |
| 夹爪 | 单指模型行程 m，0–0.05 | 标定真实 J7 rad 与实际开口/接触关系，不能直接线性换算 |
| TCP | 模型 `tcp`；前指垫中心在局部 X=-15 mm | 实测 TCP、夹爪几何与相机支架偏差 |
| 模拟力矩 | PD + 模型 bias compensation；限值为仿真配置 | 不导入设备增益、限流或限矩；保留现有执行器保护 |
| 成功判定 | 真值物体高度 + 双指接触 | 用真实视觉确认抬升/滑移，并完成 J7 接触证据标定 |

当前控制器根据已知桌面和“立方体”假设，由可见顶面推算中心；60° 倾斜朝向是为当前模型可达性选择的，不代表通用抓取姿态。后续可以用官方 OBB 短轴或 6D 候选代替。

## 后续推进顺序

1. 扩大仿真验证：遮挡、干扰物、背景、不同颜色/形状、相机安装与深度噪声；记录失败分布。当前只随机化位置、方块尺寸/yaw/颜色、照明、桌面颜色、质量和摩擦。
2. 用真实相机只采图、不执行动作，完成内外参及桌面/TCP 标定，对比同一目标的视觉位置误差。用真实少量标注数据微调视觉模型。
3. 把相机估计导出为带时间、frame、单位、置信度的候选 TCP。现有执行器负责新鲜度、IK、碰撞、速度/力矩边界及控制所有权。
4. 现场监督下，从预览、小幅接近、空夹检查开始逐步验收。仿真轨迹不自动重放到实机。
5. 累积同步成功与失败 episode 后，可以训练模仿学习动作策略（例如 ACT）。先按 episode 划分数据，禁止把同一条轨迹的相邻帧拆进训练/测试两边；真值评估字段不得成为模型输入。

参考：[Seeed 视觉抓取及标定](https://wiki.seeedstudio.com/cn/rebot_arm_b601_rs_grasping_demo/)、[MuJoCo Python 渲染接口](https://mujoco.readthedocs.io/en/stable/python.html)、[Domain Randomization 论文](https://arxiv.org/abs/1703.06907)。域随机化用于缓解视觉差异，不能替代现场几何、动力学和控制验证。
