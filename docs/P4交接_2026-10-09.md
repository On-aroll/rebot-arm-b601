## 现在能用的功能

- 控制台顶部有连接/断开/刷新/初始化仿真入口，显示七轴新鲜反馈数量、六轴实际模式、执行器与现场许可状态。刷新页面不自动连接。
- 七轴仍是独立折叠模块。展开优先显示 Kp/Kd/前馈；规划、模型和高级保护进入第二层折叠。写字、抓取、只读映射和手柄输入监视保留。
- “以实机当前姿态初始化仿真”读取新数据，经 ID/型号配置、时间、既有 identity 映射、模型限位/碰撞检查后，更新 MuJoCo 的 qpos 与 ctrl、清零六轴速度，保留场景和夹爪状态。使旧点位计划失效，显示六轴误差和 FK。它不让实机追赶 HOME。
- XYZ 预览和仿真执行仍可用。本轮 `(200,150,200) mm` 仿真到点误差 **0.56234 mm**。
- 独立真实 SDK 适配器和执行循环已写入，使用官方 `motorbridge==0.5.6`，复用 B1 的七次多项式轨迹。默认不打开 CAN，不创建硬件执行线程。**没有接入网页真实执行按钮；生产 SDK 适配器只接受另行批准的单轴试验，拒绝六轴授权。**

## 本轮实机只读结果与具体阻断

1. SDK 三轮六轴读取成功，ID 1–6 对应，模式均为 0/MIT；一轮约 **148.5–149.5 ms**。型号仍来自既有配置，不是从电机读回的型号认证；整机序列号没有通过 CAN 核验。
2. 腕部速度寄存器出现非零波动，最高绝对值约 **0.075 rad/s**；不能凭位置变化小就把速度改成零。需现场确认是否静止、是否存在抖动及固件速度噪声。
3. 第一份记录 J2 **−0.0635°**，网页在 16:21 的新鲜读取约 **−0.31°**，低于模型下限 **0°**。网页同步已实际拒绝并给出轴号和范围，仿真没有被错误初始化。没有 wrap、裁剪、改 offset 或放宽限位。这是模型与当前边界读数的具体差异，**不是已证明机械越过物理限位**。
4. 网页真实只读连接验证了 **7/7** 新鲜反馈和六轴 MIT 模式，每轮约 380–391 ms（包含更多参数）。检查结束已断开只读查询；断开不等于去使能或物理停止。
5. 现场人员、独立断电手段、J2/J3 支撑、停止方式和动态方向验收尚未收到本轮确认。**因此尚不满足 P5 运动条件，不能直接开始 P6 XYZ 实发。**

## SDK 与旧界面审查

审查官方 [v0.5.6 源代码](https://github.com/motorbridge/motorbridge/tree/c652ce420e7da1008fa1864cc7f47d7d7c57fdb6)，同时检查本机 Python 包；没有声称对发布二进制做了逐字节源码重建证明。

- 旧机械臂页面 `JointControlPanel/LiveMoveScheduler` 最终走通用 `controlMotor/sendCmd`。旧版浏览器的时间调度不满足独立执行循环；保留 `WsGatewayClient` 原只读白名单，未解锁旧页面写入。
- 新适配器调用官方 `Motor.send_mit(q,qd,kp,kd,tau)`，不重写 CAN 编码。MIT 帧的 SDK 返回表示主机发送成功，没有每帧驱动 ACK。
- `controlled_stop()` 会在缓存增益偏低时换用默认增益，故不调用。`Controller.__exit__()` 会调用 `shutdown()` 并去使能全部设备，故不用上下文管理器；只调用 `close_bus()` 和释放句柄。
- 读取 q/qd 使用指定 host ID 的官方 f32 读取；mode 的 i8 API 可能按多个 host 重试。enable/disable 的状态确认也可能依次重试，每候选约 240 ms；因此不能把请求 timeout 当成实际整次调用上界，更不能套用 B1 的 10 ms 周期。
- `rs-06` 与 `rs-00` 的官方协议量程不同，软件校验使用对应量程。协议量程不是安全限值，实际帧还有量化误差。

## 执行器保证与限制

- 许可绑定完整配置哈希、轴集合、当次现场证据、有效期和机械支撑；只在进程内存在，token 原子消费，不能用同一许可启动另一执行器。重启不恢复目标或许可。配置批准不能生成许可。
- 先从设备读起点，检查六轴位置、速度、模式及时间；XYZ/手柄规划意图还必须绑定已预演起点。使能后再次读位置，首帧使用新读数，后续轨迹也据使能后读数重建。
- 轨迹 v/a/jerk、实测速度、跟踪误差和保守 MIT 力矩估算分别检查。力矩估算不是实测转矩或重力补偿。
- 独立线程执行，心跳不按浏览器帧发送 CAN。失焦、心跳过期、取消和许可到期禁止继续旧目标。SDK 调用返回后立即再次检查；包括使能启动阶段的命令时限，不突发补发。
- 实现的是**明确授权且已机械支撑轴的撤力停止**。不自动给 J2/J3 套用 disable，也没有实现/验收承重轴保持、制动或重力补偿。请求、SDK 发送/状态确认、单次静止读数和物理停止验收分开；`physical_stopped` 永远不因 SDK 成功自动为真。停止期间为 STOPPING；停止后仍有速度或读回失败必须 FAULT，仅另存“停止前曾到位”记录。
- 使用进程锁，并拒绝已有 CAN 订阅者；SDK 建连只接受一个预期的 raw catch-all 接收者，运行中监视接收者变化。**不是内核级排他锁**：不能阻止特权程序、TX-only SocketCAN、外部 CAN 节点或读取与发帧间的极短竞态。实发仍需关闭其他控制器并采用专用控制会话。
- Python/SDK 是软实时。一个阻塞中的官方 C 调用不能被线程取消立即打断，进程崩溃也不能保证断力；必须有现场独立停止条件。真实多轴启动/保持、物理停止和 XYZ 反馈联动留到 P5/P6。
- `MotionIntent` 预留 joint-waypoints 来源：单轴、XYZ、已规划手柄。当前没有浏览器硬件 heartbeat/execute 接口，不把它称作已完成的手柄实控。
