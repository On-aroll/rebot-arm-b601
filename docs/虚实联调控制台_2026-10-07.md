# 虚实联调控制台（原「书写任务」页）

改名日期：2026-10-07。入口 <http://127.0.0.1:8765/studio/console>，旧地址
`/studio/writing` 继续可用，书签不会失效。

这一页原来的名字只描述了"国庆快乐"那个演示任务，实际定位是**实机与仿真的联调入口**：
设备使能与限速、任务执行、手柄遥操作都在这一页收敛，三维视图只是其中一块。

## 为什么之前 `/zh/...` 打不开

Studio 的 i18n 会把语言写到地址栏最前面（`src/i18n/index.js` 的 `buildPathWithLocale`），
切换语言后地址变成 `/zh/studio/writing`。当时 `scripts/rebot_sim.py` 的路由只认
`/studio/` 与 `/studio-model/` 前缀，所以刷新或转发链接就是 `{"error": "Not found"}`。

现在 `do_GET` 先剥掉 `zh|en|es` 语言段再走原判断，并把 `/studio/console`、
`/studio/writing`、`/studio/simu` 都列为可硬刷新的前端路由。剥离只影响前缀匹配，
路径穿越仍然返回 403。

## 分区

- **运动与轨迹**（通栏置顶）：Three.js + URDF 三维视图，关节角取 MuJoCo **实际反馈**
  （`/studio-state`，160 ms 轮询），不是目标角。计划路径只在书写任务下显示，
  切到抓取任务会自动隐藏并禁用勾选。
- **电机模块**：七个自包含模块（ID 1–7），每块含 mechPos、`limit_spd`、本会话使能状态、
  模式选择、vlim、tau / kp / kd、目标位置与限位滑块，以及使能 / 去使能 / 下发目标 /
  切模式 / 写限速五个动作。这是与「机械臂模式」的关键区别：那边七个电机共用右侧一块面板
  （`JointControlPanel` 只显示当前选中的 `activeRow`），改哪一轴要先点它的卡片；
  这里一轴一块，直接改，不选中不翻页。写入受总开关 + 演练 + 限速兵三道闸控制，
  见下方「网关与总控」。读数与写入都由 `src/hooks/useMotorGateway.js` 直连网关，每轮约 125 ms。
- **任务执行**：可选「国庆快乐 · 连续立体书写」（`print_demo`，6 阶段）与
  「抓取并放置 · 往返搬运」（`grasp_demo`，13 步）。支持暂停、继续、取消、重置仿真与导出。
  执行中其他运动入口由服务端互斥锁挡住。
- **虚实逐轴对比**：实机读数、仿真读数、差值并排显示，差值超过 2° 标红。
  实机优先取网关读数，退回 `rebot-twin-sync` 发布的文件；两者都不可用时整列显示 `—`，
  不会用零位冒充读数。
- **参数与限速**：逐轴列出 `limit_spd` 并评估，超过 0.5 rad/s 标为偏快。
  首次实机动作建议压到 0.3 rad/s（约 17°/s）以下再谈放开。「下发限速参数」禁用。
- **手柄遥操作**：实时显示手柄轴与按键（`navigator.getGamepads`，150 ms 轮询，
  死区 0.08），用于先验证输入设备可用。「启用手柄控制末端」禁用，缺的是执行层。
- **接入边界**：把"本页允许对实机做的三件事"、使能状态为何恒为未知、
  RobStride 切模式会自动去使能这三条直接写在页面上，不靠翻文档。

## 实机只读数据链路

主路径是控制台直连网关，**不再需要额外跑 `rebot-twin-sync --follow`**：

```
控制台 useMachineMotors → ws://127.0.0.1:9002 → ws_gateway → can0
```

只允许 `set_target` / `robstride_read_param` / `close_bus` 三个 op，白名单断言在
`useMachineMotors.js` 里。刻意不复用官方前端的 `setTargetFor()`：它会在选中电机时写
`0x7026`（主动上报周期，会存进电机）并打开 `set_active_report`，见
`src/hooks/useGatewayBridge.js:239-285`。

备用路径仍保留，用于不经过网关的对照读数与镜像仿真：

```
rebot-twin-sync --follow  →  outputs/machine_live.json  →  GET /machine-state  →  控制台
```

- `scripts/rebot_twin_sync.py` 新增 `--follow`（持续读取直到 Ctrl+C）与每轮原子写出
  `outputs/machine_live.json`；`--no-live` 可关闭。写出的关节角是**钳位之前**的真实读数，
  钳位只影响推给仿真的值，不影响对比列。
- `scripts/rebot_sim.py` 新增只读端点 `/machine-state`（实机关节，超过 2 秒算过期）与
  `/machine-params`（`rebot_can_readstate.py` 的最近一次参数扫描），
  并在 `/studio-state` 里发布 `limits_deg` 供模块滑块取模型限位。
  **仿真服务不打开 CAN**，也不向实机下发任何指令。
- 启动只读跟随：

```bash
~/.local/bin/rebot-twin-sync --follow --dry-run     # 只读实机，不推仿真
~/.local/bin/rebot-twin-sync --follow               # 同时把实机姿态镜像到仿真
```

`--dry-run` 下实机与仿真的差值会一直很大（仿真停在原地），这是正常现象。

网关侧只读核实：`tests/verify_gateway_readonly.py`，报告
`outputs/gateway_readonly_verification.json`。2026-10-07 实测七轴全部读到，
且与 python-can 通路逐项一致（6 轴最大差 0.01°）；七轴 `limit_spd` 当前均为 1.0 rad/s。

**待核实的共存问题**：控制台每轮结束会 `close_bus` 归还总线。网关首帧显示
`router_mode: standby` 且带 `peer` 字段，看起来总线状态是按连接隔离的，
但这还没实证。若发现控制台轮询干扰了「机械臂模式」的会话，就把控制台轮询做成可关。

## 网关与总控

连接/断开做在这一页了，不必再去「机械臂模式」找。页面顶部一张「网关与总控」卡：

- **网关地址**：默认 `ws://127.0.0.1:9002`，可改；连接中禁用输入。
- **连接 / 重连 / 断开**：断开时总开关一并复位。页面加载会自动连一次。
- **状态行**：已连接 / 每轮耗时 / 距上次刷新 / 读到几轴。
- **总开关**：长按 1.5 秒才打开，防误点；随时可"立即关闭"。
- **演练模式**（默认开）：走完全部校验、把将要发送的完整 payload 记进日志，
  但**不发那一帧**。只有 `stop` 不受演练限制——急停永远真发。
- **限速阈值**：默认 0.3 rad/s（约 17°/s）。
- **动作日志**：最近若干条，含演练时记录的 payload 原文，可事后审计。
- **急停**：头部常驻按钮，对七轴依次 `set_target` + `stop`，连着就能按。

写入要过三道闸，全部在 `src/hooks/useMotorGateway.js` 里强制，不是界面自觉：

1. `armed` 总开关 —— 关着时 `write()` 直接返回"全局下发总开关未打开"；
2. `drill` 演练 —— 开着时校验通过也不发帧；
3. **限速兵** —— `enable` / `pos_vel` / `mit` / `vel` 之前，该轴 `limit_spd`
   必须读到且不超过阈值；目标还要落在模型限位内、与当前位置差值不超过 15°。

op 白名单也在这一层：只读三件套 `set_target` / `robstride_read_param` / `close_bus`，
写入 `enable` / `disable` / `stop` / `ensure_mode` / `pos_vel` / `mit` / `vel` /
`robstride_write_param`。**`set_id`、写零位、`clear_error` 不在名单里**，
底层 `send()` 会连发都发不出去。

运动 op 的单位是**弧度**，界面输入是度，换算在 `MotorModuleCard` 里做。
`pos_vel` 需要 `vlim` 与 `kp`（位置环刚度，官方默认约 60），`mit` 需要 `kp`/`kd`/`tau`
三个都填 —— 留空当 0 发出去等于给电机一条"没有刚度"的指令，所以宁可拒绝。

## 边界

- 默认状态仍是只读：总开关关着 + 演练开着，两道都过去才会真的发帧。
- **使能状态读不到。** RS 固件的 `get_state()` 与流式帧在本机失效，模块里的
  「本会话使能」只是页面自己记录的状态，不代表电机真实状态。
- 给未使能的电机发运动帧是**静默无操作**（总线返回 ok、固件忽略），
  所以顺序必须是先使能再下发；切换 RobStride 模式会让该轴自动去使能。
- 反馈过期只锁定浏览器入口，急停按钮也只是发 `stop` 帧，**都不是硬件急停链**。
- 手柄只到"能看见输入"，末端增量 → IK → 可达性预检 → 执行层这条链还没接。
  后端解算已存在：`scripts/rebot_core.py` 的 `ik()` 与 `check_path()`，以及 `/command` 的
  `ik_check` 动作。
- 未做：夹爪角度→位移正式标定、TCP 标定、统一执行层（实机与仿真同时执行同一轨迹）。

**下发任何实机运动指令前必须确认：正方向、零位、限位，且现场有人能断电。**
