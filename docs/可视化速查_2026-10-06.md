## 二、自建控制台（最推荐）

**这是唯一能在浏览器里拖滑块、点按钮的界面。**

```bash
rebot-sim serve
```

然后浏览器打开 **http://127.0.0.1:8765**

能做什么：

- 六个关节各一个滑块，拖动 → 机械臂跟着动
- 夹爪行程滑块
- 末端 XYZ 输入框 + 「求解并移动」（走 IK，会检查限位与插值路径碰撞）
- 四个按钮：播放关节轨迹 / 末端画圆 / 抓取并放置 / 恢复初始姿态
- 画面上拖动可旋转视角

换端口：`rebot-sim serve --port 9000`

> 界面上写的是"纯仿真 · 未连接实机"。它是本项目自建工具，不是 Seeed 官方软件。

## 四、官方示例（终端驱动）

Seeed 官方控制库自带的 Pinocchio + Meshcat 示例。

```bash
cd "/home/bonvoyage/Desktop/seeed Robotics"
~/.local/share/robotics/envs/rebot-sim/bin/python \
  external/reBotArm_control_py/example/sim/fk_sim.py
```

浏览器打开 **http://127.0.0.1:7000/static/**

### ⚠️ 控制入口在终端，不在浏览器

Meshcat 网页**只是显示器**，没有任何输入控件。控制是回到**你启动脚本的那个终端**里打字：

```
MeshCat 已打开. 输入 6 个 arm 关节角度（度）:
  q/quit/exit: 退出

关节角度 > ▊        ← 在这里输入
```

**怎么输入**：鼠标点一下那个终端窗口 → 敲 6 个数字（空格分隔）→ 回车。
不用敲 `>`（已经在那儿了），数字之间**只能用空格**，不能有逗号。

可直接用的输入（已用 `compute_fk` 逐个验算）：

| 输入（度） | 末端位置 [m] | 效果 |
| --- | --- | --- |
| `0 0 0 0 0 0` | [+0.3017, 0, +0.2177] | 零位，确认输入通路 |
| `0 90 90 0 0 0` | [+0.5377, 0, +0.4537] | 大臂展开，向上前方伸出 |
| `0 90 45 0 0 0` | [+0.4375, 0, +0.0664] | 向前平伸 |
| `45 90 45 0 0 0` | [+0.3100, −0.3099, +0.0664] | 底座转向侧方 |

⚠️ 避开 `0 90 0 0 0 0`：末端 Z 变成 −0.1367 m，跑到基座以下。

⚠️ **官方 docstring 的示例 `45 -30 15 -60 90 180` 是错的**——J2 的模型限位是
0~180°，`-30` 超范围，而 `fk_sim.py` 不做限位检查，会照算出一个物理上不可达的姿态。
守好范围：**J1 ±160°、J2 0~180°、J3 0~180°、J4 ±90°、J5 ±90°、J6 ±180°**。

退出：敲 `q` 回车，或 `Ctrl+C`。

同目录还有：

| 脚本 | 用途 |
| --- | --- |
| `fk_sim.py` | 正运动学，输入角度看末端位置 |
| `ik_sim.py` | 逆运动学，输入末端位置求角度 |
| `traj_sim.py` | 笛卡尔轨迹 |

## 五、ROS 2 侧（RViz 与 MuJoCo 窗口）

### 5.1 RViz 看 URDF

```bash
cd "/home/bonvoyage/Desktop/seeed Robotics/external/reBotArmController_ROS2"
source /opt/ros/jazzy/setup.bash && source install/setup.bash
ros2 launch rebotarm_bringup fake_rs_bringup.launch.py use_rviz:=true
```

**`use_rviz` 默认是 `false`** —— 不加这个参数，屏幕上一个窗口都不会出现。

### 5.2 MuJoCo 原生窗口 + ROS 2 物理仿真

```bash
cd "/home/bonvoyage/Desktop/seeed Robotics/external/reBotArmController_ROS2"
export PYTHONPATH="$HOME/.local/share/robotics/py312${PYTHONPATH:+:$PYTHONPATH}"
source /opt/ros/jazzy/setup.bash && source install/setup.bash
ros2 launch rebotarm_mujoco_rs mujoco_rs.launch.py \
  model_path:="/home/bonvoyage/Desktop/seeed Robotics/external/reBotArmController_ROS2/src/rebotarm_mujoco_rs/models/rs_grasp_scene.xml" \
  use_viewer:=true
```

**`use_viewer` 默认也是 `false`。** 另外 **`model_path` 必须显式给**——不给的话
`find_default_model()` 会向上遍历到本项目根目录，抓到 `models/rs_grasp_scene.xml`
（那是另一套模型，执行器叫 `joint1`，而这个包要的是 `joint1_motor`），随即崩溃。

可加参数：`simulation_mode:=physics`（默认 `kinematic`）、`arm_namespace:=rebotarm_rs`。

### 5.3 前置：把 mujoco 装到固定位置（一次性）

ROS 2 节点跑在系统 Python 3.12 下，看不到 rebot-sim 那个 3.10 venv。**一次性设置：**

```bash
mkdir -p ~/.local/share/robotics
mv "/home/bonvoyage/Desktop/seeed Robotics/downloads/_pkg2" ~/.local/share/robotics/py312
```

验证：

```bash
PYTHONPATH=$HOME/.local/share/robotics/py312 python3 -c "import mujoco; print(mujoco.__version__)"
# 应输出 3.15.0
```

> 若日后需要重装（例如换了机器）：
> ```bash
> pip install --target=$HOME/.local/share/robotics/py312 --no-deps \
>   mujoco==3.15.0 absl-py etils glfw pyopengl
> ```
> **必须带 `--no-deps`。** 不带的话 pip 会往目标目录塞一份 numpy 2.x，
> 把系统的 numpy 1.26.4 顶掉，而系统的 `scipy 1.11.4` 要求 `numpy<1.28` ——
> scipy 会直接坏掉，而 `rebotarm_mujoco_rs` 正好依赖 scipy。

## 八、看不到画面？按这三条排查

1. **是不是用了默认参数？** ROS 2 的两条 launch 的 `use_rviz` / `use_viewer` **默认都是
   `false`**。默认跑起来屏幕上什么都不会有，但话题和 TF 是正常工作的。
2. **浏览器地址对不对？** 自建控制台是 `:8765`，Meshcat 是 `:7000/static/`，别弄混。
3. **是不是在等你在终端输入？** 官方示例启动后是**阻塞等待输入**的，
   不去终端敲数字，它就一直停在那儿，网页上也不会有变化。

补充：渲染依赖 OpenGL 上下文。**在无图形会话的环境里（比如 SSH、受限 shell）**
MuJoCo 会报 `an OpenGL platform library has not been loaded`，
`rs_scene_camera` 会报 `X11: The DISPLAY environment variable is missing`。
这类报错不是配置错误，是环境本身没有显示。
