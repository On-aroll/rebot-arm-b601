## 重启电脑后最快启动

推荐终端执行本节命令。项目目录中也保留了 `启动项目.desktop` 和 `reBot 项目启动.desktop`；快捷方式路径适用于本机，换电脑时按实际目录修改。

程序会检查并启动以下服务，正常运行的服务直接复用：

| 服务 | 本地地址 | 内容 |
| --- | --- | --- |
| MuJoCo 与网页 | 127.0.0.1:8765 | 仿真、XYZ 预览、控制台 |
| 实机网关 | 127.0.0.1:9002 | 只启动 WebSocket 监听，等待页面明确连接 |
| ROS 虚拟验证 | 127.0.0.1:8767 | 隔离 Fake Driver，ROS_DOMAIN_ID=43 |

健康检查通过后自动打开网页。终端显示结果，按 Enter 关闭；后台服务继续运行。
不会下载依赖、重新编译、自动续跑动作、使能电机或写设备参数。
启动项目不是给电机上电；当前主页面提供一次现场确认与七轴统一使能/立即失能。

Kubuntu 首次打开新快捷方式可能询问是否信任/允许运行，这是桌面启动器的确认。
若双击显示文本或没有启动，可直接使用下面的终端命令：

```bash
cd /home/bonvoyage/Desktop/seeed_Robotics
python3 scripts/start_project.py
```

这里只启动软件服务，不启动 Codex 或 Cockpit Tools；AI 工具不是项目运行依赖。

## 需要真实 CAN 通信

普通双击仅显示 CAN 状态，不自动修改接口。电脑重启后 `can0` 可能处于 DOWN。

施工期间跳过这一节。恢复现场连接后，接好 USB-CAN、CAN 线和电源，再使用 **准备 CAN 并启动**。
也可在终端执行：

```bash
cd /home/bonvoyage/Desktop/seeed_Robotics
python3 scripts/start_project.py --can-up
```

该选项只在接口 DOWN 时设置 1 Mbps、关闭 listen-only/loopback 并将接口 UP；
需要输入本机 sudo 密码，不保存密码。配置失败则报告错误，不继续错误的配置步骤。
已经 UP 且正常时不重配；已经 UP 但总线或配置异常时不会强制 DOWN，以免打断现有通信。
未发现 USB-CAN 时仿真仍可使用。

成功后预期显示：`can0 UP / 1000000 bps / ERROR-ACTIVE`。
ERROR-ACTIVE 是正常 CAN 状态名称；BUS-OFF、持续增长的错误计数要排查线路。

页面操作：

1. 选择“实机操作”，点击“连接实机”，取得当前七轴反馈。连接只查询状态。
2. 点击“一键检测当前状态”，读取位置、模式与模型起点范围；日常启动不必重新晃动或找零位。
3. 当确实需要电源操作时，完成一个综合现场确认，点击“全部使能 · J1–J7”；需要撤力时直接单击“全部立即失能”。
4. 页面只记录请求结果；真实动力、保持力矩及撤力仍需现场观察。立即失能仍不能替代机械臂旁的独立断电，检测也不自动解锁真实 XYZ。

使能先七轴预检，再逐轴重新检查 MIT 模式、新鲜原始位置、六轴模型限位和显式 1° 起点容差与发送前页面焦点；不扩大目标范围。
不自动切模式、不发送保持 MIT 帧；仅 enable 不保证立即具有保持刚度。
失能不依赖位置或模式校验；撤去承重轴力矩前先支撑。
断开网页、关闭终端或结束网关不等于电机失能，也不能代替独立断电。
立即失能会中断后续轮询及尚未发出的使能，直接排入带明确型号与目标轴 ID 的 `disable`；失能后自动查询暂停，可点“刷新状态”恢复只读查询。网关仍按序处理已开始的 CAN 查询，按钮不提供硬件急停保证；网关或 CAN 异常时立即独立断电。用户已更正为失能后声音停止，但真实承重与运动效果尚未验收。

## 仿真与 ROS 虚拟验证

默认“离线验证”主流程：使能虚拟电机 → 输入 XYZ → 计算并预演 → 执行虚拟动作。模型和当前坐标持续跟随 ROS Fake 反馈，不需要手动同步起点。

“高级验证 · MuJoCo 写字 / 抓取 / 状态与导出”保留国庆快乐和抓取物理仿真程序；运行后明确显示 MuJoCo 任务反馈，可“返回当前执行反馈”。这些入口不会控制真实 CAN 电机。

ROS 服务新启动时默认虚拟失能；复用正在运行的服务时保留当前状态，不重置或停止任务。
完整步骤以 [项目使用手册](项目使用手册.md) 为准；[ROS 软件对接](ROS软件对接_2026-10-10.md) 保留早期接入记录。

真实 XYZ 轨迹、参数应用、零位及模式写入仍未开放验收。
用户 3/1/0 是软件草稿，不是真实 MIT 参数备份。

## 常用启动选项

```bash
# 只读状态检查：不启动服务、不写启动报告
python3 scripts/start_project.py --status

# 只启动仿真与网页
python3 scripts/start_project.py --sim-only

# 启动仿真与网关，跳过 ROS
python3 scripts/start_project.py --no-ros

# 不自动打开浏览器
python3 scripts/start_project.py --no-browser
```

`--status` 在所选服务未运行或异常时返回非零，方便脚本判断。
CAN 未就绪单独提示，不能从网关在线推断电机在线。
重复点击不会结束现有服务；同时点击时只允许一个启动过程。
端口被其他程序占用或无法确认进程身份时报告错误，不杀陌生进程。
没有设置开机自动运行，电脑重启后手动点击入口即可。

## 故障检查与日志

| 现象 | 检查与处理 |
| --- | --- |
| 页面打不开 | 运行 `--status`；检查 8765 与 `outputs/dashboard.log`。 |
| 仿真画面不更新 | 启动器会验证 /state 更新序号增加；异常时先结束任务，再手动重启后端。 |
| 网关正常但无真实反馈 | 核对电源、USB-CAN、can0、CAN 接线及页面型号/ID；网关在线仅表示监听正常。 |
| ROS 未启动 | 查看 `outputs/startup/ros.log`；检查 ROS Jazzy、锁定上游版本和已构建的 install 目录。 |
| 端口被其他进程占用 | 使用 `ss -ltnp` 查明进程；启动器不会自动结束它。 |
| 使能按钮灰显或拒绝 | 查看连接、当前轴反馈与具体提示；启动不代替现场确认和模式/限位检查。 |
| 页面仍是旧版本 | 先 Ctrl+Shift+R；改过前端源码时按下一节构建。 |
| CAN Broken pipe / BUS-OFF | 检查适配器直连、数据线、供电和 CAN 接线，恢复接口后再连接。 |

本次启动报告：`outputs/startup/last-start.json`。
服务日志：`outputs/dashboard.log`、`outputs/gateway.log`、`outputs/startup/ros.log`。
这些是本地运行产物，不是电机配置或安全验收报告。

## 只有改过代码时才做

### 后端更新

一键启动会复用现有服务，不会让已运行进程自动加载修改。
先完成或取消当前仿真/ROS 任务，再显式重启仿真：

```bash
cd /home/bonvoyage/Desktop/seeed_Robotics
bash scripts/restart_sim.sh --host 127.0.0.1
```

修改 ROS 服务后，在确认虚拟任务已结束时停止旧 ROS 进程，
核对确为本项目进程后再运行一键启动；不按过期 PID 直接结束进程。

### 前端更新

```bash
cd /home/bonvoyage/Desktop/seeed_Robotics/external/motorbridge-studio
VITE_BASE_PATH=/studio/ /usr/lib/chatgpt/resources/cua_node/bin/node node_modules/vite/bin/vite.js build
```

构建后刷新即可。此 Node 来自本机已安装的 Codex，应用升级可能改变路径。
日常启动使用已构建的 dist，不需要 Node、Vite 开发服务器或重新 npm install。

### 首次重建 ROS 依赖

已有环境正常时跳过。仅依赖丢失或首次部署时：

```bash
cd /home/bonvoyage/Desktop/seeed_Robotics
python3 scripts/setup_external.py
bash scripts/build_ros_validation.sh
```

不把重新安装依赖当作日常重启步骤，不同时运行 twin-sync 跟随和自主仿真任务。
