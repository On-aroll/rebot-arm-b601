# 实机通信打通（2026-10-07）

**结论：7 个电机全部找到并能读到位置。根因是 CAN 线物理脱落。**

---

## 一、根因

**连接机械臂的 CAN 线自己掉了下来。**

这不是软件问题，也不是适配器问题，也不是机械臂问题。
排查了大半天，最后是用户目视发现线是松的。

---

## 二、决定性判据：ENOBUFS 对照实验

### 判据来源

本机的 UTC-101 是**克隆适配器，不上报 CAN 总线错误**
（拔掉总线发帧，`berr_counter` 与 `bus_error` 仍为 0）。
**但 SocketCAN 的写路径会如实报错**：

| 情况 | 后果 |
| --- | --- |
| 帧被对端 ACK | 传输很快完成 → 队列排空 → 连续发送不失败 |
| 帧**未被 ACK** | 控制器不断重传 → 队列填满 → **`ENOBUFS (errno 105)`** |

### 对照结果（同一接口、同一模式、同样参数）

| 组 | 条件 | 结果 |
| --- | --- | --- |
| **A 组** | **CAN 线已脱落** | **第 22 帧失败**（0.046 s，≈476 帧/秒） |
| **B 组** | **CAN 线接好** | **连续 200 帧全部成功，无 ENOBUFS** |

**差距是决定性的。** 这同时证明 ENOBUFS 判据在本适配器上**有效**。

> 注：A 组之前还有一次标着"机械臂已连接"的测量，结果也是 22 帧 ——
> 说明那次线其实已经掉了，标签不成立。

## 三·补 符号约定：官方文档 + 实测双重确认

### 官方结论

`docs/gravity_calibration_rs_2026-07-17.md`（一台 RobStride DevArm 上实测）：

> **Sign convention: motor/mechPos frame maps to this repo's URDF with identity**
>
> **Motor zeros coincide with the URDF zeros** (rest pose = extended arm = URDF q=0)

本项目用的正是 "this repo's URDF" ⇒ **符号 +1（不取反）、零位偏移 ≈ 0**。

### 实测验证（18:47，用户手动顺时针旋转底座）

**关键**：URDF 里 `joint1` 的轴向是 **`(0, 0, −1)`（负 Z）**。
绕 −Z 的正向旋转（右手定则）= **从上往下看顺时针**。

| 项目 | 结果 |
| --- | --- |
| 用户操作 | 底座（J1）**顺时针**旋转 |
| mechPos 变化 | **+23.83° → +69.21°，净 +45.38°（增大）** |
| URDF 正向 | 绕 −Z 正向 = 顺时针 |
| **结论** | **顺时针 = mechPos 增大 = URDF 正向 ⇒ 符号 = identity (+1)** |

**官方文档与本机实测一致。**

### 另外两条实测结论

**① 无减速比（1:1）** —— 期间 J1 的行程达到 122°（−52° ~ +70.4°），
落在 URDF 的 ±160.4° 行程内。若有 9:1 减速比，122° 电机转角只对应 13.5° 关节角，
与观察不符。⇒ **mechPos 就是关节角。**

**② `mechPos` 是未归一化的多圈位置** —— J6 读到 −196.02°，
归一化到 **+163.98°** 后正好落在模型限位 ±180° 内。
（−196° 与 +164° 物理上是同一角度，差 360°。）
`rebot-twin-sync` 已**默认做归一化**。

## 四、这对项目意味着什么

**"以实机反馈驱动数字孪生"这条路是可行的。**

官方警告说的是 `get_state()` 那条路走不通 —— 但**参数读取是通的**，
位置读得到。所以只需换一条读取路径，不需要推翻方案。

**但有一个前提待确认**：`0x7019` 的参数定义尚未与官方参数表逐字核对。
当前依据是"数值合理、各轴不同、符合姿态"。**用于标定前应先确认。**

## 六、本次排查中被推翻的错误推断（留档）

| 推断 | 被什么推翻 |
| --- | --- |
| "帧被应答了，总线上有活节点"（据零总线错误） | 对照实验：拔掉线发帧，错误计数仍为 0 → **计数器不可信** |

| "缺地是根因" | 用户确认此前不接地也能通信 |
| "软件层可调项已穷尽，需换适配器" | **CAN 线脱落** —— 硬件连接问题 |

**共同模式：缺少对照与读回验证就下结论。** 真正的转折点是用户目视发现线松了，
以及那个 ENOBUFS 对照实验。
