# 实机电机参数表（2026-10-07 实测）

设备：reBot Arm B601-RS，7 个 RobStride 电机，CAN `can0` @ 1 Mbps。
读取方式：`motorbridge` 的 `robstride_get_param_f32/u8`（**只读**）。

## 一、电机配置

| 电机 ID | 关节 | 型号 | 依据 |
| --- | --- | --- | --- |
| 1 | joint1 | **rs-06** | 官方 `config/rebotarm_rs.yaml` |
| 2 | joint2 | **rs-06** | 同上 |
| 3 | joint3 | **rs-06** | 同上 |
| 4 | joint4 | **rs-00** | 同上 |
| 5 | joint5 | **rs-00** | 同上 |
| 6 | joint6 | **rs-00** | 同上 |
| 7 | gripper | **rs-00** | 官方 `config/rebotarm_rs.yaml`；实测注册 rs-00 成功、rs-06 失败 |

**夹爪（ID 7）标定（2026-10-07，`rebot-signprobe --ids 7` 探针，先开后合）：**
- **符号**：张开 → mechPos **增大**；闭合 → 减小。（开段增量全正、合段全负，已确认）
- **行程语义**：mechPos 是**角度(rad)**，仿真夹爪是**移动副(m)**，单指行程 `0–0.05 m`。
- **实测极值**：闭合端 ≈ **−3.986°**（起始/as-found 最小值），张开端 ≈ **+339.060°**（开合峰值）。
  行程 **343.046° = 5.987 rad**。
- **映射**：`finger_m = clamp((mechPos − (−3.986°)) / (339.060 − (−3.986)) × 0.05, 0, 0.05)`
  （仿真 `0.05 m` = 张开、`0 m` = 闭合，与官方 ROS2 桥 `real_to_sim.py` 方向一致：mechPos 增→disp 增→张开）。
- **与官方桥对照**：官方 `gripper_scale = 0.05/6.021 rad`（额定行程 6.021 rad），本机实测 5.987 rad，差 0.6%，属个体差异；官方假设闭合角=0 rad，本机实测闭合角≈−3.986°（零位偏差）。
- **twin_sync 参数**：`--gripper-closed -3.986 --gripper-open 339.060 --gripper-stroke 0.05`，若发现实机张开时仿真反而闭合加 `--gripper-invert`。
- **VBUS** = 47.76 V（实测）。
- ⚠️ 闭合参考是 as-found 最小值，未必是物理全闭；若需更准，做一次完整「全闭→全开」循环重测两端。

`feedback_id`（host_id）= **0xFD**，`responder_id` = 0xFE（ping 应答时返回）。
**映射关系：motor_id N = jointN**（1:1），来自官方配置。

## 三、✅ 符号与零位：官方文档已给出答案（不需要自己测）

来源：`external/reBotArm_control_py/docs/gravity_calibration_rs_2026-07-17.md`
（在一台 RobStride reBot DevArm 上实测：rs-06 ×3 + rs-00 ×4、ids 1–7、can0、48 V）

### 3.1 符号约定 = **identity**

原文：

> **Sign convention: motor/mechPos frame maps to this repo's URDF with identity**,
> and to the Seeed reBot-Isaacsim URDF with `q_urdf = −q_motor`.

**本项目的 `scripts/rebot_core.py` 用的正是 "this repo's URDF"**
（`external/reBotArm_control_py/urdf/RS/urdf/ReBot_Arm_RS.urdf`）。

→ **`q_urdf = q_mechPos`，直接对应，不需要取反。**

### 3.2 零位偏移 ≈ **0**

原文：

> **Motor zeros coincide with the URDF zeros** (rest pose = extended arm = URDF q=0).

标定结果表里 j2 的 zero offset = −0.06 ≈ 0、j3 = +0.02 ≈ 0，
结论是 "with **no zero offsets** and no extra terms"。

→ **电机零点与 URDF 零点重合，无需零点补偿。**

### 3.3 状态读取的正解就是读 `mechPos`

原文（解释 RS 版"重力补偿手感不对"的第一个原因）：

> **`get_positions()` returned frozen values on RS firmware**
> (type-0x18 stream frames are not decoded by `get_state()`),
> so `example/9_gravity_compensation.py` evaluated g(q) at **q=0 forever**
> — Fixed in this PR (**mechPos 0x7019 param reads**).

**即：`get_state()` 在 RS 固件上返回冻结值，官方改用读 `mechPos` 参数解决。**
本项目 `rebot-readstate` / `rebot-twin-sync` 采用的正是这条路径。

## 三·补 因此镜像失败只剩一个原因：**当前姿态超限**

用 identity 符号重跑镜像，只有两处需要钳位：

| 轴 | 实机读数 | 模型限位 | 差值 |
| --- | --- | --- | --- |
| J2 | −0.05° | ≥ 0° | 0.05°（可忽略，机械回差量级） |
| **J6** | **−196.02°** | ≥ −179.9° | **16°** ← 需要解释 |

**J6 超出 16° 有两种可能：**

1. **`mechPos` 是未归一化的连续位置（多圈累积）** —— 则实际关节角可能是
   −196.02 + 360 = **+163.98°**，落在 ±180° 内
2. 机械臂确实被拨到了模型限位之外

**待验证**：把 J6 往正方向拨过 180° 界线，看 mechPos 是连续变化还是跳变到 +180 附近。
**这项验证不影响其它五轴**，可以先跳过。

> 注：官方 `phase_a_sign_probe.py` 只用 mechPos 的**变化量符号**，
> 不涉及绝对量程，所以官方工具没有暴露这个多圈问题。

## 四、仍未确定的事项

| 事项 | 状态 |
| --- | --- |
| 六轴**符号约定**（电机正方向 ↔ 模型正方向） | ✅ identity(+1)，URDF `joint1` 轴 `(0,0,−1)`+实测顺时针 mechPos 增大；且**仅 J2≈0 处验证过**，非零 J2 符号待复核 |
| **减速比**（mechPos → 关节角） | ✅ 1:1（J1 行程 122° 落 URDF ±160° 内，非 9:1） |
| **零位**（实机零点 ↔ 模型零点） | ✅ 臂 ≈0（J2 差 0.05° 回差量级）；夹爪闭合角≈ −3.986° |
| **限位**（实机 vs 模型） | ⚠️ 模型侧已知；实机硬限位未独立测。仿真侧经 MuJoCo 反号映射到 `command()` 合法范围 |
| 夹爪（ID 7）的行程与 `mechPos` 语义 | ✅ 已标定（见上方夹爪标定段） |
| `0x7005` / `0x701B` / `0x7029` 等参数的确切含义 | ❌ 部分未定 |

**只读镜像已建立，但实机下发运动指令仍不应贸然进行** —— 虽然符号/零位/减速比已定，
实机硬限位与多轴联动安全性尚未独立验证；下发运动前须确认现场有人可断电。
（注：仿真服务 `rebot-sim serve` 若长期运行，修改 `rebot_core.py` 后必须重启该服务，
否则其内存中的 `Robot` 限位是旧版，会拒绝所有关节指令——可用 `POST [0,0,0,0,0,0]` 探活。）

## 五、确定符号的最安全方法（官方做法）

官方 `tools/gravity_calibration/phase_a_sign_probe.py` 注释原文：

> NO-torque sign check: streams mechPos while you **move joints by hand** —
> anchors the motor→URDF sign convention **before any torque is applied**.

**电机全程保持未使能，不产生任何力矩。** 用手拨动一根关节，
观察 mechPos 变大还是变小，即可定出该轴的符号。

本项目已封装为 `rebot-signprobe`（只读，不使能、不发运动、不写参数）。

**实测有效性已确认**：用户手动拨动后，mechPos 实时跟随变化
（J1 +18.3°、J6 −20.7°），说明读取灵敏可靠。
