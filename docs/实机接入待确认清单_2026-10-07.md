## A. 必须先定死的三件事

这三条**任一条没定，后面的工作都可能推倒重来**。

### A1. 这台设备到底是 RS 版还是 DM 版 ⚠️ 最高优先级

**为什么必须先定**：两个版本的电机协议、URDF、关节限位、末端帧名**全都不同**。

| | RS | DM |
| --- | --- | --- |
| 电机 | RobStride `rs-06`×3 + `rs-00`×4 | 达妙 `4340P`×3 + `4310`×4 |
| 传输 | CAN `can0` | 官方配置走**串口桥 `/dev/ttyACM0`** |
| URDF | `ReBot_Arm_RS.urdf` | `ReBot_Arm_DM.urdf` |
| 末端帧 | `gripper_end` | `end_link` |
| J2 / J3 | **0 ~ +3.14** | **−3.14 ~ 0**（符号相反） |
| J4 | ±1.57 | −1.87 ~ +1.57 |

**当前矛盾**：中转板丝印是**达妙科技**，但电机外观判断是 **RS**。

**若最终是 DM**：项目现有的全部仿真成果（RS URDF、Menlo 场景、动作程序里的
`gripper_end` 坐标、已验收的抓取姿态）**对应的都不是这台机器**，需要整体迁移。

**怎么定**：① 电机铭牌/丝印型号；② 购买记录或包装；③ **问 Seeed 用设备号核对**
（设备号 `20250907852512190405`）。

### A2. 用什么适配器连接

**当前用的 XCAN-USB 是克隆品**，有两个硬伤：

- VID/PID `0c72:000c` 冒用 PEAK PCAN-USB，实际设备串是 `XCAN-USB`
- **不上报 CAN 总线错误**（对照实验证实：拔掉总线发帧，TEC 仍为 0）
  → **排查 CAN 最主要的信号失效**，无法区分"对侧没应答"和"帧没发出去"

**需要确定**：Seeed 官方推荐用哪个适配器。若是 DM 版，达妙官方的 USB-CAN 桥
（官方配置里的 `/dev/ttyACM0`）是最匹配的选择。

**为什么重要**：现在所有"零响应"的结论都建立在一个不上报错误的适配器上，
**换一个能上报错误的适配器，排查效率会完全不同**。

### A3. 出厂参数

| 参数 | 现状 |
| --- | --- |
| CAN 波特率 | 官方 1 Mbps 来自**另一台 DevArm**（`docs/gravity_calibration_rs_2026-07-17.md`），未与本台核对 |
| 电机 ID 分配 | 同上：ID 1–7 是参考配置 |
| 反馈 ID（host_id）约定 | 同上 |

**需要确定**：本台设备的实际波特率与 ID 分配。

## B. 只读接入阶段要测出来的（文档既定第 1 步）

`docs/动作程序与数字孪生` 第 132 节已列明，原文照搬：

| 要测的 | 说明 |
| --- | --- |
| 七个电机的**轴编号与实际型号** | 哪个 ID 对应哪根轴 |
| **总线接口** | 通道、波特率、终端电阻 |
| **编码器位置** | 能否读到、单位、量程 |
| **零位** | 各轴机械零位与编码器零点的关系 |
| **正方向** | ⚠️ 原文提醒：**"当前六轴 URDF/Menagerie 的反号映射不能直接当作实机映射"** |
| **限位** | 实机限位 vs 模型限位 |
| **夹爪行程与 TCP** | 仿真里夹爪是"单指模型位移"，**未标定真实开口** |

### ⚠️ B 阶段有一个可能致命的已知限制

官方示例 `example/0x01rs06_test.py` 的 `state` 命令自带警告（原文）：

> motorbridge 内部协议配置问题：**RS 电机无法像 DM 电机那样查询**，
> 可能会出现读取不到实际电机状态的情况，请以实际运动效果为准。

**这意味着**：即使通信打通，**RS 电机的状态回读也可能读不到**。

而项目的最终目标是"**以实机反馈驱动数字孪生**"——
**如果状态读不回来，这条路的方案要重新设计**（例如改用仿真镜像而非实机反馈）。

**建议：把"能否读到编码器反馈"作为 A 阶段之后、B 阶段之前的第一个验证点**，
不要等做完标定才发现读不到。

## E. 建议的推进顺序（把上面的依赖关系串起来）

```
① 定型号（A1）—— 看一眼铭牌 + 问 Seeed，成本最低、影响最大
        ↓
② 换/借一个能上报总线错误的适配器（A2）
        ↓
③ 通电，只用官方波特率扫一次（A3）
        ↓
④ 通了 → 立刻验证"能否读到编码器反馈"（B 的致命限制）
        ↓
⑤ 能读 → 按文档第 1 步做只读标定
   读不到 → 重新设计"数字孪生"的方案，不要硬推
```

**①②③ 是"能不能开始"的门槛；④ 是"这条路走不走得通"的门槛。**
两者都不通过时，继续在软件层调整是没有意义的。
