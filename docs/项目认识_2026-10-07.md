## 一、这个项目要做什么

深圳矽递（Seeed）**reBot Arm B601** 机械臂的仿真落地，机型按 **B601-RS**
（RobStride 电机 / 48 V）推进，DM 为可选扩展。

**最终目标**（`docs/动作程序与数字孪生_2026-10-06.md` 结尾）：

> 输入动作程序 → 实机执行 → 以实机反馈驱动数字孪生模型；
> 屏幕上同时显示"计划目标"和"实机反馈模型"，二者有误差时能看出来。

**当前阶段**：仿真已完成并验证；ROS 2 桥接已完成（只读）；**实机接入刚开始**。

## 二、已建成的三条链路

### 链路 A：MuJoCo 物理仿真（项目主体）

**入口**：`MUJOCO_GL=egl PYOPENGL_PLATFORM=egl ~/.local/bin/rebot-sim serve`
→ 网页工作台 `http://127.0.0.1:8765/`

**核心是两套模型资产协同工作**（`scripts/rebot_core.py`）：

| 资产 | 来源 | 用途 |
| --- | --- | --- |
| `urdf/RS/urdf/ReBot_Arm_RS.urdf` | Seeed 官方控制库 | **运动学**（Pinocchio：FK / IK / 限位） |
| `mujoco_menagerie/seeed_rebot_devarm/scene.xml` | Google DeepMind Menagerie | **物理**（MuJoCo：动力学 / 碰撞 / 接触） |

**⚠️ 关键实现细节（`rebot_core.py` 第 32 行注释）**：

```python
# All six axes are reversed between these two pinned upstream assets.
self.d.qpos[self.qadr] = -self.target        # 写状态时取反
self.d.ctrl[self.act_ids] = -q               # 发指令时取反
self.lower = np.maximum(pm.lowerPositionLimit, -m.jnt_range[:, 1])   # 限位区间也要翻
```

**这两套上游资产的六个轴符号全部相反。** 所以代码里到处是 `-q`，
限位也要做区间翻转后取交集，再对 J1 额外夹到 ±150°。

**能力**：

- 关节空间 / 末端笛卡尔两种运动，IK 带**路径碰撞采样检查**（`check_path`）
- 夹爪为两个移动副（`joint_left` / `joint_right`），单位是**单指模型位移**（0–0.05 m），
  **尚未标定真实开口**
- 动力学用理想偏置力补偿：`qfrc_applied = qfrc_bias`，**明确标注不可当作实机增益**

**动作程序格式**（`docs/动作程序与数字孪生`）：

```json
{"version": 1, "name": "程序名", "steps": [...]}
```

| 操作 | 关键字段 | 说明 |
| --- | --- | --- |
| `move_joints` | `q_deg` 六个角度 | 官方控制 URDF 坐标，单位**度** |
| `move_tcp` | `xyz` 三坐标 | `gripper_end` 帧，单位**米**；`orientation: keep/down` |
| `gripper` | `finger_m` | 单指行程 0–0.05 m；`completion: position/contact` |
| `wait` | `seconds` | 保持上一步目标，按仿真时间等待 |
| `assert_object` | `object/xyz/tolerance_m` | 检查物体位置，失败即停止 |

上限 200 步；单步 0.1–60 秒；大位移自动延长时长使峰值速度 ≤0.7 rad/s。
**执行前整体校验**：未知字段、非有限值、超限、IK 无解 → 拒绝整个提交。

**完成判据**：关节误差 <0.02 rad、速度 <0.12 rad/s，连续保持 0.1 s；
夹爪位置误差 <2 mm，接触条件要求两指都接触。

### 链路 B：ROS 2 只读桥接（同一仿真源）

`scripts/rebot_ros_bridge.py` + `scripts/same_sim_ros.launch.py`

**设计立场很明确**：桥接**只读网页服务的真实物理反馈**，
**不新建第二个物理仿真、不订阅运动命令、不打开电机总线**。

| 话题 | 内容 |
| --- | --- |
| `/rebot/sim/joint_states` | 实测六轴弧度 + 两指米制位移 |
| `/rebot/sim/target_joint_states` | 同采样时刻的目标值（独立话题） |
| `/rebot/sim/status` | 连接状态、反馈年龄、实例 ID、采样序号、跟踪误差 |
| `/rebot/sim/robot_description` | 匹配的 URDF |
| `/tf`、`/tf_static` | 前缀 `rebot_sim/`，末端 `rebot_sim/gripper_end` |

25 Hz；生产者时间戳过期 >0.5 s 或断线时**停止发布关节状态**并在 status 标记失联。
文档特别提醒：**TF 旧值可能被下游缓存，不能只凭缓存模型判断在线。**

### 链路 C：Seeed 官方 ROS 2 栈（独立）

`external/reBotArmController_ROS2`，7 个包已构建（msgs / controller / agent /
mujoco_rs / bringup / moveit_config / moveit_demos）。此前验证过
`fake_rs_bringup`：16 个静态 TF frame，`base_link → gripper_end` = [0.302, 0, 0.218]。
与链路 B 是**两套独立的东西**，不要混。

## 四、从文档里提炼出的设计原则

这几条贯穿整个项目，**是判断"该不该做"的依据**：

1. **不伪造成功。** 原文："不会偷偷重置方块以伪造抓取成功"；
   "完成判定使用实机反馈……不以'发送成功'代替'动作完成'"。
2. **目标与反馈分离。** 日志区分目标角和实际角，ROS 里也是两个独立话题。
3. **明确声明边界。** 反复强调"仿真结果不能作为电机总力矩、额定负载或实机稳定性的验证"；
   "ROS 的 scene_detector 读取模拟器物体真值，不是图像识别"。
4. **单一控制写入者。** 程序运行时独占控制权，手动与另一程序都被拒绝。
5. **只读优先。** 实机接入先做只读反馈，再谈下发。
6. **不夸大验收。** 每次验收都写明"验证次数有限，不表示任意物体、任意位置都已通过"。

## 五、实机接入：文档早已定好的顺序

`docs/动作程序与数字孪生_2026-10-06.md` 第 132 节给出的四步：

1. **只读状态接入与标定** —— 获取七个电机的轴编号、型号、总线接口、编码器位置；
   核对零位、正方向、限位、夹爪行程、TCP。
   ⚠️ 原文特别提醒：**"当前六轴 URDF/Menagerie 的反号映射不能直接当作实机映射"**。
2. **由实机反馈驱动显示** —— 按时间戳发布实机关节状态；断连/过期明确显示，
   **模型不继续假装实机在运动**。此阶段**先不下发运动命令**。
3. **统一轨迹执行接口** —— 先仿真检查，再由实机适配器下发；完成判定用实机反馈。
4. **小幅低速联调，再完整任务。**

**当前卡在第 1 步**：连只读状态都还没拿到（详见 `实机连接检查_2026-10-07.md`）。

## 六、我看到的几处风险与不一致

只列观察，不做改动：

1. **两套模型的符号约定相反**（URDF vs MJCF，六轴全反）。
   这是已知并已处理的，但它意味着**任何"从仿真里读出的关节角"在跨链路使用时都必须先确认符号**。
   实机接入时更容易踩——文档已提醒不能直接套用。
2. **`models/rs_grasp_scene.xml` 与 ROS 2 包内同名文件是两份不同模型**
   （本项目版执行器叫 `joint1`，官方包要 `joint1_motor` + `joint7`）。
   已实测过 `find_default_model()` 会抓错。
3. **`docs/` 里存在新旧并存**：`上手指南_2026-10-06.md` 与 `reBot_仿真实施规划_2026-10-05.md`
   描述的是"7 包构建、fake_rs_bringup"那条线，而 `控制工作台_2026-10-07.md`
   与 `动作程序与数字孪生_2026-10-06.md` 描述的是"网页仿真 + 动作程序"这条线。
   **两条线的入口不同（`rebot-sim serve` vs `ros2 launch`），阅读时容易混。**
4. **上游资料缺口**：README 引用的 `scripts/setup_rs_workspace.sh` 在仓库里不存在；
   官方 1 Mbps / ID 1–7 来自**另一台 DevArm**；仓库内无接线文档。
5. **中转板印"达妙科技"而电机外观是 RS** —— 两个信号对不上，尚未解释。
