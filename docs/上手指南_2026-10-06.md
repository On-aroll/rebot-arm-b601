## 2. 五分钟跑起来（仿真部分，已就绪）

仿真环境是 uv 托管的独立 Python 3.10.22，入口 `~/.local/bin/rebot-sim`，任意目录可直接调用。

```bash
rebot-sim --help                 # 看全部子命令
rebot-sim verify                 # 端到端自检，约 3 秒
rebot-sim demo --kind circle     # 画圆轨迹演示
rebot-sim demo --kind joints     # 关节空间演示
rebot-sim grasp                  # 抓取演示（接触/摩擦，不用绑定约束）
rebot-sim serve                  # 网页控制台 http://127.0.0.1:8765
rebot-sim meshcat                # Meshcat 可视化 http://127.0.0.1:7000/static/
```

常用参数：`--seconds N`（时长）、`--video`（出 mp4）、`--trials N`（抓取重复次数）。

### 官方自带示例（已实测可跑，2026-10-06）

`external/reBotArm_control_py/example/sim/` 下有 **Seeed 官方的** Pinocchio + Meshcat 示例，
这是与官方 wiki 教程（`/cn/rebot_arm_b601_rs_pinocchio_meshcat/`）对应的一条路。
此前一直没跑过，实测可正常启动：

```bash
cd "/home/bonvoyage/Desktop/seeed Robotics"
~/.local/share/robotics/envs/rebot-sim/bin/python external/reBotArm_control_py/example/sim/fk_sim.py
# 浏览器打开 http://127.0.0.1:7000/static/
# 然后在终端输入 6 个关节角度（度），例如: 45 -30 15 -60 90 180
# q / quit / exit 退出
```

⚠️ **控制入口在终端，不在浏览器。** Meshcat 网页**只是一个显示器**，
没有任何输入控件（只有 Scene / Background / Lights 这类显示选项）。
`fk_sim.py` 用 `input()` 从标准输入读角度，提示符是 `关节角度 > `，
出现在**你启动脚本的那个终端**里。在网页里找输入框是找不到的。

**怎么输入**：鼠标点一下那个终端窗口 → 直接敲 6 个数字（空格分隔）→ 回车。
不用打 `>`（它已经在那儿了），数字之间**只能用空格**，不能有逗号。

可直接使用的输入（已用 `compute_fk` 逐个验算，2026-10-06）：

| 输入（度） | 末端位置 [m] | 效果 |
| --- | --- | --- |
| `0 0 0 0 0 0` | [+0.3017, 0, +0.2177] | 零位，用于确认输入通路 |
| `0 90 90 0 0 0` | [+0.5377, 0, +0.4537] | 大臂展开，向上前方伸出 |
| `0 90 45 0 0 0` | [+0.4375, 0, +0.0664] | 向前平伸 |
| `45 90 45 0 0 0` | [+0.3100, -0.3099, +0.0664] | 底座转向侧方 |

⚠️ **避开 `0 90 0 0 0 0`**：末端 Z 变成 −0.1367 m，跑到基座以下（实际会撞桌面）。

⚠️ **官方 `fk_sim.py` 的 docstring 示例本身有问题。** 它写的是
`例: 45 -30 15 -60 90 180`，但 **J2 的模型限位是 0~180°（`0 ~ 3.14 rad`）**，
`-30` 已超出范围。`fk_sim.py` **不做限位检查**，会照算不误并显示一个物理上不可达的姿态。
输入时请自行守住：**J1 ±160°、J2 0~180°、J3 0~180°、J4 ±90°、J5 ±90°、J6 ±180°**。

**退出**：敲 `q` 回车，或按 `Ctrl+C`。

它每次还会在终端打印末端位姿，例如：

```text
  末端位置: [+0.3017, +0.0000, +0.2177] m
  末端姿态: [+0.00, +0.00, +0.00] deg
```

**启动时的姿态是 q=0（零位）**，看起来是"收起来"的，与 `outputs/rs_initial.png`
（用的是 HOME=`[0, 0.7, 1.1, 0, 0, 0]`，末端 Z≈0.566 m）不是同一个位形。两者都对，只是位形不同。

> **交叉验证（2026-10-06）**：q=0 时官方 Pinocchio FK 给出末端
> `[+0.3017, +0.0000, +0.2177]` m，ROS 2 侧 `tf2_echo base_link → gripper_end`
> 给出 `[0.302, 0.000, 0.218]` m —— **两条独立路径一致**，说明官方 Pinocchio 路线与
> 官方 ROS 2 路线用的是同一模型、同一坐标约定。

**想要滑块/按钮式的网页控制**，用本项目自建的控制台（见上一节 `rebot-sim serve`），
它才是浏览器内可交互的。

同目录还有 `ik_sim.py`（逆运动学）与 `traj_sim.py`（笛卡尔轨迹）。

## 5. 坑清单（今天实踩，按优先级）

### 5.1 系统级

1. **本机无 CUDA。** RTX 3050 Mobile 由 **nouveau** 开源驱动接管，未装官方驱动，
   无 `/dev/nvidia*`、无 `/usr/local/cuda`。→ Isaac Sim、LeRobot 训练路线不可行。
2. **`packages.ros.org/ros.key` 是过期副本。** 指纹 `C1CF6E31...C654` 但 2025-06-01 到期。
   照抄官方教程会报 EXPKEYSIG。→ 从 keyserver 取同指纹的更新副本（有效至 2030-06-01）。
3. **keyserver 返回的是 ASCII 装甲格式，必须 `gpg --dearmor` 成二进制。**
   存成 `.gpg` 但内容是文本时，apt 解析不了，报 `NO_PUBKEY`。
   **致命细节：`gpg --show-keys` 两种格式都读，指纹校验会通过 → 假的安全感。**
   **指纹校验不能代替格式检查。**
4. **代理 MITM（`HTTPS_PROXY=127.0.0.1:35553`）。** `packages.ros.org` 的 https 证书校验失败
   → 用官方同样采用的 `http://` 通道。`raw.githubusercontent.com` 经代理超时。
5. **`set -e` 的安装脚本里，`apt-get update` 必须容错。** 上一轮遗留的坏 apt 源会让每次
   update 失败，脚本会在"修密钥"之前就被打断。自检修复必须排在一切 apt 操作之前。
6. **`ros2 --version` 不存在**（CLI 报 `unrecognized arguments: --version`）。
   校验用 `ros2 --help` + 包计数 + `ros2 topic list`。
7. **代理 shell 只能写工作空间**：`/etc`、`/usr`、`/var` 一律 Permission denied（root 也拒绝）。
   `/tmp` 在 bash 与文件写入工具之间不共享。→ apt / 系统级安装必须用户在自己终端执行。
8. **⚠️ 构建 ROS 2 包时，`python3` 必须是系统的 3.12，不能是 rebot-sim 的 3.10。**
   这是今天实际撞上的一次（2026-10-06）。

   **症状**：`colcon build` 报
   ```
   ModuleNotFoundError: No module named 'em'
     File "/opt/ros/jazzy/lib/python3.12/site-packages/rosidl_adapter/..."   ← 3.12 的包
     File "/home/bonvoyage/.local/share/robotics/python/cpython-3.10-.../runpy.py"  ← 3.10 的解释器
   ```
   `em` 缺失只是**表象**，根因是解释器错位：ROS 2 Jazzy 构建在 Python 3.12 上
   （`/opt/ros/jazzy/lib/python3.12`），而 uv 托管的 3.10 里既没有 `em` 也没有 ROS 的包。
   系统 `/usr/bin/python3`（3.12.3）本身**有** `em`（`/usr/lib/python3/dist-packages/em.py`）——
   所以**不要去给 3.10 装 em，那是错的解法**。

   **修法**（二选一，推荐第一条，不依赖 PATH 卫生）：
   ```bash
   colcon build --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3 -DPYTHON_EXECUTABLE=/usr/bin/python3
   ```
   ```bash
   export PATH=/usr/bin:/bin:$PATH    # 然后确认 python3 -V 显示 3.12.3
   ```

   **关联**：`rebotarm_bringup not found` 这类"包找不到"报错通常是**级联失败**——
   前面的 `rebotarm_msgs` 没构建成功，`install/` 里就没有东西。先看第一个 Failed 的包，
   不要急着追"找不到包"。
9. **⚠️ 工作空间路径含空格会打断 launch 里的 `python3` 调用。**（2026-10-06 实测）

   **症状**：`ros2 launch` 起来后节点列表只有 driver，没有 `robot_state_publisher`；
   TF 树为空；日志里
   ```
   Command: python3 /home/bonvoyage/Desktop/seeed Robotics/.../rviz_urdf_compat.py ...
   Captured stderr: python3: can't open file '/home/bonvoyage/Desktop/seeed'
   ```
   **根因**：上游 launch 写的是
   ```python
   Command(["python3 ", rviz_urdf_compat, " ", urdf_file])
   ```
   替换后的路径**没有加引号**，而本项目路径 `seeed Robotics` 带空格，参数在空格处被截断。
   官方环境路径无空格，所以上游不会暴露这个问题。

   **修法**：给路径加引号（已改为本地补丁，见第 3 节末）：
   ```python
   Command(['python3 "', rviz_urdf_compat, '" "', urdf_file, '"'])
   ```

   **教训**：这类"路径含空格"的问题在 Linux 上常被忽略，但凡是把路径拼进命令字符串的
   地方（`Command`、`os.system`、shell 脚本）都会中招。**能选就选无空格的工作目录。**
10. **⚠️ `rebotarm_mujoco_rs` 需要把 `mujoco` 装进 Python 3.12，不是 3.10。**（2026-10-06 实测）

    **症状**：`ros2 launch rebotarm_mujoco_rs mujoco_rs.launch.py` 后
    `mujoco_rs_sync` / `rs_task_server` / `rs_scene_camera` 三个节点全部
    `ModuleNotFoundError: No module named 'mujoco'`（`rs_scene_detector` 存活）。

    **根因**：这是坑 8 的**镜像**。坑 8 是 3.10 解释器去跑 3.12 的包；
    这里是 **3.12 解释器需要 `mujoco`，而 `mujoco` 只装在 rebot-sim 的 3.10 里**。
    ROS 2 节点由 `ros2 launch` 用系统 python3.12 启动，看不到 venv 里的包。
    实测系统 3.12 有 `numpy 1.26.4` / `scipy 1.11.4`，**没有 `mujoco`**。

    **上游缺口**：`rebotarm_mujoco_rs/package.xml` 只声明了 `python3-numpy` 与
    `python3-scipy`，**没有声明 `mujoco`**——所以 `rosdep` 也不会替你装。

    **修法**（先确认 apt 有没有现成包）：
    ```bash
    apt-cache policy python3-mujoco ros-jazzy-mujoco-vendor
    # 若都没有，再考虑装进系统 3.12（Ubuntu 24.04 有 PEP 668 保护，需显式放行）
    sudo pip install --break-system-packages mujoco
    ```
    ⚠️ `--break-system-packages` 会改动系统 Python 环境，属权宜之计；
    若日后 ROS 2 出问题，这是第一个要排查的点。版本建议与 rebot-sim 保持一致
    （当前 3.15.0），避免两套仿真的数值行为不一致。

    **注意**：仿真链路（`rebot-sim`）与 ROS 2 链路对 `mujoco` 的**依赖方向相反**——
    前者要 3.10 有它，后者要 3.12 有它。两边版本要对齐。

### 5.2 大文件下载

8. **codeload 不支持 HTTP Range** —— 恒返 200（非 206）且从字节 0 重发。
   按"追加续传"写下载器会得到多段拼接的垃圾文件（实测造出 127 MB 废料，内含 55 个 gzip 头）。
   **判据：响应 `status != 206` 就绝不能 append。**
9. **github / codeload 经本机代理被限速到 20–40 KB/s，且与 502 交替出现。**
   曾据此误判为"GitHub 整体不可达"——实际一直连通，只是慢。
10. **解法：走 jsDelivr CDN 逐文件取**，实测 1603 KB/s（快约 60 倍）。
    清单用 GitHub API `git/trees/<sha>?recursive=1`；
    `data.jsdelivr.com` 的目录 API 返回 **403**，不可用。

### 5.3 模型口径

11. **两份 RS URDF 只差网格路径，不是模型分叉。** ROS 2 版 19,716 字节用
    `package://rebotarm_bringup/description/RS/meshes/...`，控制库版 18,078 字节用 `../meshes/...`。
    84 处差异全是 `filename=`，限位完全一致。→ 切换运行时只需换路径写法，两侧文件不可互换。
12. **同名 `rs_grasp_scene.xml` 是两个不同文件**：上游 3,199 字节 vs 本项目
    `models/` 下 22,214 字节（后者加了地面/桌面/方块/灯光）。引用必须写全路径。
13. **`reBotArmController_ROS2` 上游未声明许可证**（GitHub API `license=None`）。
    涉及分发前需单独确认。
