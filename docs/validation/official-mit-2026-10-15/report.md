# 官方控制接入与有界实机试验

现有分支 `codex/mit-console-protection`，保留网页、IK、MuJoCo、Mock、任务会话和 SDK。**已测到多轴真实运动，但 XYZ 到位尚未完成。** 本轮用户授权小幅慢速迭代和任务内增益调整；保存的 3/1/0、设备调定值、零位、限位未覆盖。J7 不参与 XYZ，没有在本轮驱动夹爪。

## 复用与适配

使用 Seeed SDK `6415d43130d1e143c70dc106096a857ac5556f81` 的真实 `RebotArmEndPose._loop_cb` 与 JointGroup，来源模型/配置均带指纹。参考 Yang-Ci `aa807cf2affe85b13b86221159871aae7742c01b` 的 J1 80/5 上限和立即安装当前位置保持的启动方式。没有启动另一个 CAN 所有者或调用自动回零、切模式的上游生命周期。

初次实验方案 Kp 为 80/75/75/40/40/40，Kd 为 5/6/6/4/4/4，在锁定官方/参考配置范围内。逐轴使能前复读该轴，紧接使能发送新鲜当前位置、零速度、零前馈保持，再完整复读和验证；小于运动上限的瞬态须在既有 0.3 秒窗口内停稳。任务内重力力矩在 4 秒中渐变建立，形状直接调用官方 `GravityCompensation._transition_blend`。上游原本以此过渡增益，**这里将其用于力矩建立属于本项目适配**，不是官方默认或实机已调参数。

原 0.02 rad/s 试验速度、加速度/jerk、软件力矩 1/3/9/3/1/1 N·m 保留；实验方案的 J1/J2 跟踪边界收紧为 0.6°/0.75°，其余仍为 1°，不以放宽误差通过到位。使能后的起点漂移没有改成软件零位；原始反馈不裁剪。失能先发送，之后记录短暂回弹与连续安静反馈，最多观察反馈期限加稳定窗口；不再用一个瞬时样本代表最终停止，也不把 SDK ACK 当物理停止验收。失败信息分别显示实际跟踪误差或软件力矩估算。

## 验证及剩余条件

110 项虚拟 SDK/执行器/任务检查、15 项模型检查、24 项相关前端检查与生产构建通过。自动测试不连接真实 CAN；上表明确列出另外执行的真实试验。单击停止、取消、失联、首次保持、渐变中取消、连续停止观察和既有限速保留经过回归检查。

尚未区分支撑接触、实际工具/质量与模型差异、摩擦和控制采样时序对保持偏差的贡献。真实跟踪未通过，不放宽 1° 边界继续推力、不照搬另一台机器的重力缩放或偏置。用户已确认支撑没有限制 J1 转动，且连杆与夹爪均未接触支撑物或桌面。这是用户的观察记录，底座安装方向、连杆相互接触与实际质量/零位映射仍未独立验证。不要要求手托承重轴，也不要把接触状态下的数据拟合成正式重力标定。

当前发送与同步 SDO 反馈查询仍串行，真实六轴刷新约 0.15 秒，并非上游独立发送线程的 125 Hz。SDK ACK、反馈稳定和按模型算出的 TCP 坐标均不等于现场硬件急停、完整动态标定或独立空间精度验收。后续应先排除外部接触、核对控制周期与实际保持偏差，再做同样有界的载荷/保持验证与网页 XYZ 验收；不得宣称国庆书写或所有七轴已调好。

初次网页检查（仅预演，早于下方实发续验）：`/zh/studio/console` 已实际加载实验选项并连接七轴只读反馈。目标 `[300.59,16.23,227.02]` mm 的模型预演通过，预计运动 1.5 秒、任务时限 7 秒、求解残差 0.001 mm，距当时反馈约 5 mm；未从页面发送执行或使能。最终 J2 0.75° 边界仅经过离线检查和页面预演，尚未实机重试。见 [页面截图](console-profile.png)。

另外直接运行了锁定官方工程的 `tools/gravity_calibration/fit_sweeps.py`，对其附带的 J3 数据使用 `--qmin 0.4`，复现 897 个样本的拟合结果：缩放 0.946、偏置网格 0.02 rad、残差 RMS 0.265 N·m。它是另一台机器的既有数据，不是本机标定，未应用任何系数或零位。官方实测工具可用于后续测量，但其原采集脚本会切模式、自动使能、扫动默认 2.2 rad 并在结束时降低机械臂；不能直接运行在本轮小动作试验中。只复用了只读拟合工具。最后一次本机重力渐变记录的连续命令批次间隔中位数约 0.25 秒，另保留为时序问题的证据。

## 网页实发续验：官方 J3/J4 增益及逐帧证据

J3/J4 改用 SDK YAML 中的 150/10、50/5；任务 Kp 80/75/150/50/40/40、Kd 5/6/10/5/4/4。J3/J4 跟踪边界相应收紧为 0.6°/0.75°，保留原 9/3 N·m 包络。第一次网页续验使用 4 秒渐变，因 J3 误差 0.601° 停止；当时只有 29 批计数，没有逐帧记录，不能为它补造精确前馈或超界时序。副本 [4 秒试验](web-official-gains-4s.json)。

随后重力建立改为 8 秒，并从网页预演/执行 `[300.73,15.94,226.27]` mm，距起点约 5 mm，速度 0.02 rad/s，预计轨迹 1.5 秒、运行时限 7 秒（启动建立另在有界现场许可内）。**启动保持阶段即因 J3 误差 0.645° 停止，未进入 XYZ 轨迹。** 六轴均取得失能回执，停止后持续 0.3 秒速度样本满足稳定门限，未声称独立物理停止验收。原始 [8 秒试验](web-official-gains-8s.json) 保留当时的控制指纹、目标、起点、38 批记录和停止观察；这两次由网页任务执行，页面停止入口有效。

最后一批完整 J3 请求：目标 0.3418°、读回 0.9106°、差分速度 0.00495 rad/s，前馈约 4.296 N·m，比例项约 −1.489 N·m；按 MIT 公式的软件有符号估算约 2.757 N·m。**这是主机算式，不是实测转矩，也不是质量缩放标定。** 当时前馈尚未完整建立就已偏移，不足以证明只是低 Kp，也不能从这一段瞬态猜测缩放系数。由触发停止的关节角算得末端约 `[299.88,11.17,234.23]` mm；释放后约 `[300.75,10.89,226.22]` mm；都是模型 FK，目标未到达。分析 [JSON](web-8s-analysis.json) 和 [逐帧 CSV](web-8s-trace.csv)。

修复了两个证据/同步问题：终端一次落盘完整命令记录，HTTP 轮询仅返回小状态；停止后最新反馈更新模型，故障触发反馈单独保留。后续还修复了某批在后轴失败时前轴请求漏记、异常发送可能到达设备却未留证的问题：记录尝试、主机发送完成或可能已达驱动器的异常。此修复晚于上方 8 秒记录，不能将该原始记录宣称为完整线级 CAN 证据，也不回填旧数据。

当前代码 113 项虚拟 SDK/任务检查、15 项模型检查、24 项相关前端检查与构建通过。保存的 pending 草稿 SHA256 仍为 `fb34001a6aad21c25b53f25ba9b7781d7882f391f745467f00f1e1a6af8f3b3f`，设备参数写入为 0。下一次真实试验应先核对底座重力方向与本机受控保持力矩，不重复当前失败方案，不放宽边界强行执行。网页模型持续跟随实测位置的能力已存在；承重模型、XYZ 到位和 J7 标定仍未验收。

## 驱动器反馈能力核查（只读，未出力）

在没有活动任务、网页归还 CAN 后，沿用 Seeed 注册/总线所有权进行两轮六轴只读核查。48 次请求全部返回：`0x701A iqf`、`0x302C torque_fdb` 此时均为 0；`0x7029 zero_sta` 均返回原始 1，不能据此宣称 URDF 零位或方向已经标定。单次读取中位约 8.14 ms。控制帧和设备参数写入为 0。原始 [寄存器响应](diagnostic-register-capability.json)。参数定义来自 [RobStride 官方 Python 协议](https://github.com/RobStride/Python_Sample/blob/main/robstride_dynamics/protocol.py)。这些静止零值仅证明对应读取请求有响应，**未证明出力时数值会更新、单位/符号准确或是独立实测转矩**。

下一次显式选择“官方范围增益”并执行时，现有 worker 会附加 J3 的电流与转矩读取，记录各自请求/接收时间；不修改目标、增益、前馈算法或包络。只加 J3 两次读取，避免把额外查询扩展到整个六轴周期。参数获取时间独立于 mechPos 时间，位置差分仍用原位置采样窗口。额外查询仍接受取消、租约和命令期限检查，超时、无效数值或超过原命令期限会停止，不能通过加测量延长期限。默认方案和单轴旧入口不自动增加读取。

119 项虚拟 SDK/执行器/worker 检查通过，新增覆盖位置差分初始化不丢诊断值、取消中止后续查询、诊断超时和命令过期停止、非有限值拒绝，以及电流/转矩读数不被偷偷当作新前馈或增益。新采集代码尚未进行出力测量；当前仍需现场底座安装方向，真实 XYZ 仍未验收。


## 直立安装确认、出力反馈与自动三秒采集

用户已观察确认底座直立固定在水平桌面，暂沿用官方重力方向；这是现场观察，不等于各关节物理零位、实际质量或连杆相互接触已经独立核验。

普通启动增加 J3 只读诊断后，从网页执行相同量级的邻近目标。页面旧会话第一次拒绝了请求，没有启动新的 worker；刷新后的一次请求真实启动。原计划依靠页面停止提前结束，但工具往返期间已触发 J3 0.601° 误差保护，**不能把它写成三秒内结束**。记录 [出力电流采集](web-j3-current-capture.json)：37 批，J3 电流原始读数约 −0.179～3.343 A，转矩寄存器始终 0；六轴失能回执齐全且随后反馈稳定，XYZ 轨迹未开始。电流变化证明该诊断字段会响应，不能用额定转矩常数换算并宣称独立转矩标定。

为避免依赖人工/工具点击时序，新增独立 `StartupObservationIntent` 和同源网页 `probe-startup` 操作，复用本次预演、起点复读、现场许可、增益及启动过程。从首次使能尝试起三秒检查结束、停止发新目标并请求撤力；即使上游渐变提前结束也不会进入 XYZ。仅允许已审核的六轴官方范围方案；默认旧方案不增加诊断动作。SDK 同步阻塞仍可延迟实际撤力，软件计时不是硬件急停。

新入口已从现有控制台实测一次。记录 [自动三秒采集](web-startup-observation-3s.json)：25 批，终态 `CANCELLED`，原因“三秒启动采集结束”，最后主机目标距首帧 2.969 秒；六轴失能有 SDK 回执，随后连续反馈稳定，未宣称物理停止独立验收。J3 原始电流约 −0.256～0.691 A、前馈末值约 0.711 N·m；转矩寄存器仍为 0，不能用于本机受力标定。没有执行已预演的 XYZ，未改驱动器参数、零位或保存草稿。汇总与原始文件指纹见 [分析](startup-observation-analysis.json)。

同时修复长时间闲置页面复用过期会话：每次明确点击新任务前获取新会话；可能已下发的执行请求一律不自动重试。任务取消显示后端结束原因，避免将启动观测误作 XYZ 到位。123 项虚拟 SDK/执行器/worker 检查、26 项相关前端检查及生产构建通过，新增覆盖首次使能超时、诊断无轨迹、配置来源要求、固定三秒与页面会话更新。真实出力试验独立列出，不包含在虚拟测试数量中。

当前剩余条件：正常重力方向已由用户确认；J3 保持与模型预测的差异仍未解释，不能据此任意改质量、角度映射或放宽包络。下一步需对照当前整臂实际侧面姿态与模型，排除物理零位和连杆相抵，再进行受控保持力矩辨识。真实 XYZ 到位、J7 标定和书写仍未验收。
