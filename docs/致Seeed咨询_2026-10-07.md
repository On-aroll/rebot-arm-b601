**日期**：2026-10-07
**设备号**：`20250907852512190405`
**现象**：按官方文档配置 CAN 接口后，无法与机械臂建立任何通信。

---

## 一、我们的配置

| 项 | 值 |
| --- | --- |
| 主机 | Ubuntu 24.04.4 LTS (noble)，内核 7.0.0-34-generic |
| USB-CAN 适配器 | USB-TO-CAN **UTC-101**（VID:PID `0c72:000c`，设备串显示 `XCAN-USB`） |
| 驱动 | 内核自带 `peak_usb` |
| 接口 | `can0`，1 Mbps，`listen-only off`，`loopback off` |
| 软件 | 官方控制库 `reBotArm_control_py`（commit `6415d431`）+ `motorbridge` 0.5.0 |
| 机械臂 | 已通电（48 V，MEAN WELL LRS-600-48） |

**接线**：适配器 3 孔端子 `CANH / CANL / GND` 中，`CANH`、`CANL` 接到机械臂侧
中转板的 CAN 引出线（该 2 芯插头只有 H / L 两根线，**无接地端**）。

| 检查 | 结果 | 方法 |

| 适配器内部通道 | 正常 | 自环模式（`loopback on`）发送后能收回自己发的帧 |
| 机械臂供电 | 已确认 | 用户确认通电，电机端可见 |

## 四、一个影响排查的结构性问题

**我们使用的 UTC-101 适配器不上报 CAN 总线错误。**

对照实验：**把 CAN 线从机械臂上拔掉**（总线上没有任何节点），
再发送 3 帧 —— 预期必然出现 ACK 错误、TEC 上涨，但实测：

```
berr_counter: tx=0  rx=0
bus_error=0  bus_off=0  error_passive=0
```

**即该适配器不会上报总线错误。** 这导致无法区分下面两种情况：

- (a) 帧确实送上了总线，只是没有电机应答
- (b) 帧根本没送出去（适配器外部收发器未驱动总线，或线路问题）

**这是目前最大的排查障碍。**

   是另一台 DevArm 的实测值，我们无法确认是否适用于本台）

   （官方仓库中未找到接线文档，README 提到的 `scripts/setup_rs_workspace.sh` 也不存在）
4. **官方推荐的 USB-CAN 适配器型号**，或一份已知可用的适配器清单
5. 关于官方示例中提到的限制——
   "**motorbridge 内部协议配置问题：RS 电机无法像 DM 电机那样查询，
   可能会出现读取不到实际电机状态的情况**"——
   是否有官方说明或替代方案？**这直接决定我们能否实现"实机反馈驱动数字孪生"的目标。**
6. 是否有**最小可用的官方自检流程**（例如一段确认能与出厂设备通信的命令），
