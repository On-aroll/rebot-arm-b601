# 左侧工具栏与项目启动台

更新于2026年10月17日。按用户要求，将功能导航移到左侧，另设完整工程启动页面。

## 日常入口

双击桌面「ReBot Arm B601-RS 项目启动台」。启动器调用 `scripts/quick_start.sh --web-only`，只启动网页服务并打开 `http://127.0.0.1:3002/startup.html`。网页服务关闭时，不能仅靠访问一个 URL 启动本地进程，因此桌面图标是冷启动入口。

在启动台选择对象，按编号点击。所有必需步骤就绪后，点击「进入操作工作台」，会在本次导航中连接所选对象的反馈；不准备、不接管、不使能。普通打开或刷新 `http://127.0.0.1:3002/` 仍不自动连接。进入意图通过一次性 sessionStorage 标记传递并消费。

## 启动步骤

| 步骤 | 实际操作 | 就绪依据 |
| --- | --- | --- |
| ROS 2 环境 | source 既有 rs_env，核对包与 Python 依赖 | 检查命令成功；ROS 2 无需 roscore |
| ROS 联动接口 | 独立启动 ROSBridge 9090 | 本项目进程与 WebSocket 连接 |
| 仿真 | 启动 Fake、MuJoCo 和场景工具 | 新鲜控制反馈与 MuJoCo 状态同时存在 |
| CAN（实机） | 固定 can0 / 1 Mbps / up | ip 查询接口已启用、速率正确、未 BUS-OFF / STOPPED |
| 实机反馈 | 复用 hardware-launcher 的唯一 CAN 驱动 | 有效且新鲜的状态；服务就绪不代表可运动或已使能 |
| MCP（可选） | 仿真命名空间接口 8081 | 本项目进程与监听端口 |
| 文本代理（可选） | 127.0.0.1:8082，连接仿真 MCP | 本项目进程与监听端口；模型配置需另行完成 |

`start_component.sh` 仅接受固定组件名。新仿真分步启动设置 `REBOTARM_START_AGENT=false`、`REBOTARM_START_ROSBRIDGE=false`，避免捆绑启动；旧脚本默认行为保留。已有服务按真实反馈复用，异常进程不自动重启、不另起第二份驱动。

## 界面与控制边界

左侧包含原12项功能，以及分步准备、重置维护、ROS高级连接设置。右侧只显示所选操作的参数、坐标、说明和模型/相机；原功能大网格及重复页签隐藏，连接操作压成简短工具条。模型默认展开，宽屏与参数并排，窄屏上下排列。

原功能表单、输入值、程序、驱动配置及业务处理器沿用。切换仅改变显示和定位，不执行程序或重置。重置入口只展开相应操作区，仍需点击实际重置按钮；现场确认与显式手动使能保持不变。

启动 API 仅接受本机回环地址、合法 Host 与同源写请求，无任意命令、路径、参数入口。每步有互斥任务、前置条件、真实状态及有界日志，浏览器刷新不重复启动。后端 ROS 观察器只订阅三个状态话题，不取得租约，不建立 CAN socket，不调用使能、运动或重置服务。

CAN 按钮只配置网络接口。接口未启用时，通过标准 Polkit 对固定 ip 参数请求本机认证；没有新增免密规则。持有 CAN 驱动或其他接收者时拒绝重配，不自动 down / restart 接口。接口已是 UP / 1 Mbps 时直接复用，不触发认证。
