# 完整控制：官方参数对齐

2026-10-16，按用户要求，将网页完整控制从小幅试验预算迁移到有来源的官方参数。当前完整方案为 `native-csp-twin-full-v3-official`。默认速度仍为 0.1 rad/s，用户可直接输入，连接和切换模式均不自动使能。

## 参数与来源

| 项目 | 原完整方案 v2 | 当前完整方案 v3 | 依据及含义 |
| --- | --- | --- | --- |
| 关节速度输入上限 | 0.9 rad/s | 官方网页上限 1.5 rad/s，并取六轴设备内限速的最小值 | [Seeed Web 教程](https://wiki.seeedstudio.com/cn/rebot_arm_b601_rs_web_simulator_developer_guide/)；本机六轴只读值均为 1.0，故页面实际允许到 1.0 rad/s |
| 轨迹加速度 | 0.08 rad/s² | 4 rad/s² | 同上，在线轨迹 `stream_acceleration_limit` |
| 坐标轨迹 jerk | 0.4 rad/s³ | 30 rad/s³ | 同上，`stream_jerk_limit`；键盘/手柄渐变目前只约束加速度，不宣称限制 jerk |
| 手动参考速度比例 | 输入上限的 80% | 输入上限的 100% | 取消本工程完整模式的额外八折折减；仍受平移/姿态输入、雅可比与边界制动影响 |
| J1–J3 / J4–J6 驱动限矩 | 1 / 3 / 9 / 3 / 1 / 1 N·m | 36 / 14 N·m | [MotorBridge 官方 RS 预设](https://github.com/tianrking/motorbridge-studio/blob/main/src/lib/robotArm.js)的 `REBOT_ARM_ROBSTRIDE_DEFAULT_TEMPLATE` |
| J1–J3 / J4–J6 驱动限流 | 每轴 10 A | 57 / 16 A | 同一预设的 `limitCur`；是运行峰值上限，不是持续电流额定值 |
| 持续姿态的名义重力检查 | 1 / 3 / 9 / 3 / 1 / 1 N·m | 11 / 11 / 11 / 5 / 5 / 5 N·m | [Seeed 电机规格](https://wiki.seeedstudio.com/rebot_arm_b601_rs_mit_control/)中的 RS06 / RS00 额定力矩 |
| 完整会话总时长 | 无固定上限 | 无固定上限 | 健康会话通过短许可续期；主动停止、失联或保护异常仍结束 |

官方电机表中 RS06 额定/峰值力矩是 11/36 N·m，RS00 是 5/14 N·m。不能把峰值当作任意时长可持续输出，也不能仅凭重力模型判断实际温升或额外负载。RS00 电机表峰值电流为 15.5 A（±10%），16 A 来自上述官方整臂模板；本工程没有据此推导新的更高值。

官方网页运动参数来自其在线 MIT 轨迹配置；当前网页真机后端采用电机内部 CSP 位置闭环，只借用这些主机轨迹上限，没有替换为 MIT 增益，也没有证明获得官方演示的刷新率或物理平顺性。

## 设备实际生效值

同一 CAN 所有者在启动只读反馈时读取六轴 `0x7017`。页面显示“官方网页上限”和“当前生效上限”，按两者较小值校验输入。不会把电机原来的 1.0 rad/s 自动改成 1.5 rad/s。

开始控制前仍读取真实原始寄存器快照。v3 的临时速度值不超过原值；若原始限矩或限流低于官方提案，拒绝覆盖并报告原因。连接后设备限速降低也会拒绝启动，需重新连接只读反馈刷新页面上限。停止后依照本次快照恢复四项临时运行参数，不恢复旧位置目标。

没有写入 PID、零位或 flash。J7 不参与此控制通路。

## 哪些保护仍保留

- 关节目标范围沿用官方 RS URDF，并按官方整臂规格将 J1 限于 ±150°。没有把不同模型/GUI 预设的角度混合成更大范围。
- 600 ms 反馈、300 ms 电机命令、700 ms 网页心跳、完整模式 3° 跟踪差值、租约与自碰撞检查保留。官方没有提供适用于本机同步 SDK / CSP 链路的可直接替换值。
- 平移与姿态输入范围仍是本工程界面参数，没有查到官方键盘/手柄的统一上限。最终参考速度受关节速度上限约束。
- 小幅模式仍为单独的小幅试机入口，不影响用户直接选择完整模式；不要求先完成小幅运动。

跟踪误差现在比较“已经发出的参考”与反馈，避免把较快的新目标一步直接误报成机械滞后。新参考步长另按设备限速和经过时间检查，实际卡住超过跟踪差值仍拒绝。旧 v1/v2 的包络及恢复指纹保持不变，旧事故快照不会按 v3 重新解释。

## 验证范围

- 控制器：142 项通过；包含旧快照恢复、官方参数、较低设备限速保留、跟踪滞后与目标跳变拒绝。
- 网页：22 项通过；包含官方/设备上限展示、完整模式取消八折、停止与重置输入。
- 隔离 ROS 仿真：12 项通过，`ROS_DOMAIN_ID=82`，不使用实机命名空间。
- 以此前 XYZ `(200, 0, 200)` mm 路径作离线回归：旧 J2 3 N·m 预算拒绝，额定 11/5 N·m 预算通过。这不是实机到点或外部 TCP 精度验收。

只读部署与实际设备参数的记录位于 `outputs/twin-console/official-limits-deployment.json`、`official-limits-readonly.json`。本轮未发起实机准备、接管、使能、运动或重置。目标更新仍为普通 Linux 同步 SDK 上约 90 ms 周期的软实时循环，无法仅靠提高参数保证实体高速平顺性。

## 本轮只读部署结果

服务最终为 PID 862149；完整模式连续 80 帧均为 READONLY、新鲜反馈、未准备/未接管，六轴模式 0，查询中位 85.6 ms。页面已刷新至新版本，保留原 XYZ/RPY 与速度输入，两项真机许可保持未勾选。页面 `(200,0,200)` mm 的只读预览通过，随后恢复用户原表单并清除该预览。
