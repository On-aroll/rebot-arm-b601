# 共用运动配置与反馈调参

后续更新：已接入MIT位置PD、增益调度PID、LADRC和线性MPC，见[MIT与扩展反馈控制](MIT与扩展反馈控制_2026-10-17.md)。本文以下保留第一批实现记录。

## 页面入口与实际覆盖

共用运动配置位于操作区标签上方，手动、程序、视觉任务页均可展开。同一个配置影响完整六轴的坐标到点、键盘、手柄、TCP、动作程序和反馈控制器输出。默认 Ruckig；小幅试机及 J7 保留原方案。程序仍逐点停稳，未实现无停顿穿点。

| 层级 | 当前实现 | 参数与范围 |
| --- | --- | --- |
| 轨迹生成 | Ruckig / 五次到点与加速度平滑 | 各自独立的加速度和 jerk 比例，5–100%；速度另由手动档位或程序 speed 指定 |
| 主机反馈控制 | P / PD / PID / 外部 HTTP 控制器 | 固定六轴关节目标到速度参考；显式试算、启动后运行，不替换全部日常操作 |
| 电机执行 | CSP 位置执行 | 保留电机内部 PID；当前未接入 MIT 力矩/阻抗后端 |

这些层可以组合。P/PD/PID 的输出会经过所选轨迹平滑及原执行器检查。新增的 PID 是主机位置误差到速度参考的外环，不是写电机内部 PID，也不是 MIT 的 Kp/Kd。

官方 [B601-RS MIT SDK 文档](https://wiki.seeedstudio.com/rebot_arm_b601_rs_mit_control/) 确实提供 MIT 模式及每轴 Kp/Kd，默认命令率 200Hz；该频率不是运动速度，也不是当前 CSP 链路的实测频率。官方 connect() 会切模式并使能，不能直接作为本工程的只读连接入口。

## 轨迹参数

停止并释放控制、真实后端 READONLY 且未准备后，选择轨迹方案并应用参数。后端验证并确认后才显示生效；变更使旧坐标/程序预览和反馈控制试算作废。不会使能或发运动帧。

- 加速度预算 = 原包络 × acceleration_scale。
- jerk 预算 = 原包络 × jerk_scale。
- 两个比例只允许 0.05–1；不提高官方或设备限制。
- 规划定时、模拟采样、CAN 内参考采样使用相同有效值。五次方案的 jerk 比例参与到点定时，手动流只有加速度约束。
- 每种方案分别保存。真实驱动的档案为 `outputs/twin-console/hardware/motion-settings.json`，临时文件写完再替换，重启可载入；损坏档案会明确报错，不静默套用。
- 「恢复本方案默认值」只将当前方案的两个比例恢复为 1。

## 反馈参数档案与调参

「控制与调参」可选内置 P、PD、PID；内置计算无需启动额外 HTTP 服务。六轴可分别调整：

| 参数 | 含义 | 校验范围 |
| --- | --- | --- |
| Kp | 位置误差到速度，s⁻¹ | 每轴 0–10 |
| Ki | 积分增益，s⁻² | 每轴 0–10，仅 PID 使用 |
| Kd | 实测速度阻尼，无量纲 | 每轴 0–5，PD/PID 使用 |
| derivative_filter_s | 一阶实测速度滤波时间，s | 0.02–1 |
| integral_limit_rad_s | 积分项的速度贡献上限，rad/s | 0–0.2，另受本次速度上限约束 |

公式为 `v = Kp*(q_goal-q_measured) + integral - Kd*filtered(v_measured)`。
微分作用于实测速度，避免目标阶跃直接产生微分冲击。积分只随新的反馈时间戳累计，重复反馈不积分；输出速度饱和时抑制继续向饱和方向增长，允许反向消退；超出250ms的反馈间隔重置积分。开始/停止清空计算历史，迟到计算不能重新启动运动。抗饱和针对控制器速度限幅，不等同于完整执行器动力学补偿。

网页按控制器保留独立草稿，也可命名另存多份档案（最多64份），保存到当前浏览器；支持 JSON 导入/导出。P/PD/PID 的参数不会彼此覆盖。示例见 `examples/control/pid.json`。初值 Kp=0.6、PID Ki=0.02、PD/PID Kd=0.03，仅为调试起点，未在这台实机调定，不能视为推荐最终增益。

运行监视显示每轴目标误差 RMSE、峰值（导出中）、反馈样本数、内置输出限幅次数和计算响应时间。误差相对固定期望位置计算，包含趋近阶段，不是相对时变轨迹的跟踪精度。导出记录包含本次启动时的控制参数、运动配置、目标、速度及结果，可保留不同试验；刷新前应导出需要的运行记录。

合理的调参过程是固定同一目标、起点、速度、负载与试验时长，保存基线记录，每次只改少量参数，再比较。内存中的带偏置速度对象测试证明积分可降低该简化模型的稳态误差，不能据此宣称这台真实机械臂已调稳。

## 接入更多控制器

原 `b601-controller/1.0` 协议兼容；新增可选 `engine` 字段：`p / pd / pid / external`，缺省仍是 external。内置控制器只接受 joint_velocity，不允许外部 endpoint；未知/非有限参数拒绝。

MPC、自适应、学习策略等可在 `examples/control/controller.py` 的本机计算服务中实现，分别保存连接与参数档案。当前没有附带这些算法的实际模型，不显示虚假的“已安装”选项。只支持关节位置/速度参考；需要力矩、阻抗或 MIT 的算法必须增加相应驱动后端并单独验证，不能把力矩值塞入速度字段。所有控制器仍经唯一 CAN 所有者；无法绕开现有执行校验。
