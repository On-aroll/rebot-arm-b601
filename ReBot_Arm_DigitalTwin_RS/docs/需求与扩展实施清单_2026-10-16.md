## 统一执行基础

所有输入统一走：

```text
坐标 / 键盘 / 手柄 / TCP拖拽 / 程序 / 规划器 / 大模型
                 ↓ 结构化目标或动作程序
          输入校验、预览与路径检查
                 ↓
          独占租约 + 统一运动执行器
                 ↓
        单一 CAN 所有者 → J1–J6 / 后续 J7
                 ↓
        实测反馈 → 数字孪生、日志、执行结果
```

新功能必须复用停止、反馈新鲜度、租约和恢复流程。模型和外部程序不能另开 CAN 或绕过执行层。
显示目标影子与真实反馈的职责保持清楚，不能用动画插值代替实机反馈来宣称同步精度。

## 第二批：支撑姿态、TCP 拖拽、夹爪

### 2. 无电支撑姿态

仅从**已经现场确认可机械支撑**的姿态库选择最近姿态，保留当前 J1。
姿态记录应包含机器人型号、标定版本、J2–J6 角度、安装方向、末端工具、负载与支撑接触说明。
“未使能时的位置”“关节零位”或官方 `safe_home` 名称，都不能证明无电时能稳定支撑。

按钮流程：计算候选及耗时 → 检查关节路径/碰撞/负载 → 按已设速度和加减速返回 → 确认到位。
撤去驱动力为到位后的独立步骤；未验证支撑记录、未到位或支撑条件不满足时，保持现有停止语义，不能猜姿态后自动断电。
“尽快到达”指在已有包络内选择耗时短的合格路径，不瞬间跳目标。

### 4. TCP 拖拽

复用网页已有的末端操纵显示，将位置/姿态拖动接入统一遥操作接口。
需要显式进入拖拽控制模式；按住拖动持续刷新目标，松手保持，失焦/断连仍执行现有停止逻辑。
不可通过旧仿真发布通道直接控制实机。验收包括目标限速、不可达回显、松手无残留、租约互斥及反馈模型正确。

### 5. J7 夹爪

官方 ROS 2 资料使用 ID 7、`rs-00`，电机角度 0 为关闭、5 rad 为打开，`POS_VEL` 速度上限示例为 5 rad/s。
这是电机角度，不是夹爪开口毫米数，也不能代替本机端点标定；设备原限速较低时采用较低值。
MotorBridge 的 J7 模板限矩 14 N·m、限流 16 A 是峰值/限制参考，不能当作无限期夹持力。

实施必须在现有 CAN 工作者中显式注册第七轴，并补齐独立反馈年龄、许可范围、停机、原参数快照、恢复和事故重连检查。
不能简单把六轴 `AXES` 改成七轴，导致旧包络或恢复记录失去原义；也不能启动另一套夹爪控制器争用 CAN。

来源：[官方 ROS 2 集成](https://wiki.seeedstudio.com/cn/rebot_arm_b601_rs_ros2_integration/)、
[MotorBridge 电机模板](https://github.com/tianrking/motorbridge-studio/blob/main/src/lib/robotArm.js)。

## 第三批：程序格式与示教

建议用版本化 JSON 作为通用导入格式，包含：

- `schema_version`、`robot_model`、`calibration_id`、`base_frame`。
- 单位固定为 m、rad、s；网页显示时再换算 mm / °。
- 动作：关节目标、末端目标、夹爪、等待、带时间轨迹；关键帧与连续采样轨迹分开声明。
- 每步速度约束、姿态约束和可选对象引用；拒绝未知必需字段与不兼容版本。

导入后先校验格式、单位、模型、标定、可达与完整路径，再预览/仿真，然后由同一执行器执行。
Python、C++、ROS 2、HTTP 客户端可以提交此格式，不执行导入文件中的任意 Python 或 shell。

示教录制应保存真实关节反馈、单调时间、工具/夹爪状态和标定版本；录制来源必须标记。
不能把前端动画目标当成实测示教。回放提供变速、暂停/继续/取消，不能越过当前运行包络。

## 第四批：可替换识别与规划算法接口

### 7. 视觉检测接口

传输可采用 HTTP JSON 或 ROS 2，协议语义一致：

| 方向 | 必需信息 |
| --- | --- |
| 输入 | 请求 ID、图像时间戳、`frame_id`、图像引用、相机内参、标定 ID；可选深度及外参 |
| 输出 | 对象 ID、类别、置信度、二维框/分割；可选三维位姿、位姿坐标系和不确定度 |
| 错误 | 不支持的版本、标定缺失、超时、图像过期、模型不可用 |

RGB 二维像素不能直接作为机械臂空间坐标；需要深度、手眼标定或其它可靠三维定位。
物体位姿必须带坐标系和时间戳，执行前完成坐标变换及有效期检查。
我们实现协议、校验、示例适配器；用户自行导入或替换识别模型。

### 8–9. 任务规划接口

输入为任务、有效对象观测、机器人反馈、工具与场景信息；输出为第三批定义的动作程序提案。
规划器不持有使能或 CAN 权限。过期物体位置、未知坐标系、无效路径均不能执行。
搬运与码垛使用统一程序步骤；焊接另需工艺参数、焊机接口和现场互锁，识别物体本身不足以完成焊接。

验收用固定观测和测试规划器完成“导入结果 → 仿真 → 暂停/取消/失败回传”，不要求我们训练算法。

## 第五批：大模型 API 适配器

服务端保存 API key（环境变量/服务端配置），浏览器不保存密钥。
支持供应商适配器，把自然语言与选定观测转成同一种结构化动作提案。
模型提案必须通过格式、坐标、路径与仿真校验；实机执行由页面显式发起，不能直接写电机寄存器。
返回可读的任务分解、仿真结果和执行日志；失败时报告具体步骤。

此阶段尚未接外部模型，也没有向外发送相机画面。后续接入时明确发送哪些图像/观测及目标 API。
