# 架构建议评审与本轮改进

日期：2026-10-19。针对用户提供的[架构与改进建议](工作空间架构与文档功能索引及系统改进建议.md)，对照当前源码、10月18日实测记录和官方资料评审。本轮工作均为源码、文档与隔离验证；既有网页、ROSBridge、仿真及实机控制进程未重启。

后续用户要求立即实施可离线部分，新增路径评估、J7毫米查表、手眼求解、夹持回放和实际监听审计；详见[九项建议离线实施](九项建议离线实施_2026-10-19.md)。本页以下是前一批基础修补记录。

## 1. 总体评价

文档的模块划分、主要文档导航和多数长期目标有参考价值；其“问题已经查明”和“方案保证有效”的措辞超出了证据。已修订原文第三部分，并将第四部分改为九项逐条决定和按结果验收的路线。保留[评审前原稿](history/架构建议_评审前_2026-10-19.md)用于追溯，历史原稿不作为操作指南。

主要纠正：

- 对象是Seeed reBot Arm B601-RS/RobStride电机，原文“睿尔曼”混淆了厂商。
- 不是仅做过20秒只读：10月18日已有短手动与微小四步运动记录；长时、带载与完整作业尚未证明。[实测说明](小幅实机验证_2026-10-18.md)
- 500ms不是所有保护共用期限；20ms设计周期不是所有反馈固定50Hz，历史文档中的125Hz也不是当前路径的实测结论。
- J7已有有限失持监视，但证据仍是电机接触，`object_verified=false`。没有物体身份或可靠滑移检测的独立证明。
- 已有进程身份/出生时间和只读退出互锁；“进程管理只有PID文件”“网络完全无防护”都过于笼统。网络仍有实际缺口，见第2节。
- 按原稿第二部分核对了61个去重的反引号Markdown文件引用，文件均存在；这不代表工作空间全部文档已经收录，也不代表历史文档中的结论均是当前事实。

## 2. 实际修改

### 2.1 SDK复现与doctor/构建检查

新增 `configs/csp-sdk-lock.json`，锁定官方CSP依赖路径、完整提交和规范下载URL。`scripts/csp_sdk.py`不导入硬件SDK；准备命令只在目录缺失时clone/checkout，已有修改不覆盖。

```bash
# 只读核对，无clone/fetch/checkout
bash scripts/setup_csp_sdk.sh --check

# 新环境准备；已有但不合格的目录拒绝覆盖
bash scripts/setup_csp_sdk.sh
```

`setup.sh`、`scripts/setup_rs_workspace.sh`与 `./rebotarm doctor`共用检查：

- 必须有该依赖自己的Git元数据，不能误用父仓库HEAD；接受独立checkout和submodule的.git文件。
- 完整commit必须匹配，受跟踪修改和未跟踪源码均拒绝；未知嵌套仓库仍拒绝。
- URL用于重建；现有离线镜像来源可以保留，以相同commit和干净源码为准。
- 静态回归核对清单与实机loader中的提交常量一致。本轮没有迁移现用SDK元数据，也没有改动旧vendored SDK。

同时将安装检查要求修正为Node.js≥22且存在全局WebSocket/fetch，避免Node18通过版本检查后在启动台观察器首次连接时失败；npm另行检查。依据：[Node官方WebSocket版本记录](https://nodejs.org/download/release/v22.4.0/docs/api/globals.html#websocket)。本轮没有安装/升级系统依赖。

### 2.2 本机网络边界

- Node新启动明确绑定127.0.0.1；三个ROSBridge启动入口同样改为127.0.0.1。
- `/api/`统一检查环回连接、Host及Origin；修改请求必须带同源Origin，拒绝浏览器跨来源/跨站请求。覆盖原先未统一保护的配置令牌、聊天代理及快捷启动。无Origin的本机只读CLI请求仍可用。
- 修复静态资源路径前缀边界，拒绝逃到`public`同名前缀目录；坏百分号编码返回拒绝，避免未捕获解码异常。

这组修改限制网络暴露面，没有实现用户登录、权限角色或ROSBridge直连认证；浏览器直接访问ROSBridge的Origin限制、DDS访问控制、本机不可信程序仍需独立设计。ROS官方将DDS认证、加密和访问控制列为独立安全能力，不能由HTTP来源检查替代。[ROS 2 Jazzy安全概念](https://raw.githubusercontent.com/ros2/ros2_documentation/jazzy/source/Concepts/Intermediate/About-Security.rst)

ROSBridge官方launch提供address等参数，但本机绑定不等于消息权限鉴别。[上游launch](https://raw.githubusercontent.com/RobotWebTools/rosbridge_suite/ros2/rosbridge_server/launch/rosbridge_websocket_launch.xml)

以后确有远程操作需求，应单独完成身份与访问范围设计并验证；本次不增加开放网卡的配置。既有进程不会因源文件改动自动改变监听地址。

### 2.3 J7恢复记录

`csp_gripper.py`在原有“写入意图先于硬件操作”的基础上增加：JSON写临时文件→flush→文件fsync→原子替换→目录fsync。全部成功后才允许进入后续模式/参数写入和使能。

保存pending意图时先保留内存恢复锁，任何落盘步骤失败都不能清掉锁；清除pending也必须落盘完成才清内存锁。此机制沿用真实事故前快照，不补造历史缺失数据、不修改增益/限流/限矩/保护期限。它改善进程/系统中断后的恢复可追溯性，不能提供断电物理支撑。

### 2.4 文档同步

修订原架构索引、README进度/安装说明、第三方依赖说明及交付/启动排障中的过时嵌套Git绕行步骤。交付Markdown已加更新声明，旧Word/PDF仍是10月17日基线。本轮未把全部历史文档改成当前状态，也未无差别提交/忽略现有未跟踪文件。

## 3. 第四部分中暂缓或不采用的动作

| 建议 | 本轮决定 |
| --- | --- |
| 失能前强制自动回位；急停先弹窗二次确认 | 不采用。未知工件/姿态下自动运动有额外风险；紧急停止不增加软件等待。普通支撑返回需独立路径与现场验收。 |
| 实机驱动崩溃自动拉起并恢复控制 | 不采用默认自动重启。保留现场核查、恢复日志与唯一CAN所有者；不能用服务守护绕过恢复。systemd可管理日志/依赖，Restart策略须按角色选择。[systemd官方说明](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html) |
| 立刻替换连续轨迹/夹爪单位/力控/前馈 | 暂缓实际执行器改动。先补真实标定和误差指标，保留rad接口；静态电流表不是恒力闭环，Ruckig不是TCP直线保证。 |
| 自动采15–20个标定位姿、立即接焊机 | 暂缓。相机未选，先官方Demo与人工采样/离线验证；焊接先无弧工艺与设备条件核查。 |

这些不是取消后续目标，而是将可交付软件与需要现场数据的物理能力按验收条件推进。推荐顺序仍为：指定点原位夹取与J7判据→选相机/官方视觉Demo→加上可靠夹住判断→连续路径及电弧焊专项。

## 5. 部署与后续验收

本轮没有重启正在运行的网页/ROSBridge/实机驱动，因此现有进程仍可能加载旧代码/旧监听参数。用户暂不能做现场验证，保留该运行边界。

现场可操作后，先查最新真实反馈及恢复日志，确认支撑和失能，再沿既有只读封存/受管启动流程部署；不能依据历史PID或状态自动重启。部署后核查实际端口地址和J7恢复字段，按指定点夹取验收清单采集数据。完整doctor补齐依赖后另跑，不把软件修补等同于当前现场已可作业。
