## 三步开始

1. 在终端执行 `./rebotarm start all`，打开上述网页。
2. 选择「安全仿真」，点击「启动并连接仿真」，等待「仿真反馈已连接」。
3. 点击「接管控制」。同一时间只允许一个页面或 Leader 控制机械臂。

一键启动默认使用后台 MuJoCo 和网页三维视图。需要独立 MuJoCo 窗口时，启动前设置
`REBOTARM_MUJOCO_VIEWER=true`。一键启动不会启动真实 CAN 控制器。

### 坐标到点

- 单位：位置 **mm**，姿态 **度**；坐标系为机械臂 `base_link`，X 前、Y 左、Z 上。
- TCP 为 URDF 的 `gripper_end`，外加工具的长度和偏移需要另行标定。
- 可以「填入当前位置」，然后修改 XYZ。默认仅位置自由姿态（预览显示解算 RPY）；也可主动选择保持当前或指定 RPY。
- 先点「计算并预览」：只解算，不运动；虚影显示目标姿态，并给出时间和 IK 残差。
- 再点「执行预览轨迹」。预览 30 秒内有效，输入改变或起始关节改变须重新计算。
- 轨迹为关节空间五次平滑插值，满足本面板的关节速度上限；TCP 路径可能是曲线。
- 拒绝不可达、非有限数和越限解，不会执行失败 IK 的近似结果。
- 到达判据是反馈经 URDF 正运动学计算的位置误差 ≤ 2 mm、受约束姿态误差 ≤ 2°。
  这个判据不等同于真实工具在世界坐标系中的绝对精度。

### 键盘与屏幕按钮

选择「键盘 / 按钮」。**按住空格，再按以下键位**；也可直接按住屏幕上的正负按钮。

| 控制 | 正向 | 反向 |
| --- | --- | --- |
| X 前后 | W | S |
| Y 左右 | A | D |
| Z 上下 | R | F |
| Roll 绕基座 X | U | O |
| Pitch 绕基座 Y | I | K |
| Yaw 绕基座 Z | J | L |

松开空格、松开按钮立即请求保持；保持空格并松方向键时平滑减速。输入框获得焦点时停用键盘控制；切走网页会释放控制，返回后要重新接管。详见[平滑遥操作](平滑遥操作_2026-10-16.md)。

### 游戏手柄

选择「游戏手柄」，按手柄任意键，让浏览器识别它。支持 Gamepad API 的 **Standard** 映射
（常见 Xbox / PS 手柄；实际以浏览器报告为准）。连接后先松开所有摇杆与 RB。

| 输入 | 效果 |
| --- | --- |
| 按住 RB / R1 | 允许移动；松开立即保持 |
| 左摇杆上/下、左/右 | X 前后、Y 左右 |
| 十字键上/下 | Z 上下 |
| 右摇杆上/下、左/右 | Pitch、Yaw |
| LT / L2、RT / R2 | Roll 负向、正向 |
| 同时按住 LB / L1 | 四分之一精细速度 |

摇杆有 16% 死区。对角线输入按向量归一化，避免组合按键超过速度上限。非 Standard 映射会显示提示并拒绝运动。
手柄断开后释放控制，不会自动切换到另一只手柄继续移动。

## 相机：右侧实机画面

相机独立于机械臂控制，可以只看画面，不接管机械臂。

| 来源 | 连接方法 |
| --- | --- |
| 本机 / USB 相机 | 选择设备，点「连接画面」，在浏览器授权；设备是打开网页的电脑上的相机 |
| HTTP MJPEG / JPEG | 填入相机提供的图像流地址；直接由浏览器读取 |
| HTTP 视频 | 填入浏览器支持的 MP4 / WebM 地址，具体编码取决于浏览器 |
| ROS 压缩图像 | 先连接 ROS，填写 `sensor_msgs/msg/CompressedImage` 话题，支持 JPEG / PNG |

浏览器不能直接播放 RTSP；此类相机需通过现有视频网关转换为 HTTP 流或 ROS 压缩图像。
USB 相机要求 localhost 或 HTTPS 安全上下文。HTTPS 页面不能直接嵌入 HTTP 相机流。
相机视频不上传、不自动录制。断开或关闭页面后停止本机相机轨道并释放设备。

页面支持左右观察；目前没有做相机内外参标定、视频与编码器硬件时钟同步、图像叠加或视觉测量。
不同来源的视频延迟不能视为零，界面会注明尚未标定。

## 实机接入（网页 CSP：小幅 / 完整）

1. 执行 `./rebotarm start all`，确保网页和 rosbridge 已运行。
2. 未连接时选择「实机 + 数字孪生」，点击「连接实机反馈」。网页自动启动
   `scripts/start_rs_twin.sh`，读取六轴 `0x7019 mechPos`；连接不会使能。
3. 在只读状态选择「小幅试机」或「完整控制」；核对现场确认项和网页控制开关，
   点击对应的「准备小幅控制 / 准备完整控制」。这仍然只是软件准备。
4. 点击「接管控制」。坐标先预览再执行；键盘/按钮、手柄使用同一个控制器。
   可先点「启动电机保持（使能）」，独立于坐标逆解，从实测位置逐轴使能保持。也可由首个运动输入启动。
   页面明确区分软件准备和使能已下发；固件无可靠使能状态读回，实际力矩须现场观察。准备期间松键会取消启动。
5. 普通方向输入松开时平滑减速；松空格/RB立即请求保持。点击「停止 / Esc」会释放、失能，核对停稳后恢复
   本次快照中的模式、速度、电流、力矩限制；等到「已失能 · 只读观察」再重新准备。
6. 点击「断开 ROS」会结束此反馈服务，释放 CAN 并恢复原项目网关。

默认小幅模式每次接管的各轴目标相对起点 **≤0.5°**，关节速度 **0.005–0.02 rad/s**，首次使能起
**最多 15 秒**。平移默认 1 mm/s，允许 0.5–3 mm/s；旋转默认 1°/s，允许 0.5–3°/s，
最终仍受关节限制。碰到范围须松开、释放，观察后重新准备/接管；不自动续接。
新增完整模式取消接管起点的 0.5° 限制，使用 J1–J6 名义关节范围；关节速度允许
**0.005–0.1 rad/s**，正常连接下持续使能保持，无固定时长上限。平移 0.5–40 mm/s、旋转 0.5–20°/s，
默认 5 mm/s、2°/s、关节 0.02 rad/s，最终以关节限速为准。后台仍拒绝自碰撞、
超力矩包络、跟踪/反馈异常，切换须停止并回到未准备的只读状态。
本次只做离线/仿真验证；完整范围的实机运动留待现场验收，见 [完整控制操作说明](完整控制操作说明.md)。
J7 夹爪不参与此通路。独占 CAN 时会暂时关闭经身份核验的旧 9002 网关。

本通路使用 CSP 电机内部位置环，保留原 PID；不调用旧 MIT 自动保持、回零或组生命周期。
不要同时启动 `start_rs_hardware.sh`、Leader 或旧网页的 CAN 写入入口。
停止会失能，重力下的机械姿态可能随后变化；孪生继续显示真实反馈。
模型会检查自身碰撞和名义重力包络，**没有环境避障或相机闭环控制**。

## 同步如何工作

```text
坐标 → 预览 IK → 关节轨迹 ┐
键盘 / 按钮 → 6D 速度   ├→ 同一个 TwinControl → 独占遥操作租约 → Fake / 实机驱动
标准手柄 → 6D 速度      ┘                                         ↓
三维实色模型 ← 反馈（实机编码器，或 MuJoCo 状态 / Fake 状态）←───────────┘
目标虚影     ← 计划关节目标
相机画面     ← 本机设备 / HTTP 流 / ROS 压缩图像（独立显示）
```

- 统一控制输入与状态为 20 Hz；网页在相邻反馈间做约 50 ms 插值。实机六轴串行读取本机约每 200–250 ms 一轮，页面显示真实反馈年龄；20 Hz 发布不等于 20 Hz 编码器采样。
- 数字孪生的实色模型显示实际反馈，保留略超名义限位的真实编码器角度；运动目标仍有后台限位。不能把目标虚影当作已经到达。真实运动存在反馈、网络、渲染延迟。
- 仿真检测到 MuJoCo 状态时优先用它作为实际反馈；没有 MuJoCo 时明确显示 Fake 驱动话题作为来源。
- 一旦接入 MuJoCo，其反馈过期会停止并拒绝接管，不会静默切换成 Fake 状态继续运动。
- `反馈新鲜度` 显示控制器缓存与网页接收后的时间，不是经时钟标定的单向网络延迟。
- 轨迹跟踪差值是计划关节参考与实际反馈的最大角度差，不是相机测得的误差。
- 输入样本超过 250 ms 未更新则保持；网页心跳超过 700 ms 则中断运动、释放控制。
  驱动另有独立租约看门狗。以上为软件阈值，实际响应受调度、通信与机械制动能力影响。
- 网页隐藏、失焦、失联、控制方式切换时停止原输入；断线重连不会自动恢复运动。
- 「停止 / Esc」停止本统一控制通路；仿真保持，实机直接失能并核对参数恢复。它不代替物理急停。
- 实机与 ROS 主机需时钟同步；超过 500 ms 的旧命令被拒绝，重复/乱序命令也被拒绝。
- 当前实现没有环境自动避障、全路径碰撞规划或相机闭环定位；实际作业区需按既有流程确认。

## 接口与文件

| 路径 / 接口 | 用途 |
| --- | --- |
| `rebotarmcontroller/twin_kinematics.py` | 只加载 URDF 的 FK、IK、笛卡尔微动解算，不打开 CAN |
| `rebotarmcontroller/twin_control.py` | 统一执行、独占租约、保持/停止、到点判据、反馈和超时 |
| `rebotarmcontroller/twin_jog.py` | 共用的关节速度渐变和边界制动；使用既有限速及加速度预算 |
| `public/js/twin-input.js` | 键盘、标准手柄、死区、速度归一化 |
| `public/js/twin-console.js` | 页面操作、ROS 通信、反馈渲染与状态 |
| `public/js/twin-camera.js` | 本机设备、网络视频、ROS 压缩图像的生命周期管理 |
| `public/css/twin-console.css` | 左右观察布局、常用控制、响应式界面 |
| `/<ns>/twin/acquire` | Trigger 服务；显式申请租约，不使能 |
| `/<ns>/twin/stop` | Trigger 服务；停止本通路并释放租约 |
| `/<ns>/twin/command` | String JSON；preview / goal / jog / hold / heartbeat / release；实机只读时可 control_mode（small / full） |
| `/<ns>/twin/events` | String JSON；按请求 id 返回确认或错误 |
| `power_hold` 命令 | 须有效租约、时间戳、序号、新鲜反馈；从实测姿态启动 CSP 保持，同一模型/力矩检查 |
| `/<ns>/twin/state` | String JSON；实际位置、姿态、参考、状态、误差、control_settings 范围/时限/剩余时间，无租约密钥 |
| `/<ns>/twin/reference` | JointState；已发送给驱动的共同参考，供后续独立预测仿真使用 |

`<ns>` 在安全仿真中为 `rebotarm_rs`，在实机中为 `rebotarm`。不同目标使用相同代码，连接期间禁止切换。
代码更新后需要重启 Fake 或实机控制器才能发现新增接口；单独刷新网页不会升级正在运行的 Python 节点。
