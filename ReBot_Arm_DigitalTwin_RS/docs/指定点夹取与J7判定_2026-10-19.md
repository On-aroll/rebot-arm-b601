# 指定点夹取与 J7 判定

## 本次范围

按用户确认的顺序：先指定点夹取和 J7 夹持判断，再复现 Seeed 官方视觉 Demo，视觉定位结果复用这条夹取链。金属电弧焊留到后续独立阶段。

已接入软件：工作台「动作程序 → 指定点夹取 · J7 接触判定」，以及统一程序执行器的新 `grasp` 条件步骤。没有运行真机验证；本轮没有连接硬件 SDK、使能、运动、重置、修改电机参数或重启现有服务。页面静态资源已更新，**正在运行的 Node API 与 ROS 驱动仍是原进程，需在允许的部署窗口重启加载代码**。现有恢复锁不能靠重启或此功能解除。

## 使用入口

1. 在「动作程序」展开「指定点夹取」。可手工输入 XYZ / RPY，或在反馈连接后用当前末端姿态填写。
2. XYZ 单位 mm、RPY 单位度；生成程序时转为 m / rad。坐标是 `base_link` 中的模型 `gripper_end` 原点，不能直接把工件表面点当成已经标定的夹持中心。实际工具 TCP 仍须现场校准。
3. 通过现有手动控制采集空载闭合、夹住试件的 J7 位置、速度和电流。空夹位置、接触电流、中止电流不提供实机默认值；页面「记录当前空夹位置」只读取已有新鲜静止反馈，不能自行闭合夹爪。
4. 填写阈值，生成程序；可保存到原程序库、导出 JSON，或检查整套路径。生成和导入均不执行运动。
5. 恢复状态正常、现场条件确认后，使用原「使能并执行程序」。仍由同一个租约、看门狗和 CAN 所有者执行。

流程：张开 J7 → 到指定点上方 → 每段不超过 5 mm 的竖直接近目标点 → 低速闭合并判定 → 原位保持。这里的 5 mm 是笛卡尔目标采样间隔；每段仍采用现有 IK 与关节轨迹，**不是已验证的精确直线插补**。去接近点的关节路径，以及工具、夹具、环境和载荷碰撞仍需检查。本次不添加自动抬升、搬运或放置。

## “夹住”如何判断

`grasp` 步骤需要完整标定 profile，不能用 `gripper(position=0)` 或等待秒数代替：

| 状态 / 情况 | 判断与动作 |
| --- | --- |
| 起点 | 新鲜静止、有效 J7 授权、机械臂已使能保持；开度足够产生最小闭合行程 |
| 闭合检测 | 速度最多 0.1 rad/s，且大于停滞阈值两倍；保留原设备更低限速 |
| 空夹 | 进入实测空夹端点公差，判定失败 |
| 接触候选 | 闭合行程、距空夹端点间隙、低速度、接触电流、闭合参考误差同时满足 |
| 接触确认 | 第一次候选即冻结闭合参考，至少 3 个不同时间样本，连续满足接触和额外保持时间 |
| 电机保持判定通过 | 返回 `holding`，后续程序才可继续；记录任务 ID 与反馈证据 |
| 不稳定 / 超时 / 电流达到中止值 / 反馈过期 / 任务 ID 变化 | 本步骤失败，停止后续动作，保持当前参考；不自动张开、失能或重试 |
| 保持中疑似滑移 | 位置漂移、速度或低电流持续异常，撤销保持证据，阻止后续目标继续发送 |

只累计不同、顺序正确且不超过 600 ms 的反馈时间戳；重复 UI 状态不能累计保持时间。闭合参考最多领先实测位置 0.02 rad，低于原 3° 跟踪误差保护；接触后不继续向空夹端点施压。不改 PID、零位、flash、限流、限矩、模式策略或既有保护期限；中止电流也不能超过本次保留的设备限流。

输出 `method=motor_contact`、`object_verified=false`。**电机接触证据能区分很多空夹和异常情形，但不能区分所有“夹到工件”与“碰到夹具”，也不能单独证明搬运不会掉落。** 真正的自动抬升、视觉夹取须补做试件验证与抬升后验证；可进一步接入夹指触觉/力传感器或视觉工件跟随证据。

## 与官方方案的关系

已逐行核对官方 `GraspController.gripper_tick()` / `grasp()`：官方有闭合、保持及空夹硬端点分支，主要使用运动行程和低速度判断接触，MIT 方式施加闭合/保持力矩。

- [Seeed B601-RS 视觉夹取教程](https://wiki.seeedstudio.com/rebot_arm_b601_rs_grasping_demo/)
- [官方夹爪实现，锁定版本](https://github.com/Seeed-Projects/reBot-DevArm-Grasp/blob/547faa08e5161af996892497c0aaa788401454fc/drivers/robot/grasp_driver.py)
- [前序完整调研](research/自主夹取与电弧焊调研_2026-10-19.md)

本地当前链路采用原 CSP 夹爪控制，增加电流、持续时间与任务门控；没有将官方 MIT 力矩参数照抄到实机，也没有启动官方独立驱动抢占 CAN。下一阶段复现官方视觉能力时，应将检测/深度/坐标变换输出接入同一指定点生成器，再复用 `grasp`，而不是另起运动控制器。相机尚未选定；移动腕部相机必须使用图像时刻的 FK/TF 与手眼标定，不能沿用固定外参假设。

## 验证与边界

- 76 项针对性 Python 测试通过：输入与标定检查、重复/过期/倒退样本、空夹、普通停顿、噪声、超时、保持丢失、真实夹爪 worker 的内存反馈路径、任务门控、原程序与 J7 行为。
- 6 项恢复/许可相关回归通过；13 项 Node 页面生成器、程序协调与 API 测试通过。
- 真实浏览器验证：缺少阈值时拒绝生成；合成输入生成 4 步程序，无错误/警告。未连接 ROS、未点击执行。
- 同一 JS 生成器输出通过本地原生 IK / 编译器检查：2 个合成姿态点。残差只是数值解算结果，不代表物理精度；无环境/工具/载荷碰撞验证。
- Fake 没有物体接触物理或力反馈，零电流不能判为夹住；只能验证路径、空夹/超时等失败流程。成功接触路径使用带合成反馈的内存 SDK 验证，不冒充实物或物理仿真成功。

扩大回归初跑 134 通过、2 失败：一项许可过期测试被更早的心跳超时抢先触发，原测试单项复跑通过；另一项 J7 测试缺设备限速值，保存的修改前源码也能复现失败。仅补齐该测试夹具 `speed_max=1`，未放宽生产保护。没有宣称整个扩大测试集已重新全通过。

证据在 `outputs/fixed-pick-20261019/`：`python-tests.txt`、`node-tests.txt`、`recovery-recheck.txt`、`compilation.json`、`synthetic-program.json`、`workbench.png`。合成程序中的电流阈值仅用于测试，不是实机标定数据。
