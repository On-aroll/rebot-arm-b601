# 通信保持与七轴手动控制（2026-10-16）

## 用户要求与现场原因

用户报告运动中因通信超时失能，悬空机械臂失去支撑后下落；明确要求反馈不及时先保持，不能继续走旧动作。另要求核查TCP拖拽的J5、将J7纳入键盘/手柄且参数与六轴同列、四种手动方式统一可选速度。

最新实机报告 `csp-session-1792161638567245336.json` 原因为J4模式字段超过600ms；此前还记录网页失焦、300ms命令期限和J5模式字段过期。共同的原清理路径发送失能，不能仅归因电脑卡顿或程序导入格式。300ms为命令有效期，不是反馈刷新周期；网页状态500ms、各电机字段600ms、网页心跳700ms保持原检测值。

## 通信超时后的冻结保持

适用：完整控制且六轴已经全部进入ACTIVE。通信超时、过期许可、网页失焦/隐藏/关闭/断连、释放控制权、顶部「暂停并保持」进入HOLDING。

- 取消旧控制令牌、程序/算法、轨迹、手动输入和待返回结果；停止推进位置参考。
- 不发失能、模式、参数或目标写入。电机保留已有CSP位置目标；只读监测反馈。
- 不将旧反馈当作“已托住”。缺反馈明确显示“反馈未确认”；恢复通信也不会续跑。
- 读回六轴loc_ref，核对属于本会话最近成功或最近尝试目标；重新接管要求完整新鲜反馈、静止和原3°跟踪范围。
- 只有明确重新接管才建立新许可/命令窗口；不会重新使能，不重放旧程序。已活动J7同时冻结；重新接管后只刷新其保持参考。
- 保留事故参数快照和HOLDING记录，进程意外退出后不能抹去恢复来源。

「失能撤力 / Esc」、重置、服务关闭，以及模式改变、过流、实际越界/超速等机械电气保护仍进入失能清理。启动尚未全部使能和小幅15秒试验仍使用原清理语义。暂停不能代替机械制动，电源/驱动故障或固件自行失能仍可能失去支撑；新软件保持尚未做物理故障注入验收。

协议依据：
- [MotorBridge RobStride API](https://github.com/motorbridge/motorbridge/blob/main/motor_cli/ROBSTRIDE_API.md)：CSP模式5、loc_ref 0x7016、limit_spd 0x7017；使能/失能为独立操作。
- [厂家RS00手册](https://files.seeedstudio.com/products/RobStride/Product%20Literature/RS00/RS00User%20Manual251112.pdf)：CSP顺序及掉电阻尼描述不等同机械抱闸。

## J5 / TCP

J5未被单独禁用。原TCP“仅位置”虽然旋转误差为零，速度逆解仍使用完整6×6雅可比，隐含约束角速度为零。现仅位置拖拽只用位置雅可比；勾选保持朝向才约束旋转。TCP页新增Roll/Pitch/Yaw按住微调，松开保持，切换姿态微调会取消旧拖拽。

真实URDF回归检查位置推进、自由姿态与锁姿态差异，以及J5雅可比列的响应；这不能证明实机J5机械、电气无故障，也不能要求每个位置方向所有关节都转动。

## J7 / 七轴参数

移除单独J7控制卡、独立授权勾选及到端点按钮。统一参数表显示J1–J7位置、范围、速度上限及状态。连接后在唯一CAN所有者中只读检查J7；不使能。

- 键盘：空格+Q打开、空格+E闭合；方向按钮也有J7开/合。
- 标准手柄：RB/R1+A/×打开，RB/R1+B/○闭合；LB/L1为四分之一精细速度。
- 与六轴同一jog消息、接管令牌、输入时效；松键/松RB、输入过期、暂停均冻结夹爪目标。
- J7内部仍验证完整范围、模式、反馈、恢复来源、0–5rad、设备/官方较低限速及力矩电流。运行记录和参数恢复保留，不写PID/零位/flash。
- 显式启动含gripper步骤的已检查程序覆盖该程序J7授权，不再要求单独勾选。
- 开口宽度未标定，模型仍为官方比例示意。

## 手动速度

低速 / 常速 / 高速 / 当前允许最高速度 / 自定义。统一更新关节上限、平移和旋转速度；坐标到点使用关节上限，键盘/手柄/TCP另受平移旋转上限；J7取所选关节速度与自身设备上限较小值。

当前实机六轴设备限速1.0rad/s，官方参考1.5rad/s，因此最高档最多1.0rad/s，不提高电机原限速。手动平移40mm/s、旋转20°/s为当前控制器接口上限，不能称为厂家保证的TCP极限。姿态、加速度、jerk、跟踪和自碰撞限制仍可能降低实际速度；运动中暂停后才能改档位。

程序每步speed独立，档位不会覆盖导入程序速度。导入与换页仍不使能、不执行。
