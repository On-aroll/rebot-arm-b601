# 九项建议：本轮可实施部分与使用说明

日期：2026-10-19。承接[架构建议评审](架构建议评审与改进_2026-10-19.md)。用户暂不能进行实机验证，本轮完成独立于现场的工具、文件契约和验证。各工具不连接服务、不导入硬件SDK、不产生运动程序，也不安装控制参数。

## 2. 入口与环境

工具入口为 `examples/autonomy/qualify.py`，命令有 `j7-width`、`handeye`、`path`、`grasp`。输入示例在 `examples/autonomy/fixtures/qualification/`，**全部为合成数据**，不能用作设备标定或控制参数。

本机已具备下列两个计算环境。迁移到新电脑时，手眼所需的独立视觉环境按[已有离线视觉说明](离线视觉回放与J7采样_2026-10-19.md)及 `requirements-vision-offline.txt` 建立；安装器本轮仅携带清单，没有自动建立该环境。

下列命令在项目根目录运行。`--output`必须是新文件，父目录需已存在；已有输入/报告不会被覆盖。

```bash
# 标准Python即可：毫米表查询和夹持回放
python3 examples/autonomy/qualify.py j7-width \
  examples/autonomy/fixtures/qualification/j7-width.synthetic.json \
  --direction closing --width-mm 25 --output /tmp/j7-width-review.json
python3 examples/autonomy/qualify.py grasp \
  examples/autonomy/fixtures/qualification/grasp.synthetic.json \
  --output /tmp/grasp-review.json

# 隔离视觉环境：NumPy + OpenCV，无相机SDK/YOLO依赖
~/.local/share/robotics/envs/rebot-vision-offline/bin/python \
  examples/autonomy/qualify.py handeye \
  examples/autonomy/fixtures/qualification/handeye-wrist.synthetic.json \
  --output /tmp/handeye-review.json

# 项目运动学环境：仅设置本终端环境，再做纯离线计算
source scripts/rs_env.sh
python3 examples/autonomy/qualify.py path \
  examples/autonomy/fixtures/qualification/path.synthetic.json \
  --output /tmp/path-review.json

# 只执行ss读取监听表；不连接、停止或重启服务
python3 scripts/audit_local_network.py
```

`qualify.py`退出码：0=计算完成且适用误差预算通过，1=输入/依赖/写文件失败，2=计算完成但误差预算未通过（报告仍保存）。`grasp`没有设置误判验收预算，退出0仅表示回放完成，要查看统计。路径合成示例预期退出2。网络审计另定义：0=已观测网页和ROSBridge均仅本机监听；1=发现非回环监听；2=所选关键服务缺失；3=工具不可用。端口审计不证明身份认证、DDS安全或实机状态。

报告使用独立的 `*-review/1.0` schema，统一保留 `hardware_execution_allowed=false`、`physical_validation_passed=false`、`object_verified=false`。J7与手眼报告还保留 `calibration_ready=false`。`validation_passed`仅指本次输入在指定数学误差预算内通过，不能直接导入动作执行。

## 3. 输入数据和判定规则

### 3.1 J7角度与毫米开度

输入 `b601-j7-width-data/1.0`，必须记录 `source.kind`、标定/设备/夹爪ID、毫米误差预算。`measurements.opening/closing`各至少3个 `{position_rad,width_mm}` 点；`validation`各至少2个未用于建表的角度点。角度和开度必须严格单调增加，两方向分别处理。当前软件接受范围0–5rad、0–200mm只是文件校验范围，**不是夹爪行程规格**；只在实际测量区间内插值，量程外拒绝。

现场应从两个方向分别接近量点，记录工件/指尖、量具与负载条件，并保留多轮重复测量及独立验证点。仅把旧角度值改写为毫米不能生成标定。查询必须明确 `opening` 或 `closing`，并且只选 `--width-mm` 或 `--position-rad` 一个。拟合检查失败不能查询。工具不输出夹力、不自动改空夹端点或电流阈值。

### 3.2 固定/腕部手眼标定

约定 `T_A_B` 将B系坐标变换到A系。输入 `b601-handeye-data/1.0` 中每个静止姿态提供：

- `T_base_tool`：拍摄时工具到基座的4×4刚体变换。
- `T_camera_target`：标定板到相机的4×4刚体变换，不是其逆矩阵。
- `robot_stamp_s`、`camera_stamp_s`：同一个时钟基准的秒，不直接混用网页墙钟和驱动单调时钟。
- `stationary=true`、`reprojection_rms_px`、唯一 `id` 及 `split=train/validation`。
- 明确基座/工具/相机/靶标坐标系、设备与标定ID、米单位及误差预算。

本工具工程门槛为至少6训练+3留出姿态；检查非平行旋转激励、重复姿态、有效旋转矩阵、米/毫米错误和配对时差。数量与这些检查都不是完整标定质量保证。无噪声示例为8训练+4留出；真实数据还需覆盖实际工作空间。

使用OpenCV `CALIB_HAND_EYE_PARK`：

| 安装方式 | 约束 | 求解结果 | 采样期间必须固定 |
| --- | --- | --- | --- |
| `eye_in_hand` 腕部相机 | `B_i X C_i = Y` | `X=T_tool_camera` | 相机与工具刚性连接，标定板固定在基座/工作台 |
| `eye_to_hand` 固定相机 | `inv(B_i) X C_i = Y` | `X=T_base_camera` | 相机固定，标定板与工具刚性连接 |

其中 `B_i=T_base_tool`、`C_i=T_camera_target`。只用训练姿态拟合X和常量Y，再检查留出姿态的闭合平移/旋转残差。留出数据不参与拟合。即使闭合一致，也可能有共同的模型/坐标系偏差，必须用独立物理检查点验证。工具不检测标定板、不标定内参、不移动机器人、不自动安装外参。参考[OpenCV官方手眼说明](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。

### 3.3 路径误差和时序

输入 `b601-path-review-input/1.0` 必须声明 rad/m/s单位、工具刚性偏置及四项预算：TCP弦偏差(mm)、姿态插值偏差(°)、单次关节变化(rad)、样本间隔(s)。

- `reference_segments`：按现有生产版 `point_duration/point_sample('ruckig')` 生成关节参考，经当前URDF正运动学求TCP；相邻段必须共享关节端点。时间统计属于**生成的参考采样**，不代表控制器或总线实际周期。
- `recorded_segment`：提供单段有序 `{t_s,q_rad:[六轴]}` 样本。根据记录自身时间计算间隔中位/p95/最大值、单步关节变化和模型TCP速度；请在数据来源说明中写明是参考还是反馈及其时间定义。

TCP弦偏差是采样点到该段起终点连线段的距离，不是连续曲线误差上界或焊缝跟踪误差；姿态与端点SO(3)插值比较。输出包含模型文件SHA-256、抽样坐标与峰值。未做碰撞、负载、重力、真实TCP量测、参考与反馈时钟对齐；本工具没有实现笛卡尔直线规划或无停顿穿点。

### 3.4 夹持证据回放

输入 `b601-grasp-evaluation/1.0`：

- `profile` 是已冻结的生产 `GraspMonitor` 参数。工具不选择阈值。
- `recording` 嵌入网页导出的 `b601-j7-recording/1.0` 原始记录。
- `truth` 按记录唯一id逐一标注 `object/empty/fixture/free/slip`；`slip`还需要同一 `sample_at` 时基下的 `event_at`。标注来自独立观察/传感证据，不能照抄待评估判据的输出。

记录须包括接触前闭合过程，保留有效 `reference`、`sample_at`、`received_ms`、位置、速度和电流；重复、倒序、间隔>600ms、缺参考的片段拒绝。只采静止尾部的旧记录不足以评估完整夹取过程，应重新采集，而不是补造参考。

报告调用生产版纯 `GraspMonitor`，按驱动样本间隔推进；真实hardware与fake/synthetic分开统计。负例只要曾到达holding即记误接纳，避免后来失败掩盖夹具误判。滑落检测必须先holding，随后在标注事件之后由实际保持丢失判据失败，才报告延迟。网页墙钟与驱动单调时钟的绝对偏移未知，因此不声称复现了运行时接收新鲜度检查。

## 4. 本轮验证与局限

测试日志、CLI报告和只读网络审计在 `outputs/qualification-20261019/`。本轮25项通过：8基础/J7/夹持/网络、5手眼、4路径，以及8打包/安装完整性测试（含5项原有回归）。其中20项为新增测试。

| 合成检查 | 实际结果 | 可说明的范围 |
| --- | --- | --- |
| J7开合两张表 | 留出最大误差各约0.2mm；逆查询通过 | 插值/方向/误差闸逻辑，不是实机精度 |
| 腕部、固定两种手眼 | 恢复已知合成矩阵；留出残差<1e-9mm | 数学方向和数据分离正确，不是实际标定精度 |
| 留出点扰动、错误矩阵方向、退化旋转、坏时间/单位 | 被拒绝或误差检查不通过 | 有效拦截所构造的坏输入，不能保证识别全部系统误差 |
| B601当前Ruckig参考示例 | 起终点弦约60.494mm，TCP峰值偏离约1.513mm；0.1mm预算未通过 | 当前关节线段平滑仍可生成TCP弧线，不能据此宣称严格直线 |
| 4段夹持合成记录 | 空夹拒绝；工件/夹具均holding；夹具误接纳1次；1次滑落在0.2s后检测 | 显示电机证据歧义及统计能力；真实记录数为0，不估计现场误报率 |
| 当前监听表 | 3002为`*`、9090为`0.0.0.0`，8081为`127.0.0.1` | 前轮源码尚未改变旧进程的监听；端口报告不证明身份认证或实机状态 |

打包器现在会核对SDK锁与干净源码（含未跟踪文件），随后将锁清单、所有离线工具/JSON示例、视觉依赖文件以及嵌套Markdown纳入源清单与SHA-256。只复制允许的配置锁文件，不带私有配置、运行记录、`.env`或密钥。暂存包验证记录见 `bundle-stage-verification.json`；本轮没有发布新二进制安装包，现有dist文件不变。

本轮未进行真实连接/使能/运动、相机采样、增益或电流修改，也未重启现有服务。网络收紧需在现场可操作、按既有恢复/只读封存流程受控重载后再验收。原先未通过的完整doctor仍需补齐系统依赖，本轮没有安装系统依赖。

## 5. 现场可操作后的最小数据任务

1. 核对当前进程、真实反馈和恢复日志，完成支撑/失能及受控部署，重新运行端口审计。不能依据历史PID、旧恢复状态启动或解除锁。
2. 指定点原位夹取：确认TCP/指尖、方向/限位、空夹端点；采开合量具数据及独立验证点。先保持原位，不自动抬升或重试。
3. 冻结一版夹持参数，用独立空夹、夹物、碰夹具、滑落片段量化误判/漏判/延迟，再决定传感器。
4. 相机选定后按官方流程完成真实视觉Demo，人工静止采样，经手眼留出与物理检查点验收后再进入目标夹取。

研究依据及论文/仓库/专利检索边界沿用[自主夹取与电弧焊调研](research/自主夹取与电弧焊调研_2026-10-19.md)。本轮未补造专利或软著已检索穷尽的结论，也未把离线通过当成焊接工艺验收。
