# 算法接入与程序工作台

2026-10-16。本轮把第2、4、5、6–10项接入当前3002网页和统一CSP执行链；新增功能的实体运动仍需现场验收。本轮未新增真实准备、接管、使能、运动或重置。

## 在哪里接

**持续反馈的控制算法**已独立在顶栏「控制算法」，见[控制算法接入](控制算法接入.md)。下面介绍识别、任务规划和对话服务，与控制算法并列。原「算法接入」标签现改名「视觉与任务规划」，顶栏入口改为「视觉 / 大模型接入」。

打开 http://127.0.0.1:3002 ，点击顶栏 **算法 / 大模型接入**，直接到达配置表单。模型对话在 **对话任务**；动作在 **动作程序与示教**。这三个工作区与 **手动控制** 并列。

### 识别算法

1. 在上方相机模块连接USB、本机视频、HTTP视频或ROS压缩图像。
2. 在「算法接入」新增连接，用途选 **视觉识别**，协议选 **自定义HTTP JSON**。填写完整推理地址、可选健康检查地址、模型标识和API Key，保存、测试。
3. 点击 **下载接口与示例JSON**，按其中的请求/响应格式封装你的算法。连接配置也可导入、导出。
4. 选择识别服务，确认向该服务发送本帧，点击 **采集一帧并识别**。页面显示类别、置信度、坐标系和三维位置。没有三维位置的结果只能显示二维检测，不能猜深度。
5. `base_link`三维结果可点击 **填入坐标目标**，仍需预览才执行。`camera_optical_frame`坐标只有在保存有效的`camera_to_base`后才能转换。矩阵平移为米，须为4×4刚性变换；内参为行优先9个数值。

识别结果5秒内可作为规划输入。勾选「请求规划 / 对话时先刷新观测」可在请求前重新识别一帧；需要保持图像发送许可。无关旧结果可点「清除当前观测」。ROS相机还要有正确时间戳和主机时钟；跨域相机须允许CORS读取，并勾选相机区「用于算法取帧」后重新连接，或改用ROS压缩图像。MJPEG无法确认帧更新时仅观察，不当作新鲜算法输入。

导入的是**算法服务配置**及**识别结果JSON**。ONNX、PT、TensorRT或其他模型权重由你自己的推理服务加载。网页不直接执行上传的Python、shell或模型代码。

### 规划算法

新增用途 **任务 / 路径规划** 的HTTP JSON连接，填写规划端点。右侧选择该服务、输入任务，点击 **请求规划并载入程序**。

服务会收到任务、机器人六轴实际角度、TCP位姿、标定版本、速度约束，以及可选新鲜物体观测。服务返回本工程的动作程序。程序载入编辑器后，须依次做整套路径检查、仿真试运行、明确执行。

接口支持你将搬运、码垛等算法接入；焊接工具、电气工艺、工件碰撞模型与工艺互锁需要由具体集成补充。本工程当前校验关节、模型重力及采样自碰撞，不具备通用环境自动避障，也不把算法提案当作已验证的工艺。

### 大模型API

1. 用途选 **大模型对话**。
2. 选择 **OpenAI兼容Chat Completions**，填写完整`https://服务地址/v1/chat/completions`、服务端支持的模型名、API Key。也可选择自定义HTTP JSON，由你自行封装其他API、VLA或代理系统。
3. 保存；测试连接默认查询同一服务的`/models`，也可填写服务提供的健康检查URL。测试通过仅表示JSON通信可用，实际模型能力须发送任务验证。
4. 切换 **对话任务**，选择配置，描述任务。可选择本次附加相机图像；模型须支持视觉。未勾选时不附图。
5. 点击 **载入模型生成的程序**，到程序工作区检查、仿真、再执行。模型只输出结构化提案，不能直接持有CAN、使能或控制租约。

无有效物体三维坐标、缺标定或信息不足时，模型可以只返回说明而不生成程序。自定义服务必须回传同一`request_id`；响应超过30秒或格式不符会显示错误。Chat Completions适配支持普通文本说明，以及JSON/JSON代码块中的`explanation`和`program`；不保证所有供应商的私有字段或模型格式通用。

API Key仅保存在本机`outputs/workbench/connectors.json`，目录权限0700、文件0600；配置API和导出文件不返回Key。它不是加密保险箱。同一URL留空Key保留旧值，改变URL且留空会清除旧值，也可勾选清除。

## 动作程序、导入和示教

动作格式为1.0版JSON，固定`robot_model=b601_rs`、`base_frame=base_link`、`calibration_id=rs-identity-v1`、单位m/rad/s。该标定ID表示当前运动学配置版本，不代表做过外部TCP精度或相机标定。

支持动作：

| 类型 | 内容 |
| --- | --- |
| `joint` | 六轴`joints`，可选`speed`、`duration` |
| `pose` | 六维`pose=[x,y,z,roll,pitch,yaw]`，`orientation`决定是否约束姿态，速度及可选时长 |
| `gripper` | J7电机角`position=0..5`和`speed`，不是夹爪毫米 |
| `wait` | `seconds`等待 |

最多250步。不执行任意脚本。不兼容单位、标定、未知动作或动作字段会拒绝。

可导入ROS `JointTrajectory` JSON：恰好`joint1`到`joint6`，按名字重排；`time_from_start`支持秒数或`{sec,nanosec}`，严格递增。转换为本工程的关节关键帧，按当前速度重新定时；不会照搬原速度/加速度字段。

**开始录制**记录真实反馈，自动抽取变化关键帧，也可手动 **记录当前关键帧**。录制不使能电机，可切回手动工作区操作；结束后生成可编辑、保存、导出的程序。最多120个采样关键帧，J7反馈可用时一并记录。默认按当前速度重新定时，避免录制时停留几十秒变成一段极慢运动；勾选「保留录制间隔」可保留间隔（含停顿）。回放逐点平滑到达并在关键帧停稳；不是原速度曲线的无停顿连续复现。

**检查整套路径**逐步做IK、限位、路径、速度和时长检查，最长25秒；超时请拆分程序。短时长自动延长。检查通过的预览60秒有效，起点变化超过允许差或范围改变后须重算。

**播放预览虚影**只播放目标动画；**在仿真中试运行**单独接管`/rebotarm_rs`并执行程序，绝不访问`/rebotarm`。先释放当前控制再试运行，虚影显示仿真反馈，实色仍显示当前连接的真实反馈。最后 **执行已检查程序**才通过顶部当前目标的租约执行。支持暂停、继续前重查剩余路径、取消、全局停止；迟到的预览/继续不能复活已停止的动作。

程序库在`outputs/workbench/programs/`。运行结果与进度在页面显示；真实CSP会话仍生成原有硬件报告。

## 支撑姿态、拖拽与J7

### 返回最近的已验证支撑姿态

当前已按用户2026-10-16现场指定，保存 **初始稳定姿态（J2–J6：0°±3°）**，五轴目标均0°、各自允许±3°到位偏差。返回仅调整这五轴，保留当时J1，J7不参与。实测角度与本次只读预览结果见[初始稳定姿态](初始稳定姿态.md)；真实返回/撤力尚未执行。

在手动控制下方展开 **记录当前无电支撑姿态**。先停止并释放，确认机械臂在实际无电条件下靠结构稳定、且J1旋转不影响支撑，再填写支撑点、安装、工具、负载说明并保存反馈。

之后 **预览最近支撑姿态**会保留当前J1，检查所有已验证记录的路径，选耗时较短的可行姿态。**返回最近支撑姿态**在有效接管下检查并执行；速度采用当前输入。只有本次勾选「支撑条件与记录一致，到位后撤去驱动力」，才会在确认到位后执行现有停止/失能/参数恢复。

当前这组五轴零度目标及±3°容差来自用户现场指定；自动计算不承担无电支撑验证。工具、负载、支撑或安装改变后须重新验证；本轮未做实体收纳/撤力试验。支撑库在对应驱动输出目录的`support-poses.json`，重置不会删除。

### 拖拽TCP

2026-10-19更新：选择 **拖拽TCP**，准备并接管后按住模型末端绿点选择目标，**松手后自动检查并执行到点轨迹**，远处较快、接近时减速，停稳后保持。移动平面与开始拖拽时的视角平行，可先旋转视角再拖动。自动关节速度上限取0.3 rad/s与当前模式/设备上限的较小值，独立于手动速度滑条；共用加速度、jerk及原保护仍生效。小幅模式仍受自身范围/速度/时间限制。可勾选保持拖拽开始时的姿态；旋转控制继续用键盘、手柄或RPY。

拖动期间只选目标，开始新拖动会请求暂停原运动；只有正常松手才执行一次。取消指针、切换入口、暂停、失焦或反馈过期会作废尚未执行的结果。实色模型始终由反馈驱动，拖拽目标和虚影不冒充真实位置。目标沿用现有IK与到点执行层的限位、跟踪与路径检查；不承诺TCP严格直线或环境自动避障。详见[TCP拖动选点](TCP拖动选点到位_2026-10-19.md)。

### J7夹爪

点击 **连接 / 检查J7**，由唯一CAN所有者读取ID7 / rs-00。完整模式中，接管后单独勾选「本次接管允许控制夹爪」，并使能机械臂保持，才可执行夹爪目标。程序里的J7也需要该授权。仿真试运行只在Fake命名空间自动授权其虚拟夹爪。

采用官方0关闭、5rad打开；速度上限为官方5rad/s与原设备内限速较小值；原限流/限矩更低时保留较低值，官方预设为16A、14N·m。仍用当前CSP执行方式，不调用会争抢CAN的旧MIT夹爪服务。不写PID、零位、flash。宽度动画仅按官方比例示意，未做本机开合宽度标定。

四项运行值有独立真实快照，**先写持久恢复记录，再改参数/使能**。停止先失能并连续确认停稳，再恢复原值；进程重启保留未知恢复锁，不能盲写默认值。记录在`csp-gripper-state.json`。本轮已验证内存SDK完整生命周期，未在真实J7上运动。
