# 实机异响与模式残留排查（2026-10-16）

## 用户观察

用户在“启动电机保持”后感到声音过大、怀疑卡住；顺时针手转未动，逆时针转动后自动停止，
随后再次启动报“J1 原生 XYZ 运行模式不符”。本次只读排查和离线修复，没有发送新的使能、
运动、清错、切模式或恢复参数指令。

## 日志确认的链路

1. 12:50:35 开始一次完整模式保持会话。六轴目标始终接近实测起点；J1 最大下发变化
   0.002459°，没有执行网页中的 Y+5 mm 预览轨迹。
2. J1 编码器位置差分速度读到 0.232500 rad/s，高于完整模式实测速度上限 0.12 rad/s，触发停止。
   该速度来自编码器差分，不能单独证明运动由手拨、闭环抖动或机械原因引起。
3. 六轴失能调用成功，并取得 SDK 状态模式位 0、故障位 0。它不等同独立物理停止认证。
4. 后续 1.5 秒内未确认连续 0.3 秒速度 ≤0.01 rad/s，清理失败：
   “失能后未确认连续停稳，保留低限制”。未恢复原模式/限速/电流/力矩；原始快照仍保留。
5. 12:51:30、12:51:39 再次启动前，六轴运行模式读到 5（CSP），而初始检查要求 0，故未发送
   新写入或使能就拒绝。运行模式寄存器不是使能状态；模式 5 本身不等于电机还在出力。
6. 软件重启后丢失未清理故障的内存状态，后续无写入的拒绝报告又标成 cleanup_ok=true，
   造成页面显示普通只读，掩盖此前未恢复参数的情况。这是软件状态缺陷。

## 修复

- 从本工程会话日志恢复最近一次实际改动设备的清理结果；启动前无写入的报告不能覆盖它。
- 未确认清理时保持 RECOVERY 只读反馈，准备、接管、范围切换均拒绝，重启也不会解除。
- 连接时检查非零初始运行模式并锁定；不会把未知模式直接覆盖成 0 或 5。
- 页面显示“停止/参数恢复待核查”“恢复未确认 · 禁止使能”，保留具体原因。
- 模式错误明确显示读到值与要求值，并说明模式不代表使能状态。
- 停稳采样失败时也保存已有观测。正常恢复后重建两轮新鲜速度差分窗口，再发布恢复后的模式。
- 未改变速度/力矩/电流阈值、PID、零位及 flash。未自动恢复旧目标，没有新增清错或解除恢复锁入口。

## 当前处置边界

先保持停止，不在使能保持时强行手转，也不要反复使能来测试阻力。位置保持会抵抗外力，
单方向难转也可能涉及限位、线缆或机械干涉，日志无法排除。若仍有异常声、明显发热或异味，
按现场既定支撑与独立断电流程处置。

需要先核查机械状态和异常声，再确认六轴失能与停稳，并对照事故前真实快照核对、恢复四项
临时运行参数。不能直接清错、重置零位、改 PID 或写默认参数来绕过。**本次未执行硬件恢复，
不能宣称已解决异响或恢复使能。** 原始参数见事故报告 register_snapshot。
