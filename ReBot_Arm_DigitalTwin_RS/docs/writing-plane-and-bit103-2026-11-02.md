# 书写平面约定与 BIT103

## 用户最后修正（优先于下方先前方案）

实际夹持的工具可能与夹爪纵向垂直。今后的真实书写平面必须经过实际笔尖，法线沿实际笔杆轴线，而不是直接取夹爪纵向轴。设 `a_tool` 为夹爪坐标系中的笔杆正向单位向量，`t_tip` 为夹爪到笔尖的偏移，则 `n_base = R_base_gripper * a_tool`，`p_tip = p_gripper + R_base_gripper * t_tip`。生成时冻结笔尖原点与法线；退笔沿笔杆轴反向。仅凭“垂直夹爪”不能唯一确定 a_tool。

工具安装方向、长度/笔尖偏移和外形尚未标定，不能假设 local Y 或 Z 任一垂线就是真实笔杆。新工具的碰撞体、扫掠路径和现场障碍需要检查；原机械臂自碰撞检查不等于已检查笔杆与桌面碰撞。夹爪轴版本已归档，程序库条目替换成零秒等待，显示“待工具标定”；没有执行这版。生成脚本默认拒绝把夹爪轴预览当真实笔程序，只能显式选择几何预览。

下文保留先前夹爪轴方案的实现及验证历史，不能视为最终工具书写定义。

2026-11-02，用户明确要求：书写平面经过生成程序时记录的末端位置，以夹爪纵向为法线，并保留碰撞检查。此约定取代先前固定基座 XY / Z 高度的默认解释。

## 平面定义

控制 TCP 沿用 `TwinKinematics` 中的 `gripper_end`。URDF 的 `j_gripper_end`、手指安装位置以及 MuJoCo 夹爪体一致表明夹爪纵向为该坐标系的 X 轴，不能套用其他机器人常见的工具 Z 轴。

生成时记录 `p0` 和 `R_base_tcp`，整个程序保持这组坐标：

- 书写横向 `u = -R[:,1]`，纵向 `v = R[:,2]`。
- 法线正方向取退笔方向 `n = -R[:,0]`；正负不改变平面本身。
- 笔画目标 `p = p0 + a*u + b*v`，满足 `dot(p-p0,n)=0`。
- 换笔时沿 `+n` 回撤 5 mm，不是沿基座 Z 轴抬高。
- 末端姿态在笔画和退笔中保持不变；运动时不以新反馈持续重建平面。更换原点或夹爪朝向须重新生成并预览。

通用纯数学实现为 `scripts/writing_plane.py`，BIT103 生成器默认使用它。程序中的 `writing_plane` 只保存冻结坐标、供二维展示；动作仍为既有 schema 1.0 的三维 pose，执行器检查实际三维路径。网页按 u/v 展开笔画，三维窗口仍使用 base_link 的实际路径；旧驱动丢弃显示元数据时，网页从匹配编辑器保留冻结平面。

## BIT103 新版

- 总宽 90 mm，字高 20 mm，13 笔，共 152 步；低速 0.05 rad/s，固定当前姿态。
- 本机程序库名称：`BIT103 · 末端法向平面 · 90mm`。旧 XY 程序原件归档保留，其程序库条目已替换为无运动的等待步骤，避免误用。
- 最新生成原点来自新鲜保持反馈；先前 77.821633 mm 的 Z 快照作为历史保留，不再被解释为新版的固定水平面。
- 离线全部逆解、关节限位、额定重力包络、采样模型自碰撞检查通过；采样关节插值的最大平面偏差约 0.00495 mm，最大线偏差约 0.00512 mm，换笔段最小退笔距离约 4.643 mm。这是模型值，不是外部笔尖精度或真实墨迹验证。
- 当前实机驱动仅作整套路径预览，通过 152 步，估计约 163.2 秒；没有执行新版，没有接管或使能请求。
- 检测覆盖当前模型的机器人自碰撞。桌面、工件、额外笔具或人体并未因这个改动自动进入碰撞场景；模型 TCP 也不等于已标定笔尖。接触书写仍需笔尖/表面标定和现场空间核对。

## 本轮实际动作与中断记录

在用户补充法向平面定义之前，曾按原固定 XY 解释生成并执行一次 153 步程序。离线及当前驱动预览均通过，但实机在进入第 11 步（第一笔结束后的移笔）时触发原 600 ms 反馈保护，最大记录年龄 733.013 ms，程序 cancelled，未写完整。无自动重跑。

驱动保持原位置目标，后续连续 20 帧反馈有效，最大约 377.351 ms，HOLDING、无控制者、已准备、六轴模式 5，保持反馈确认；没有调用失能、退出、重启或重配 CAN。此后新版仅预览，反馈超时的根因尚未修复，不能把新版预览通过当作已完成实机书写。后续须重新核对实时状态；保持状态下普通失能或服务退出会撤力。

## 个性化排序

现有功能排序保存在 `rebot-feature-order-v1` 的 localStorage，同一设备、同一浏览器用户配置、同一站点地址下重新打开会恢复；不同浏览器用户配置独立。实测重载前后 16 个功能顺序完全一致，没有恢复初始排序。系统没有跨浏览器的人物身份识别，不能将同一个浏览器配置中的不同使用者自动分开。
