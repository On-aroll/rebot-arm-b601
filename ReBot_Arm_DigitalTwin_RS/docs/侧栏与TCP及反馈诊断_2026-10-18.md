# 侧栏、TCP 与反馈诊断更新

日期：2026-10-18。范围：用户新增四项的软件实现与验证。

## 1. 侧栏与功能页面

- 拖动入口右侧的 `⠿` 调整顺序；也可聚焦入口后按 Alt + ↑ / ↓。
- 顺序保存在本机浏览器，刷新后保留。未知、重复、损坏的旧排序记录不会丢失入口。
- 嵌入式浏览器使用指针拖动；普通浏览器保留 HTML 拖放。拖动结束不触发导航。
- 动作程序页优先显示导入、程序库、编辑器、检查与执行；不再混入位置与姿态控制。
- 示教录制独立为一个页面。坐标、键盘、手柄、TCP 仍各显示自己的操作区。
- 移除独立的“速度与平滑”入口。需要运动配置的功能在主内容下方显示配置；切换页面移动同一组参数控件，草稿不会因为复制控件而不一致。
- 手动滑条仅在适用页面显示。程序各步速度仍由 JSON 的 `speed` 指定，轨迹平滑配置共用；页面内说明了影响范围。
- 七轴参数收进下方“七轴参数与跟随诊断”。MotorBridge 与 ROSBridge 保留独立入口。

## 2. TCP 绿色拖拽点

原问题：停止本地动画会关闭 `dragMode`，但 `twinDrag` 仍为 true。旧 `setTwinDrag(true)` 因布尔值未变直接返回，无法恢复标记。

现在会核对实际拖拽状态，并在进入 TCP 页和收到控制状态时恢复视觉标记。切换到其他功能时关闭 TCP 标记；保留原项目独立拖拽方式。显示标记不代表已取得控制权，运动仍需新鲜反馈与控制许可。

## 3. 程序反馈过期

历史日志 `outputs/twin-console/hardware/csp-session-1792287161851677057.json` 显示：

- 暂停原因是实机反馈过期；J3、J4 位置年龄分别为 638.411、610.394 ms。
- 最近查询回复最长 12.691 ms，但查询之间空档最长 97.876 ms。
- 因此不能把此次问题简单归结为单次 CAN 回复慢，也不能仅通过放宽反馈期限解决。

软件修改：

1. ROS 控制与看门狗仍按 20 ms 执行；状态计算和 JSON 发布按独立 50 ms 相位执行，跳过过期状态时槽，减少重复工作。
2. 路径检查使用每线程独立的 Pinocchio / MuJoCo 工作数据，避免 CAN 参考更新等待预览线程占用的路径锁。重力、路径采样及自碰撞检查仍执行。
3. 增加近 64 次查询的回复耗时、查询间空档及逐轴反馈年龄显示。故障日志同时保留每次查询间空档。

这些是减少竞争的修改，不足以证明所有历史空档都来自上述两处。600 ms 实机反馈、500 ms 完整模式命令、500 ms 网页收包、700 ms 心跳、250 ms 手动输入期限保留。通信异常仍冻结原目标并进入 HOLDING，不能自动继续旧程序。

## 4. J3–J5 颤动与参数

历史会话使用 CSP；MIT 的 Kp/Kd 不参与该会话运动。使能是开关，不能理解为“使能强度”。完整模式已按电机型号采用不同运行上限：

| 轴 | 电流上限 A | 峰值力矩上限 N·m | 持续重力模型上限 N·m |
|---|---:|---:|---:|
| J1–J3 | 57 | 36 | 11 |
| J4–J6 | 16 | 14 | 5 |

这些是限制值，不代表当前输出或可持续输出。对应来源在 `csp_official_limits.py`，CSP 原有内部 PID 读取后保留；本轮未提高上限或写入 PID。

新增：

- 逐轴实测电流、跟随误差、反馈年龄，以及本次启动读取的 CSP 环参数快照（0x701e / 0x701f / 0x7020 / 0x702b）。没有读过就显示“—”，不伪装成实测值。
- “填入柔和试调草稿”：将共用加速度/jerk预算填成 25% / 20%，减小启停冲击；保留六轴路径同步。需要明确点击“应用并保存参数”才保存，且沿用停止、释放后的应用条件。
- 草稿是未做实机调定的试调起点，不是 J3–J5 专属 PID 或已经证实有效的负载补偿。实际改善、负载与跟踪能力仍需现场数据验证。
