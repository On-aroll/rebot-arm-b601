# 一键重置控制状态

网页右上角「↻ 重置控制状态」是统一的恢复入口。

## 怎么用

1. 保持 ROS 连接。实机异常声、卡滞或受力异常时先处理现场问题，并托住可能因失能下落的机械臂。
2. 点一次「↻ 重置控制状态」。按钮会显示「正在重置」，不需要先接管，也不需要先使能。
3. 查看页面顶部结果：成功后保持只读；失败时显示具体原因，继续保留实机恢复锁定。
4. 成功后需要重新勾选现场确认、打开网页控制许可、准备并接管，再发起新的操作。

控制范围选择保留，速度回到该范围的默认值。重置不是回零，机械臂不会主动回到某个姿态。

## 重置哪些状态

| 状态 | 重置结果 |
| --- | --- |
| 控制权与电机 | 释放租约、撤销准备；六轴 J1–J6 请求失能并逐轴核对返回状态，不参与 J7 |
| 键盘、屏幕按钮、手柄 | 清空按住状态与指针，手柄重新要求回中，默认回到「坐标到点」 |
| 目标与轨迹 | 清空预览、执行目标、参考、误差结果和目标虚影；重置前的延迟请求作废 |
| 输入框与姿态 | 回填新的实测位置/姿态；默认「仅位置（自动选择姿态）」 |
| 控制许可 | 取消现场确认及网页写入开关，需要重新主动打开 |
| 临时运行参数 | 只按本驱动事故前的完整六轴快照核对恢复，保存完整过程 |
| 故障记录与标定 | 保留记录；不写 PID、零位、标定、flash，不发送固件清错/恢复出厂指令 |
| 相机与观察 | 保留画面连接及只读反馈，便于继续观察 |

没有 ROS 连接时，只清空本页状态；页面会明确提示「未确认实机停止或参数恢复」。重新连接反馈后再点一次，
不会因为刷新网页就宣称设备已经恢复正常。

## 实机恢复的检查

所有 CAN 操作仍由当前独占工作线程串行执行，不打开第二条硬件连接。活动会话先完成停止清理，重置不申请运动许可。

- 六轴失能返回状态全部通过，且无返回故障位。
- 新鲜六轴反馈连续至少 0.3 秒速度不超过 0.01 rad/s；2 秒内不能确认就拒绝恢复。
- 有临时参数残留时，必须有本工程会话的原始完整快照、匹配的控制方案。
- 恢复前核对所有轴：四项运行参数只能是原快照值或该会话明确使用的临时值；PID 等保护参数必须与原快照相同。
- 只恢复 `0x7005/0x7017/0x7018/0x700b`；写后读回核对。不装载旧位置目标，不调用 enable。
- 参数扫描和恢复期间持续刷新反馈；运动、反馈过期、未知参数、缺失快照、读回错误均保留锁定。
- 按时间保存 `outputs/twin-console/hardware/csp-session-*.json`，记录来源快照 SHA256、失能、停稳和恢复。
  失败可重试，仍沿用最初事故快照。原事故报告不删除；重启也保留未完成的恢复记录。

此按钮用于纠正控制流程和本驱动临时参数残留，不能修复机械卡滞、噪声或真实电机故障。
失能状态依据 SDK 返回帧，没有独立设备时间戳；实机是否受力、是否存在机械损伤仍须现场检查。

## 接口与验证

- ROS 服务：`/rebotarm/twin/reset`（实机）、`/rebotarm_rs/twin/reset`（仿真），类型 `std_srvs/srv/Trigger`。
- 实机服务立即返回任务 ID；`twin/state.reset_status` 报告 queued/running/succeeded/failed。
- 重复请求在同一任务运行期间返回同一任务 ID；不排队、不使能、不重放旧轨迹。
- 页面请求超时或断线会提示「未确认」，不自动重试。
