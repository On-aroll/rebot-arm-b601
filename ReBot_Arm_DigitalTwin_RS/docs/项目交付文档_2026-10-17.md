## 2 系统组成与控制链路

### 2.1 运行结构

网页通过 rosbridge 与 ROS 2 通信。仿真命名空间为 `/rebotarm_rs`，实机为 `/rebotarm`。网页的实线模型显示测量反馈，目标影子和预览路径显示计划目标；两者不能互相替代。

运动输入依次经过统一控制仲裁、路径与限位检查、参考轨迹生成、所选驱动后端，最终由唯一 CAN 线程与机械臂通信。坐标到点、键盘、手柄、TCP、程序执行共用这一链路。相机、视觉、规划与大模型接口只提供观测或结构化程序提案。

| 模块 | 主要文件或目录 | 职责 |
| --- | --- | --- |
| 网页与本机 API | `reBotArm_simulator-RS/` | 交互、显示、程序与连接配置 |
| 统一控制 | `twin_control.py`、`twin_extensions.py` | 控制租约、状态机、动作与扩展功能 |
| 轨迹与调参 | `twin_motion.py`、`twin_servo.py`、`twin_algorithm.py`、`twin_tuning.py` | 参考生成、反馈控制与参数管理 |
| 实机与 CAN | `csp_twin_driver.py`、`csp_hardware.py`、`csp_runtime/` | 只读查询、驱动模式、保持与恢复 |
| 模型与仿真 | `rebotarm_ros2_RS/src/rebotarm_mujoco_rs/` | RS 模型、场景、相机与仿真反馈 |
| 运维入口 | `rebotarm`、`scripts/`、`launchers/` | 启动、环境、安装和桌面入口 |

上述 Python 文件位于 `rebotarm_ros2_RS/src/rebotarmcontroller/rebotarmcontroller/`。

### 2.2 端口与 ROS 接口

| 接口 | 默认地址或名称 | 用途 |
| --- | --- | --- |
| 网页 | `http://127.0.0.1:3002/` | 本地工作台 |
| rosbridge | `ws://127.0.0.1:9090` | 网页与 ROS 2 桥接 |
| 实机进程 API | `/api/hardware/status`、`connect`、`disconnect` | 同源本机受管启动与退出 |
| 工作台 API | `/api/workbench/` | 程序库、连接配置、视觉与模型接口 |
| 状态与参考 | `/{namespace}/twin/state`、`events`、`reference` | 状态、事件、轨迹参考 |
| 控制接口 | `/{namespace}/twin/command`；服务 `acquire`、`stop`、`suspend`、`reset` | 命令、接管、停止与重置 |
| 实机反馈 | `/rebotarm/joint_states`、`/rebotarm/arm_status` | 关节与控制状态 |

表中 `namespace` 替换为 `rebotarm` 或 `rebotarm_rs`。实机 `/rebotarm/enable` 服务目前表示准备控制，不等于电机已经出力；`/rebotarm/disable` 会提交失能请求。不要仅凭服务名称判断物理状态。

可选 MCP 地址为 `http://127.0.0.1:8081/mcp`，自然语言入口端口为 8082，接口演示端口为 8088。演示接口只返回示例等待动作或空识别结果，不含实际智能模型。

## 3 环境与部署

### 3.1 环境要求

推荐 Ubuntu 24.04、ROS 2 Jazzy、Python 3.12 和 Node.js 22 及以上（需全局WebSocket/fetch）。Ubuntu 22.04、ROS 2 Humble、Python 3.10 为兼容路径，迁移后需要重新回归。SocketCAN 接口默认 `can0`，速率 1 Mbps。

固定 Python 依赖包括 `motorbridge==0.5.6`、`pin==4.1.0`、`ruckig==0.12.2`；MuJoCo、NumPy、SciPy、fastmcp 使用版本范围，详见根目录 `requirements-rs-*.txt`。本交付不宣称所有依赖都已完全锁定。ROS ABI 与 Python 版本必须配套。

已安装环境从工程根目录运行：

## 4 日常使用与动作程序

### 4.1 实机操作流程

1. 启动网页与仿真，检查 CAN 接口和连接状态。
2. 在实机入口连接，只读观察六轴与 J7 反馈是否持续新鲜。导入、切换页面和只读连接均不应自动执行程序。
3. 按操作范围选择小幅或完整模式。完整模式可配置驱动后端与共用轨迹参数；配置应用须在只读、未准备、无控制主状态下完成。
4. 现场核实方向、零位和限位，确认人员可断电且运动空间满足当前任务条件，再打开所需操作许可。
5. 手动操作按页面提示准备、接管，再显式启动保持或运动。程序可点击“使能并执行程序”，自动完成完整范围切换、准备、接管、从当前反馈起点检查与执行。
6. 操作后区分暂停保持与失能撤力；在托住机械臂或确认无电支撑后再失能、重置、退出实机服务或关机。

执行不要求先观察一遍仿真。起点、限位、路径、负载与反馈检查由软件内部执行；检查失败应处理具体原因，不用跳过检查来完成启动。

### 4.2 手动操作与 J7

坐标到点、键盘、标准手柄、TCP 拖拽和 J7 共用低速、常速、高速、当前最高及自定义档位。“当前最高”仍受官方上限与设备原有限速约束。程序步骤中的 `speed` 独立设置，不由手动档位代替。

键盘按住空格时使用页面显示的运动键，夹爪使用 Q/E；标准手柄按住 RB，A/B 控制夹爪。松开允许键或输入过期会清空手动输入。J7 参数并列在七轴参数表中，内部仍有独立范围、反馈和恢复校验。

TCP 仅位置拖拽允许 IK 调整朝向；勾选锁朝向后会约束姿态。J5 是否移动取决于当前姿态与目标的逆解，不要求每次拖拽六轴都明显运动。其实体手感仍需验证，不应据界面推断电机损坏或问题已经解决。

### 4.3 程序导入合同

推荐使用工作台导出的 JSON 作为模板。顶层需要 `schema_version`、`robot_model`、`base_frame`、`calibration_id`、`units` 和 `steps`。一份程序含 1 至 250 步，角度为 rad、位置为 m、时间为 s。

| 步骤类型 | 核心字段 | 约定 |
| --- | --- | --- |
| `joint` | `joints` 六关节角、`speed` | 按关节目标规划 |
| `pose` | `pose` 六元素 XYZ RPY、可选 `orientation` | 根据当前模型与姿态约束解算 |
| `gripper` | `position`、`speed` | J7 角度范围 0 至 5 rad，非毫米开口量 |
| `wait` | `seconds` | 等待 0 至 3600 秒 |

以下是不会产生位移的最小导入示例，可先验证文件格式和导入流程：

```json
{
  "schema_version": "1.0",
  "robot_model": "b601_rs",
  "base_frame": "base_link",
  "calibration_id": "rs-identity-v1",
  "units": {"position": "m", "angle": "rad", "time": "s"},
  "steps": [{"type": "wait", "seconds": 1.0}]
}
```

关节速度格式校验范围为 0.005 至 1.5 rad/s，实际执行还受设备原有限速等约束，超出时拒绝。可选 `duration` 不会强迫轨迹超过运动限制。导入的 ROS 轨迹会转换为关键帧并重新定时；示教与程序当前逐点停稳，未实现连续穿点。

编辑程序、修改运动配置或改变起点会使旧检查失效。继续前需重查剩余路径，恢复反馈不会自动续跑。程序草稿需保存至程序库或导出文件，不能依赖未保存页面内容。

### 4.4 国庆快乐示例与 ROS 高亮

在程序工作区载入“国庆快乐”，或导入 `examples/writing/guoqing_kuaile.json`。程序包含 182 步、26 笔，关节速度 0.1 rad/s，设计为空中书写。字符约 50 mm、字间隔 12 mm，书写平面 Z 为 250 mm，抬笔 Z 为 262 mm；适用起点仍须重新检查。

```bash

```

此命令启动 RViz 规划路径预览，不申请实机控制，不发运动。高亮笔画发布到 `/rebotarm_writing/strokes`，完整 TCP 路径发布到 `/rebotarm_writing/tcp_path`。这是模型 FK 计算的计划路径，不是实测笔尖轨迹。

## 5 控制方案与参数调整

### 5.1 三层配置

| 层级 | 可选方案 | 生效方式与范围 |
| --- | --- | --- |
| 共用参考轨迹 | Ruckig 默认、五次曲线 | 完整模式各运动入口共用；小幅与 J7 保留原平滑方案 |
| 电机驱动后端 | CSP 默认、MIT 位置 PD | 完整模式只读配置后使用；每次启动恢复 CSP |
| 主机反馈控制器 | P、PD、PID、增益调度 PID、LADRC、线性 MPC | 显式启动固定关节目标控制后接管，输出速度再经共用执行链路 |

因此，常规手动和程序运动默认使用 Ruckig 与 CSP；选择反馈控制器不会自动让全部运动变成 PID 或 MPC。MIT 是电机驱动接口，PID 等是上层反馈算法，两层分别配置。

MIT 当前发送位置参考、零速度前馈、逐轴 Kp/Kd 和零力矩前馈，并非整臂动力学力矩控制。逐轴增益来自锁定官方配置，仅允许向下调整；没有写入电机内部 PID、零位或 flash。新算法未附带神经网络、强化学习策略或已辨识的整臂负载模型。

### 5.2 调参工作流

先在只读状态选择方案、建立独立命名档案并导出备份；试算检查计算结果和限幅情况，再在现场条件满足时进行小幅单目标测试。每次调整少量参数，记录目标、负载、速度、误差和触发原因，比较同一条件下的记录后再扩大范围。

Ruckig 与五次曲线各自保存加速度和 jerk 比例，范围 5% 至 100%，仅缩小原包络。反馈控制器拥有各自参数；页面提供误差 RMSE、峰值、限幅计数及算法诊断，试算记录不能冒充实体运行记录。算法运行频率为 5 至 20 Hz。

命名档案与草稿保存在当前浏览器 localStorage，迁移浏览器前必须导出；共用实机运动与驱动配置另保存到服务端硬件目录。未经实体调参，不应把默认参数当作已适配所有负载的参数。

### 5.3 主要限制与时序

| 项目 | 完整模式基线 | 说明 |
| --- | --- | --- |
| 六轴速度 | 0.005 至 min 1.5 与设备原限速 rad/s | 本机原限速 1.0，手动默认 0.1 |
| 加速度与 jerk | 4 rad/s²、30 rad/s³ | 再乘当前档案比例 |
| 参考调度 | 目标间隔 20 ms | 非硬实时 50 Hz 保证 |
| 命令期限 | 500 ms | 完整模式六轴与 J7；小幅仍 300 ms |
| 电机字段反馈期限 | 600 ms | 模式、电流、位置分别计时 |
| 网页状态期限 | 500 ms | 网页收不到状态的期限 |
| 控制租约心跳 | 700 ms | 与电机反馈期限不同 |
| 手动输入有效期 | 250 ms | 与连续使能保持不同 |
| 关节跟踪误差 | 3° | 超差保护仍保留 |

名义关节范围为 J1 ±150°，J2/J3 0 至 3.14 rad，J4/J5 ±1.57 rad，J6 ±3.14 rad。小幅模式每轴位移不超过 0.5°、速度不超过 0.02 rad/s，并有从首次使能起 15 秒试机期限。表内期限是本项目控制策略，不能表述为官方统一要求。

实际通信使用同步参数查询。本次只读观察的最大反馈年龄约 121 ms，不代表活动出力、负载变化或故障时一定达到同样性能。调大期限不能解决 USB 断开、总线无回复或实际跟踪超差。

## 6 暂停保持与异常处置

### 6.1 状态与动作语义

| 状态或操作 | 控制行为 | 操作人员注意事项 |
| --- | --- | --- |
| READONLY | 只读反馈阶段，准备与控制主另看状态字段，尚未进入 ACTIVE | 不等于从模式位读到了实际失能状态 |
| ACTIVE | 有效控制会话下发送目标 | 持续观察反馈与任务状态 |
| 暂停并保持或 HOLDING | 完整模式已出力时冻结已有目标，撤销旧输入和控制租约 | 不自动续跑；反馈未确认时不能宣称已托住 |
| FEEDBACK_WAIT | 已连接、非活动只读超时后重试并重建速度窗口 | 恢复后仍需重新准备与接管 |
| RECOVERY | 上次清理或写入状态未核实 | 查恢复记录，不删除记录绕过锁定 |
| 失能、Esc、重置、服务退出 | 可能撤去电机出力并恢复参数 | 先托住或确认无电支撑，避免重力下落 |

完整模式 ACTIVE 下，通信超时、网页失焦失联或释放控制会进入 HOLDING，冻结既有参考并撤销旧输入。反馈恢复后必须满足新鲜、静止、跟踪及相应参考核对条件，再明确接管。不能自动从故障前目标续跑。

保持参考不是机械抱闸。断电、固件失能、驱动退出或硬保护仍可能导致机械臂下落，软件无法保证断电承重。若状态未知，应先处理机械支撑，再处理软件恢复。

初始支撑姿态当前按用户定义为 J2 至 J6 各 0°、容差 ±3°，J1 保持返回时角度，J7 不参与。它尚未通过实际返回与撤力验收，不能当作适用于任何安装和负载的安全回零姿态。

### 6.2 常见故障定位

| 现象 | 首先检查 | 处理方向 |
| --- | --- | --- |
| can0 DOWN 或没有 bitrate | `ip -details -statistics link show can0` | 无活动或保持控制时重新配置 1 Mbps |
| ERROR-ACTIVE 且错误计数 0 | CAN 状态及 RX 计数 | ERROR-ACTIVE 是正常错误管理状态，非故障报警 |
| TX 增长而 RX 为 0 | 本体供电、线缆、适配器、端接、其他接收者 | 检查物理通信，不靠反复使能解决 |
| 网页超过 500 ms 未更新 | 网页 ROS 连接、浏览器负载、控制器状态 | 区分网页未收到状态与电机反馈过期 |
| 首目标反馈过期 | 启动记录的具体字段年龄 | 查看实机日志；不连续重复点击使能 |
| 运动颤动 | 时间间隔、参考与实测、跟踪误差、负载 | 用相同条件记录定位，不能仅归因为速度过低 |
| J3 跟踪超差 | 参考与实测差值、姿态与负载 | 当前仍待单独实机诊断 |
| 恢复锁定 | 最近会话中的写入意图与恢复结果 | 保留会话文件，按失败字段处理 |

USB-CAN 重插或电脑重启后，临时速率配置可能丢失；当前未安装自动热插拔配置规则。确认没有活动或保持中的控制器后，若接口为 DOWN，可执行：

```bash
sudo ip link set can0 type can bitrate 1000000 && sudo ip link set can0 up && ip -details link show can0
```

不要把两个 `sudo` 命令直接拼接；使用上面的 `&&`。已经 UP 的活动接口不要为了“重试”先 down。复核后仍无回复，保留日志并检查物理链路。

### 7.2 停机与迁移步骤

正常结束先停止任务并确认状态，托住或确认无电支撑后再失能和退出实机连接。网页“断开实机”会终止受管驱动，不能当作仅关闭显示。`./rebotarm stop` 只停止 `managed.pids` 中本启动器管理的仿真与网页进程，不是全部服务急停，也不能证明机械臂已失能。

迁移前导出算法档案与未保存程序，保存恢复记录和设备参数，隔离密钥，再复制完整源码与必要数据。`.venv`、ROS 的 `build/install/log` 和缓存可在目标机重建；SDK 按锁定版本重建。迁移到另一台机械臂时，不直接套用原设备会话、支撑姿态和限速快照。

当前不提供经过净机演练的离线安装包、系统服务自启动或 CAN 自动恢复规则。交付接收人需按第 3 节部署并重新验证，而不是把运行中的 PID、端口或浏览器状态当作可迁移资产。
