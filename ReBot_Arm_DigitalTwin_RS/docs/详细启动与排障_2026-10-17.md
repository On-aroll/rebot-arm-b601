# B601-RS 详细启动与排障参考

**交付版本：2026-10-17｜适用入口：3002 虚实控制工作台｜本机：Ubuntu 24.04 / ROS 2 Jazzy。**

本指南供日常操作和项目交接使用。项目根目录为：

```text
/home/bonvoyage/Desktop/rebot-b601-doc-replica/ReBot_Arm_DigitalTwin_RS
```

完整交付范围、安装迁移、接口与验收边界见[项目交付文档](项目交付文档_2026-10-17.md)。以下命令均在上述根目录执行；本指南不要求启动其他历史工程或 8765 页面。

## 1. 启动工作台

### 桌面或终端启动

双击桌面的 **ReBot Arm B601-RS 一键启动**。没有启动器时，在项目根目录安装：

```bash
./scripts/install_desktop_launcher.sh
```

启动器调用 `scripts/quick_start.sh`，其 `.desktop` 的 `Path`、`Exec` 为本机绝对路径。换电脑或移动目录后，应按交付文档修正路径再安装。

终端启动：

```bash
cd /home/bonvoyage/Desktop/rebot-b601-doc-replica/ReBot_Arm_DigitalTwin_RS
./rebotarm start all
```

不自动打开浏览器：

```bash
./rebotarm start all --no-browser
```

启动内容是 RS Fake Driver、MuJoCo、rosbridge、网页；MCP Agent 默认随仿真启动。**一键启动不会连接真实电机、使能或发真实运动指令。** 已在运行的仿真和网页会被复用。

| 入口 | 地址 / 名称 | 用途 |
| --- | --- | --- |
| 网页工作台 | <http://127.0.0.1:3002/> | 日常操作入口 |
| ROS WebSocket | `ws://127.0.0.1:9090` | 网页与本机 ROS 连接 |
| 安全仿真 | `/rebotarm_rs` | Fake / MuJoCo 链路 |
| 实机 | `/rebotarm` | 显式连接后提供真实反馈 |
| MCP Agent（默认开启） | `http://127.0.0.1:8081/mcp` | 仿真任务服务 |

打开网页后，在顶部 **选择控制对象** 中选择「安全仿真」或「实机 + 数字孪生」。仅启动网页或打开页面不执行已导入的程序。

### 首次使用已有环境

```bash
./rebotarm doctor
```

相当于 `./setup.sh --check`，用于只读检查依赖及生成文件。2026-10-19已修复已登记CSP checkout被误判为非法嵌套Git的问题：先用 `bash scripts/setup_csp_sdk.sh --check` 核对清单锁定的commit和干净源码；缺失时在新机器运行不带 `--check` 的准备命令，再做基础安装。未知嵌套仓库或SDK修改仍会拒绝，不要删除SDK的 `.git` 绕过。依赖要求Node.js≥22且具有全局WebSocket/fetch。不要直接搬用原机器的 `.venv`、`build`、`install`，详见[本轮改进记录](架构建议评审与改进_2026-10-19.md)。

## 2. 安全仿真体验（可选）

网页选择 **安全仿真 → 启动并连接仿真 → 接管控制**。确认反馈更新后，可使用坐标、键盘、手柄、TCP 或程序工作台。

- **坐标到点**：填写基座坐标系 XYZ，单位 mm；RPY 单位 °。选择姿态约束，点击「计算并预览」，再「执行预览轨迹」。默认「仅位置」允许逆解选择朝向。
- **键盘 / 按钮**：点键盘焦点按钮，按住空格，再按方向键；编辑输入框时不会执行键盘移动。
- **手柄**：使用浏览器识别为 Standard 的手柄，按任意键唤醒；按住 RB / R1 后操作。
- **TCP 拖拽**：接管后拖动三维窗口末端绿色圆点；默认允许朝向随逆解调整，可勾选保持朝向。

实色模型显示反馈，虚影显示规划目标。程序预览、Fake / MuJoCo 成功不等于实机已经执行，也不替代实际工具、负载和工作区标定。

一键启动默认关闭独立 MuJoCo 窗口，网页仍可显示三维模型。仅启动仿真链路：

```bash
./rebotarm start quick --simulation-only
```

需要无物理求解的运动学模式：

```bash
REBOTARM_MUJOCO_MODE=kinematic ./rebotarm start quick --simulation-only
```

环境变量只影响新启动的仿真进程，复用已有实例时不会因此切换模式。

## 3. 连接实机：先获得只读反馈

### 3.1 检查 CAN

机械臂本体通电、USB-CAN 与 CAN 线接好后，先查看：

```bash
ip -details -statistics link show can0
```

期望看到接口 `UP`、`bitrate 1000000`，CAN 状态为 `ERROR-ACTIVE`。**`ERROR-ACTIVE` 是正常 CAN 工作状态名称，不代表已报通信故障。** 同时检查错误计数，不能只看接口名称。

只有在 **`can0` 为 DOWN、机械臂未由活动控制器驱动且已妥善支撑** 时，才配置并启用：

```bash
sudo ip link set can0 type can bitrate 1000000 && sudo ip link set can0 up && ip -details link show can0
```

整行复制并保留 `&&`。系统要求本机管理员密码时，在自己的终端输入。不要把两条 `sudo` 命令直接拼在一起。

USB-CAN 拔插或电脑重启后，接口可能重新出现为 DOWN，临时速率配置也会丢失，需重新检查。**本交付未安装自动恢复 CAN 的系统规则。** 如果接口已 UP，或机械臂正在运动 / 保持，不要降接口、改速率、拔 USB 或重启服务来“刷新连接”。

### 3.2 网页连接

1. 保持 3002 工作台运行，选择 **实机 + 数字孪生**。
2. 点击 **连接实机反馈**，页面启动或复用 `scripts/start_rs_twin.sh` 对应的统一实机反馈服务。
3. 等待实色模型、J1–J7 参数和反馈时间更新；确认没有恢复锁或故障。
4. 尚未操作时保持未准备、未接管。连接只建立只读通路，不会自动使能或回零。

连接使用单一 CAN 所有者。不要同时打开旧硬件驱动、MotorBridge 调试工具、CAN 抓包接收器或另一个控制进程；出现总线所有权拒绝时应核查占用来源。

界面中的「本会话使能」是控制器记录，不是电机真实使能位的读回；模式值为 0 也不能单独证明电机已经失能。

### 3.3 范围与手动控制

| 范围 | 当前行为 |
| --- | --- |
| 小幅试机（连接默认） | 相对接管起点每轴最多 0.5°，关节速度 0.005–0.02 rad/s，首次使能起最多 15 秒，J7 不参与 |
| 完整控制 | J1–J6 名义模型限位内；速度 0.005–min（官方上限 1.5、设备原限速）rad/s，本机最近核验设备上限为 1.0 rad/s；健康会话可持续保持 |

完整控制不要求先运行一次小幅试机。范围切换、轨迹与驱动参数应用要求只读、未准备、无主的状态；页面会阻止不满足条件的操作。

手动操作：

1. 核实方向、零位、限位及机械臂和工具的活动空间，现场有人可立即处理异常；勾选顶部现场确认。
2. 在「连接与高级设置」确认网页实机控制许可，点击「准备完整控制（不使能）」或小幅准备，再「接管控制」。
3. 可点 **启动电机保持（使能）**，从新鲜实测位置启动保持；也可由首个有效运动输入启动。
4. 坐标按预览 → 执行，键盘 / 手柄 / TCP 按住操作。使用结束按第 6 节处理保持与撤力。

## 4. 导入并直接执行动作程序

### 常规导入与实机执行

打开 **动作程序与示教 → 导入程序 JSON**。支持本工程版本化动作 JSON 和 ROS `JointTrajectory` JSON。工程程序使用 `schema_version=1.0`、`b601_rs`、`base_link`；位置 m、角度 rad、时间 s，与手动坐标框的 mm / °不同。

导入后可编辑、导出或保存到本机程序库。**导入、载入和切换界面本身不启动程序。** 详细格式见[程序工作台与接口](算法接入与程序工作台.md)。

**不要求先观看仿真或手动播放预览。** 连接实机并获得新鲜反馈后：

1. 核实现场条件，勾选顶部现场确认。
2. 在程序工作台载入程序，确认名称、单位、工具和工作区适用。
3. 点击 **使能并执行程序**。

该明确点击授权本次网页控制，自动完成完整范围选择、准备、接管、从当前真实起点检查整套路径，再使能执行。后台仍检查限位、模型路径、重力包络、反馈和恢复状态，不需逐个手动点击准备与接管。若已有小幅接管会话，应先按界面要求结束该会话后再执行完整程序。

程序完成后保持姿态。「暂停程序」「继续程序」「取消程序」用于本次任务；取消清除后续任务，不等同顶部「失能撤力」。通信保持后旧程序不会自动恢复，须按状态提示重新接管和检查。

### 「国庆快乐」与 ROS 路径高亮

点 **载入「国庆快乐」**，或导入：

```text
examples/writing/guoqing_kuaile.json
```

共 182 步、26 笔，是 `gripper_end` 的空中书写轨迹，关节速度上限 0.1 rad/s。网页提供彩色笔画和三维路径；当前段高亮来自执行步骤进度，不是外部实测笔尖轨迹。程序逐点到位，没有连续匀速穿点功能。

仅查看 ROS / RViz 高亮：

```bash
bash scripts/preview_guoqing.sh
```

该脚本仅发布可视化并打开 RViz，不接管 CAN 或使能。话题 `/rebotarm_writing/strokes` 为 `MarkerArray`，`/rebotarm_writing/tcp_path` 为 `Path`，坐标系 `base_link`。关闭 RViz 同时结束本次预览节点。

本例没有笔尖 TCP、纸面或接触力标定；实际接触书写需按工具重新标定，不能直接把默认 Z 高度当成纸面。参数和验证见[书写程序说明](国庆快乐书写程序.md)。

## 5. 速度、J7 与控制方案

### 手动操作速查

| 操作 | 按键 / 行为 |
| --- | --- |
| 键盘平移 | 空格 + W/S：X，A/D：Y，R/F：Z |
| 键盘姿态 | 空格 + U/O：Roll，I/K：Pitch，J/L：Yaw |
| J7 开合 | 空格 + Q/E；手柄 RB + A/B；或按住页面开合按钮 |
| 手柄 | 按住 RB / R1；左杆 XY、十字键 Z、右杆 Pitch/Yaw、LT/RT Roll；LB / L1 为 ¼ 精细速度 |
| TCP | 拖末端绿点改变位置；勾选项锁朝向，RPY 按钮微调姿态 |

J7 已整合到键盘、手柄和统一 J1–J7 参数显示中，仍受同一 CAN 线程、夹爪范围和反馈检查约束。小幅试机不含 J7。

「手动速度档位」有低速、常速、高速、当前允许最高速度及自定义，作用于坐标、键盘、手柄、TCP 和 J7。到点用关节速度上限，平移 / 旋转速度用于遥操作；最高档仍受设备、加速度、姿态和内部包络限制。程序按各步 `speed` 执行。

按住空格 / RB 并松方向输入时平滑减速，减速期间仍移动；松开空格 / RB 或鼠标拖点立即请求保持。TCP 仅位置控制由逆解协调六轴，并不要求每关节都转；J5 看似不动不能单凭此判定故障。

### 共用运动配置与反馈调参

- **轨迹生成**：完整六轴默认 Ruckig，可选原五次到点 / 加速度平滑；手动、坐标、程序和反馈控制输出共用。小幅试机、J7 保留原方案。
- **驱动模式**：默认 CSP；MIT 位置 PD 已接入软件，含逐轴 Kp/Kd，重连默认回 CSP。MIT 保持、启动和故障行为尚待现场运动验收，不作为已调好的实机默认方案。
- **反馈控制器**：P、PD、PID、增益调度 PID、LADRC、线性 MPC 及本机 HTTP 外部算法。仅在显式启动反馈控制后接管参考，不自动替换全部手动与程序动作。

各反馈算法有独立参数草稿、命名档案、试算和运行记录导出，初值仍需结合负载和实机调定；改变配置后须重新检查路径。见[共用运动配置与调参](共用运动配置与反馈调参_2026-10-17.md)和[MIT 与扩展反馈控制](MIT与扩展反馈控制_2026-10-17.md)。

## 6. 暂停、撤力与结束使用

**悬空机械臂失能后可能下落。先回到现场验证的支撑姿态或可靠支撑，再撤力。** 项目存有 J2–J6 为 0°、容差 ±3° 的支撑返回定义，J1 保持当时角度、J7 不参与；这只是返回目标，不能替代现场无电稳定验证。见[初始稳定姿态](初始稳定姿态.md)。

| 操作 / 状态 | 当前含义 |
| --- | --- |
| 暂停并保持 / 暂停并释放控制权 | 完整 ACTIVE 冻结已有位置参考，撤销旧输入与租约；不主动失能、不自动续跑 |
| 通信超时、页面失焦 / 隐藏 / 失联 | 完整 ACTIVE 进入 HOLDING；反馈未确认时只能说保留了原目标，不能宣称已可靠托住 |
| 反馈恢复后的重新接管 | 重查新鲜、静止与跟踪条件后接管；旧运动不自动续跑 |
| 失能撤力 / Esc | 明确请求失能并清理，可能撤去支撑力 |
| 重置控制状态 | 失能、停稳核对、恢复临时参数；失败保留恢复锁，不回零、不自动使能 |
| 小幅试机时限 / 硬保护 / 服务关闭 | 保留各自停止与失能清理流程，不能当作完整模式暂停 |

保持不是机械抱闸，电源或驱动故障仍可能撤去力矩。异常时先根据现场实情可靠支撑，查看停止原因和恢复结果；不要反复重启、拔线或放宽保护尝试恢复。

完整范围命令期限为 **500 ms**，小幅仍为 **300 ms**；这是命令有效期限，不是反馈刷新周期。实机反馈各字段 600 ms、网页 ROS 状态 500 ms、网页心跳 700 ms、手动输入 250 ms 分别检查，不能当作同一阈值。见[通信轮询与只读重试修复](通信轮询与只读重试修复_2026-10-17.md)。

### 查看和关闭仿真 / 网页

```bash
./rebotarm status
./rebotarm stop
```

`status` 展示受管进程、端口及 CAN。`stop` 只处理 `managed.pids` 中名称和命令 / 目录匹配的 **simulation、web** 项。受管仿真清理它自己启动的子进程；复用的 rosbridge / MCP 不保证随之结束。

**`./rebotarm stop` 不停止网页另行启动的 CSP 实机反馈服务，也不是实机急停命令。** 关闭网页可能触发通信保持，关闭实机服务则可能执行失能。先完成支撑与实机结束流程再关软件，不要把强杀进程或 `Ctrl+Z` 当作正常停机。

## 7. 日志与常见问题

日志路径从项目根目录算起；查看不会改变机械臂状态：

```bash
tail -n 80 outputs/quick-start/simulation.log
tail -n 80 outputs/quick-start/web.log
tail -n 80 outputs/twin-console/csp-driver.log
```

| 文件 / 目录 | 内容 |
| --- | --- |
| `outputs/quick-start/` | 仿真与网页启动日志 |
| `outputs/twin-console/csp-driver.log` | 受管实机驱动启动、连接与异常日志 |
| `outputs/twin-console/hardware/csp-session-*.json` | 真实会话、停止原因、临时参数与恢复结果 |
| `outputs/twin-console/hardware/` | 运动 / 驱动配置、支撑姿态和恢复证据 |
| `outputs/workbench/` | 程序库、连接及标定资料；可能含本机服务密钥，交接按交付文档处理 |

### 网页可开，ROS 未连接

运行 `./rebotarm status`，核对 3002、9090 和目标命名空间；在「连接与高级设置」核对 WebSocket。端口占用先查归属，尤其是否关联实机，避免直接结束未知进程。只有 WebSocket 在线不代表实机反馈新鲜。

### can0 DOWN、接口不存在或 TX 有而 RX 为 0

先确认是否刚重启 / 拔插 USB。无活动实机控制、接口 DOWN 时按第 3 节配置；没有 `can0` 时检查 USB 和系统识别。接口 UP / 1 Mbps 仍无回复时核对本体供电、线缆、接头和总线占用，保留错误计数及驱动日志，不把 ERROR-ACTIVE 误当根因。

### 「通信异常：已冻结电机原位置目标」

看提示中的具体字段和反馈年龄。HOLDING 已清除旧输入，等待反馈恢复和明确重新接管；反馈未确认时不要假定保持已生效。只读超时可进入 `FEEDBACK_WAIT` 重试，恢复后仍需重新准备和接管。`RECOVERY` / `FAULT` 要核对失能、停稳和参数恢复，不用重启绕过。

### 动作颤动或跟踪超差

记录操作、时间、速度、姿态和对应会话。轮询与参考调度修复已通过软件验证，完整 ACTIVE、MIT 保持和颤动尚未现场复验，J3 真实跟踪超差也未排除。不能用只读 400 帧通过宣称运动已平滑，也不应直接提高速度或改 PID 掩盖问题。

### 交接前最短核对

工作台可打开、正确选择目标、反馈持续更新；保存程序和日志，核对未完成恢复锁。首次实机运动由现场人员确认方向、零位、限位和支撑条件后明确启动。2026-10-17 最新结果为完整范围七轴约 20 秒 / 400 帧只读正常，反馈年龄最大约 121 ms、CAN 错误为 0；该批次没有使能或运动。
