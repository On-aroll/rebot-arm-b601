# 控制算法接入：持续反馈闭环

入口：http://127.0.0.1:3002 顶栏或工作区标签 **控制算法**。

这里接的是“读取当前机械臂状态，计算下一周期关节参考”的控制器。它独立于视觉、任务规划和对话，可以单独工作。

| 模块 | 输入 → 输出 | 入口 |
| --- | --- | --- |
| 控制算法 | 当前关节反馈、期望目标、参数 → 本周期六轴位置/速度参考 | 控制算法 |
| 视觉识别 | 相机帧 → 检测/定位结果 | 视觉与任务规划 |
| 任务规划 | 任务、物体观测 → 多步骤动作程序 | 视觉与任务规划 |
| 大模型对话 | 自然语言 → 解释或程序提案 | 对话任务 |

之前的“算法接入”只覆盖识别和任务规划，不能替代控制算法。现在新增了独立的控制计算接口和运行界面。

## 当前支持的控制类型

- 关节位置参考：返回六个rad数值。
- 关节速度参考：返回六个rad/s数值，主机按现有速度/加速度约束积分为位置参考。
- 适合接入输出这两种参考的轨迹跟踪器、位置/速度型MPC、策略模型等。网页另有内置增益调度PID、LADRC和线性MPC；本节描述通用本机HTTP接口。
- 期望目标为六轴关节角；可以从实时反馈填入，也可先在手动控制输入XYZ、计算预览，再点“使用坐标预览目标”。

当前共用执行器默认采用 **CSP位置通道**，完整范围可配置 MIT 位置PD。这个上层接入口不替换电机内部PID，也不接收直接力矩、阻抗或力传感输出。MIT与新增反馈控制器的参数、模型边界及待完成的实机验收见[MIT与扩展反馈控制](MIT与扩展反馈控制_2026-10-17.md)。

位置参考经速度、加速度及边界约束整形；算法原始输出可能与发给执行器的参考不同。页面分别显示两者，实色模型始终显示反馈。不要把该适配器用于要求逐采样严格等值执行或硬实时保证的控制实验。

## 接入步骤

1. 在页面下载 **Python接入模板**，或打开 `examples/control/controller.py`。把自己的算法调用写进 `control_step()`；模型应在进程初始化时加载，避免每步重新加载。
2. 在机器人主机运行你的计算服务。模板自检命令：

   ```bash
   cd /home/bonvoyage/Desktop/rebot-b601-doc-replica/ReBot_Arm_DigitalTwin_RS
   python3 examples/control/controller.py
   ```

   默认只输出保持参考；不连接CAN，不自动接管。`--demo-servo`是用于Fake验证的简单P速度跟踪示例，非生产控制算法。

3. 页面填写名称、`http://127.0.0.1:8089/step`、输出类型、请求频率和参数JSON。可以导入 `examples/control/controller.json`，或保存本浏览器配置。
4. 顶部选择 **安全仿真**并连接。填入期望关节角，点击 **只读检查 / 单步试算**。检查仅调用一次算法并验证协议、数值和本次输出，不发送运动；不代表整个未来闭环的路径预览。
5. 接管仿真后，点击 **启动闭环控制**。观察目标、反馈、算法输出、执行器参考、响应耗时及更新频率。点击 **停止算法 / 保持**结束；顶部停止会释放控制。
6. 实机操作沿用顶部的准备、接管和现场许可；先使能保持，再试算并启动算法。算法服务不获得控制租约，不得另开CAN。实机仍须现场验收，本轮代码测试不代表实体闭环验收。

配置导入仅导入服务地址和参数。Python/C++/ROS/MATLAB等计算程序可以自行实现相同HTTP协议，不依赖网页使用哪种语言；不是上传任意程序后在网页服务器执行。当前地址限定机器人主机回环地址，不通过云API构成运动控制闭环。

## 协议 `b601-controller/1.0`

主机按设定频率发送 `POST /step`，每次请求包含：

| 字段 | 含义 |
| --- | --- |
| `request_id` | 必须原样回传；拒绝旧请求结果 |
| `dry_run` | true为只读试算，false为持续控制计算 |
| `namespace` | `rebotarm_rs`为仿真；`rebotarm`为实机 |
| `state.position` | J1–J6实际反馈，rad |
| `state.velocity` | 对应反馈源速度，rad/s；来源不提供时为null |
| `state.tcp_pose` | 基座坐标系TCP，xyz为m，RPY为rad |
| `state.feedback_age_ms` | 本机反馈年龄 |
| `reference.position` | 本次期望六轴角度，rad |
| `applied_reference` | 上次提交给执行器的位置参考；未提交时null，不是CAN写入确认 |
| `period_s / elapsed_s` | 请求的名义周期/本次控制经过时间；不保证硬实时 |
| `limits` | 模型角度范围和本次速度上限 |
| `parameters` | 用户填写的算法参数 |
| `output` | `joint_position`或`joint_velocity` |

响应只包含以下四项：

```json
{
  "schema": "b601-controller/1.0",
  "request_id": "原请求的request_id",
  "output": "joint_velocity",
  "values": [0, 0, 0, 0, 0, 0]
}
```

请求频率5–20Hz，对应当前20Hz主机控制回调；实际反馈查询通常更慢，请查看运行监视和反馈年龄。不能将请求频率当成独立测量频率或电机内部控制频率。

计算在独立工作线程中执行，不阻塞原CAN线程。200ms响应期限、250ms参考年龄与原命令看门狗衔接，不补发积压目标、不自动重试。失败/过期保持当前位置；原心跳、失焦、断连、跟踪、力矩、电流和路径检查仍生效。停止/重置使迟到结果失效。

算法与坐标到点、程序、TCP拖拽互斥。运行中先停止再切换。它控制J1–J6；J7沿用夹爪模块，当前控制协议不接受J7和任意硬件操作。

## 验证与限制

离线测试覆盖只读试算、两种输出、共享执行器、起点/范围变化、未使能拒绝、输入互斥、速度/NaN/错误请求拒绝、过期保持和迟到响应不复活。隔离ROS验证通过本机HTTP控制器驱动Fake、停止及服务超时保持。

页面配置不需要视觉模型或大模型API。外部控制算法的性能、稳定性、环境避障和实体运动仍由接入算法及现场验证负责。

参考：[Seeed ROS2接口与控制模式](https://wiki.seeedstudio.com/cn/rebot_arm_b601_rs_ros2_integration/)。本接口时限是当前工程执行链的约束，不宣称为厂商所有控制模式的极限。
